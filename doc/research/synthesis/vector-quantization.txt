================================================================================================
synthesis :: vector-quantization
vector quantization and bit-compression of embeddings (the compression key for vectors)
================================================================================================

state of the art and concrete nest recommendations for this category.

summary:     The whole category converges on one move that is nearly tailor-made for nest: RaBitQ (SIGMOD
             2024, NTU) replaces trained PQ/OPQ codebooks with a fixed, deterministic codebook
             (sign-corners of the unit sphere) plus a single shared random orthogonal rotation
             P, giving 1 bit/dim plus ~2 f32 correction scalars per vector (~32x vs f32, ~8x vs
             nest's current int8 floor) AND a distance estimator that is provably unbiased with
             a sharp O(1/sqrt(D)) error bound, computed as bitwise-AND + popcount straight off
             mmap with no decompression. It is patent-free, openly published, and
             reimplementable clean-room in Rust. The bitsandbytes/INC/llm-compressor cluster
             supplies the complementary mid-tier: codebook (NF4 quantile-optimal for
             Gaussian-shaped normalized embeddings), block/group-wise absmax scaling, microscale
             block-float (MXFP4 E2M1 + power-of-two E8M0 scale that decodes by exponent-add, no
             multiply), and build-time accuracy recovery (GPTQ inverse-Hessian error
             compensation, AutoRound learned rounding). These are the 4-bit tier that sits
             between int8 and RaBitQ's 1-bit. nest is unusually well positioned to adopt all of
             this because (a) the format is additive-only with encoding ids 4-255 RESERVED in
             v1, so new codecs need no version bump, (b) the runtime already mandates a rerank
             stage, and (c) rotation/codebook determinism maps cleanly onto seeded reproducible
             builds. CRITICAL FINDING confirmed by reading the code: nest's current rerank in
             crates/nest-runtime/src/search.rs::score_subset reranks against the SAME lossy
             dtype stored on disk (int8/f16), NOT against full-precision f32. The
             search_contract docstring claims 'real cosine, never an ann proxy', but for
             quantized presets the returned score already carries quantization error. Aggressive
             1-bit/4-bit quantization makes this latent gap material: to keep the contract
             honest, nest must either keep a full-precision (or f16) shadow copy of survivors
             for rerank, or accept that 'exact cosine' means 'exact at the stored precision'.
             This decision gates the entire category and must be made before shipping a
             rabitq/nf4 preset.

state of the art
------------------------------------------------------------------------------------------------
As of 2024-2025 the frontier for vector-byte compression splits into two regimes. (1) Sub-byte
randomized quantization: RaBitQ and its B-bit extension are the state of the art for reaching ~1
bit/dim while preserving recall, because the random orthogonal rotation (Johnson-Lindenstrauss)
turns naive sign quantization into an UNBIASED estimator with an O(1/sqrt(D)) error bound that
matches the Alon-Klartag FOCS17 lower bound (asymptotically optimal). The estimator <o,q> ~=
<o_bar,q>/<o_bar,o> reduces to AND+popcount against a 4-bit query, ~3x faster than PQ table
lookups at equal accuracy, and the B-bit dial (1/4/5/7 bits via an 'ex-code' refinement) reaches
~90/95/99% recall with NO rerank. Library maturity is high (VectorDB-NTU CPU/GPU, cuVS
IVF-RaBitQ fork reporting >2.7x throughput over IVF-PQ). (2) Codebook + block-scaling at 4 bits:
from the LLM-weight world, NF4 (quantile-optimal 16-level codebook for N(0,1) data), blockwise
absmax scaling (block=32/64, one scale per block absorbs outliers), double/nested quantization
of the scales (~0.4 bits/param reclaimed), microscale block-float MXFP4 (E2M1 nibble + shared
E8M0 power-of-two scale, decode = exponent add) and NVFP4 (two-level E4M3 fp8 scale per 16).
Accuracy at 4 bits is recovered to ~99% of FP32 by build-time-only passes: GPTQ (inverse-Hessian
error compensation, one Cholesky over the calibration covariance) and AutoRound/SignRound
(SignSGD-learned per-weight rounding offset, fixed ~200 steps, zero inference overhead). The
unifying principle across both regimes: separate storage dtype from compute dtype, keep the dot
product in f32, and let the data's own distribution (Gaussian for L2-normalized embeddings) or
geometry (random rotation) dictate where the few code points go. For an L2-normalized-embedding
database with a rerank stage, RaBitQ is the clear headline lever and NF4/MXFP4 are the safe
4-bit intermediate.

top transferable innovations
------------------------------------------------------------------------------------------------
1. RaBitQ 1-bit randomized quantizer: rotate by a shared seeded orthogonal P, store sign(P^-1
   (o-c)) as D bits + 2 f32 scalars (<o_bar,o> and ||o-c||). ~32x vs f32, ~8x vs nest int8,
   distance = AND+popcount off mmap. THE headline compression lever for nest's embeddings
   section.
2. Unbiased estimator with provable O(1/sqrt(D)) error bound: turns ANN distance into a quantity
   with a confidence interval, so nest's search_contract can cite a recall GUARANTEE, not just
   an empirical number. This is what makes 1-bit safe where naive binary quantization collapses.
3. Asymmetric bit allocation: data side 1 bit/dim, query side 4 bits/dim (4 bit-planes). Error
   is dominated by data quantization, so query precision is cheap insurance; distance = sum_k
   2^k * popcount(code & q_plane_k).
4. B-bit ex-code refinement dial (RaBitQ extended, Sep-2024): one codec spanning 1/4/5/7 bits
   (~90/95/99% recall no-rerank). Gives nest a single tunable knob from a 'nano' preset up to
   near-lossless, replacing the discrete float32/float16/int8 ladder.
5. NF4 quantile-optimal codebook: 16 reconstruction levels at the quantiles of N(0,1), strictly
   better than uniform int8 for L2-normalized embeddings whose per-dim components are ~zero-mean
   Gaussian. 4 bits/dim, near-lossless, dequant is a 16-entry LUT gather (AVX2 vpermps / NEON
   vqtbl).
6. Blockwise absmax + double quantization: per-block (32/64) scale bounds error and absorbs
   outliers; quantizing the scales themselves reclaims ~0.4 bits/dim. The reason int4 is viable
   where flat int4 collapses.
7. MXFP4 microscale block-float: E2M1 4-bit element + shared E8M0 power-of-two scale per 32
   dims. Decode is an EXPONENT-ADD, not a multiply, which is the cheapest possible dequant on
   nest's SIMD hot path.
8. GPTQ inverse-Hessian error compensation (build-time only): quantize dims left-to-right, push
   each rounding error onto not-yet-quantized dims weighted by H^-1 of the embedding covariance.
   One Cholesky (O(d^3), trivial at d=384/768/1024). Recovers most of the recall lost at 4 bits,
   zero runtime cost.
9. AutoRound/SignRound learned rounding (build-time only): SignSGD over per-dim rounding offset
   in [-0.5,0.5], fixed seeded ~200 steps. Deterministic, zero inference overhead, free recall
   recovery at 4 bits.
10. FastScan batched layout: reorganize 32 codes at index time for SIMD lane-parallel
   popcount/shuffle scan (AVX2/AVX512 VPOPCNTDQ, NEON vcnt+vaddv). Makes the 1-bit scan
   memory-bandwidth-bound rather than compute-bound.

nest recommendations
------------------------------------------------------------------------------------------------
* Add a `rabitq.rs` codec under crates/nest-format/src/encoding/ as encoding id 4 (additive in
  the RESERVED 4-255 space, NO NEST_FORMAT_VERSION bump). Layout mirrors int8.rs: u32
  payload_version, u32 variant/Bq, a single deterministic rotation SEED (store the seed, never
  the dense matrix), the global centroid c once, then per vector D/8 packed sign bits as LE u64
  words + 2 LE f32 factors (<o_bar,o>, ||o-c||). Add EmbeddingDType::RaBitQ + 'rabitq'
  manifest_str in writer/encoding_choice.rs and expected_embeddings_size in encoding/mod.rs.
    where:  crates/nest-format/src/encoding/rabitq.rs (new, keep <300 lines), encoding/mod.rs (pub use +
            expected size + decode_payload passthrough like int8), writer/encoding_choice.rs
            (new enum arm), layout/mod.rs (SECTION_ENCODING_RABITQ=4)
    impact: Highest-leverage compression in nest: embeddings section (the dominant payload) drops from
            int8's ~1 byte/dim to ~1 bit/dim + 8 bytes/vec, ~8x over int8 and ~32x over f32.
            Directly the biggest single move on the 'compress more than everyone' north star for
            vector bytes.
    effort: high
    from:   gaoj0017/RaBitQ, VectorDB-NTU/RaBitQ-Library, Stardust-SJF/cuvs_rabitq

* Add a RaBitQ AND+popcount distance kernel beside the existing dot dispatchers in the simd
  module. New rabitq.rs with NEON (vcnt + vaddv), AVX2 (popcount over 4 query bit-planes;
  VPOPCNTDQ when detected), and a scalar u64::count_ones fallback, wired through
  detect_backend() exactly like dot_f32_i8. Scores codes straight off mmap as the cheap
  ANN/coarse stage. Extend score_all/score_subset in search.rs with a DType::RaBitQ arm.
    where:  crates/nest-runtime/src/simd/rabitq.rs (new) + simd/mod.rs dispatch arm,
            crates/nest-runtime/src/search.rs (DType::RaBitQ in score_all/score_subset),
            mmap_file.rs DType enum
    impact: Makes the 1-bit codec actually scorable on the hot path with no decompression (the property zstd
            lacked), at ~3x PQ speed; 1-bit codes touch ~8x fewer bytes/vector than int8, so the
            mmap scan becomes bandwidth-light.
    effort: high
    from:   gaoj0017/RaBitQ, VectorDB-NTU/RaBitQ-Library

* Decouple rerank precision from storage precision: keep a full-precision (f32) or f16 SHADOW
  copy of embeddings available so score_subset reranks survivors against true precision, not the
  lossy stored dtype. Either (a) store both rabitq codes AND an f16 embeddings blob (still ~17x
  smaller total than f32, exact-on-rerank), or (b) explicitly redefine the search_contract to
  say 'exact cosine at stored precision' and surface dtype in SearchHit. This resolves the
  confirmed gap where score_subset currently reranks int8 against int8.
    where:  crates/nest-runtime/src/search.rs (score_subset rerank source),
            crates/nest-format/src/sections/contract.rs + search_contract docs, decode.rs
            content_hash semantics
    impact: Keeps nest's headline 'returned score is real cosine, never an ann proxy' guarantee honest under
            aggressive quantization. Without this, the 1-bit/4-bit presets quietly degrade the
            contract. This is the gating design decision for the whole category.
    effort: medium
    from:   gaoj0017/RaBitQ, vllm-project/llm-compressor

* Add an NF4/quantile codebook codec as encoding id 5: per vector [block_scales | packed 4-bit
  indices], block=32, with a single shared 16-entry f32 codebook (fixed NF4 constants OR a
  seeded/sorted quantile estimate over the corpus) stored once in the section header.
  Double-quantize the block scales (group=256 to int8) to shave scale overhead. Dequant kernel =
  16-entry LUT gather (AVX2 vpermps / NEON vqtbl) * block absmax, then the existing SIMD dot.
    where:  crates/nest-format/src/encoding/nf4.rs (new), encoding/mod.rs, writer/encoding_choice.rs,
            crates/nest-runtime/src/simd/nf4.rs (new dequant-and-dot kernel)
    impact: 4-bit tier between int8 and rabitq: ~0.5 byte/dim, near-lossless because the codebook matches
            the Gaussian shape of normalized embedding components. A safer intermediate preset
            and a fallback if RaBitQ recall is unsatisfactory on the PT-BR corpus.
    effort: high
    from:   bitsandbytes-foundation/bitsandbytes, intel/neural-compressor

* Add a 'nano' preset (zstd text / rabitq embeddings / hnsw) and a 'micro' preset (zstd / nf4 /
  hnsw) to the preset resolver, below the existing 'tiny'. Expose the B-bit dial as a build
  kwarg (rabitq_bits=1|4|5|7). Pair rabitq codes with the existing HnswIndex so the popcount
  scan feeds/replaces the HNSW shortlist.
    where:  crates/nest-python/src/build_fn.rs (preset match arms + new dtype/bits kwargs), crates/nest-cli
            build surface
    impact: Turns the codec work into a user-facing one-flag win and pushes tiny's 0.283 ratio toward
            sub-0.1 on embedding-dominated corpora. The bits dial gives one tunable knob
            spanning nano->near-lossless.
    effort: low
    from:   VectorDB-NTU/RaBitQ-Library, gaoj0017/RaBitQ

* Add a build-time-only GPTQ/AutoRound accuracy-recovery pass in the python builder, run before
  quantizing to 4-bit codes: compute X^T X once over corpus embeddings, Cholesky inverse,
  error-compensated rounding (or SignSGD learned rounding, fixed seed + fixed step count).
  Produces better int4/nf4 codes; pure build-time, zero runtime cost, keeps the rust runtime
  offline and deterministic.
    where:  crates/nest-python (builder quantization stage, before encode), feeding the nf4/int4 codec
            bytes; no rust runtime change
    impact: Recovers most of the recall lost at 4 bits (INC reports ~99% of FP32), making the micro/nano
            presets viable without a precision shadow copy. Free quality at build time.
    effort: medium
    from:   vllm-project/llm-compressor, intel/neural-compressor, bitsandbytes-foundation/bitsandbytes

* Add an MXFP4-style block-float codec (E2M1 nibble + per-32 E8M0 power-of-two scale) as a third
  sub-byte option, chosen specifically because its decode is an exponent-add not a multiply,
  minimizing hot-path dequant cost during rerank. Nibble-unpack is a shift+mask, vectorizable on
  AVX2/NEON.
    where:  crates/nest-format/src/encoding/mxfp4.rs (new), crates/nest-runtime/src/simd/mxfp4.rs
            dequant-and-dot
    impact: ~4x over f32 with the cheapest possible dequant; a principled float sub-byte path alternative to
            integer NF4. Useful if NF4's LUT gather proves slower than exponent-add on aarch64.
    effort: medium
    from:   intel/neural-compressor, vllm-project/llm-compressor

* Implement the rotation P as a Fast Hadamard Transform (FHT) variant rather than a dense D*D
  matmul, so per-query inverse rotation P^-1 q is O(D log D) and per-vector build-time rotation
  is cheap. Store only the seed + sign-flip pattern. Keeps the codec file small and the build
  deterministic.
    where:  crates/nest-format/src/encoding/rabitq.rs (rotation helper) shared with crates/nest-runtime
            query-side rotation in search.rs/simd
    impact: Avoids an O(D^2) dense rotation per query and a D*D matrix in memory; matters at
            D=768/1024/1536. Keeps the codec mmap-light and the build fast on brenner's minimal
            hardware.
    effort: medium
    from:   Stardust-SJF/cuvs_rabitq, VectorDB-NTU/RaBitQ-Library

* Group-wise int8 (per-group fp16 scale, group=16/32) as the lowest-risk first step before
  committing to 1-bit/4-bit: a tiny upgrade to the existing int8.rs that swaps per-vector scale
  for per-group scale. Lands recall improvement and de-risks the layout/scale plumbing the
  harder codecs reuse.
    where:  crates/nest-format/src/encoding/int8.rs (add scale_kind=1 per-group, additive within the
            existing int8 encoding), simd/mod.rs score_int8_section group-aware
    impact: Immediate recall win at the same ~4x ratio, and proves out the contiguous per-group-scale layout
            that nf4/mxfp4/rabitq all depend on. Low blast radius.
    effort: low
    from:   intel/neural-compressor, vllm-project/llm-compressor

compression wins
------------------------------------------------------------------------------------------------
  - RaBitQ 1-bit embeddings: 768-dim f32 vector 3072 bytes -> ~768 bits + 8 bytes = ~104 bytes,
    ~30x on embedding bytes (~0.034 ratio), vs int8's 4x. 1024-dim: 4096 -> ~136 bytes. The
    single largest available lever on nest's headline ratio since embeddings dominate
    compressed-preset file size.
  - ~8x cut specifically over nest's current floor (int8 at 1 byte/dim -> ~1 bit/dim), pushing
    the 'tiny' 0.283 ratio toward sub-0.1 on embedding-heavy corpora, while staying directly
    scorable from mmap via popcount (no decompression on the hot path, the property that banned
    zstd on embeddings).
  - NF4 / quantile codebook at 4 bits/dim: ~0.5 byte/dim (half of int8), near-lossless on
    L2-normalized embeddings because the codebook sits at N(0,1) quantiles. A safe intermediate
    that beats int8 with one LUT gather of dequant cost.
  - MXFP4 block-float: ~4x over f32 (4 bits/dim + one E8M0 byte per 32 dims) with
    decode-by-exponent-add, the cheapest sub-byte dequant for the rerank path.
  - Double/nested quantization of block scales reclaims ~0.4 bits/dim of scale overhead, and
    storing the rotation as a SEED (not a D*D matrix) keeps the rabitq codec header to a few
    bytes regardless of dimension.
  - B-bit ex-code dial gives a continuous size/recall tradeoff (1/4/5/7 bits) from one codec,
    letting nest ship a 'nano' preset and a near-lossless preset from the same code path instead
    of discrete f32/f16/int8 tiers.
  - Combined stack potential: zstd on text sections + RaBitQ on embeddings + HNSW pruned by
    popcount can plausibly take a vector-dominated corpus well below the current 0.283 tiny
    ratio while the rerank (against a precision shadow) keeps returned scores honest.

watch-outs (conflict with nest constraints)
------------------------------------------------------------------------------------------------
  - CONTRACT INTEGRITY (highest): confirmed in code that search.rs::score_subset reranks against
    the SAME lossy stored dtype, not full-precision f32. The search_contract claims 'real
    cosine, never an ann proxy', but quantized presets already violate the spirit of that.
    Shipping 1-bit/4-bit without either a precision shadow copy or a redefined contract turns
    the headline guarantee into a half-truth. Decide this first.
  - CONTENT_HASH STABILITY: nest's content_hash is documented as STABLE across encodings, but
    for quantized embeddings it hashes the on-disk bytes (per decode.rs). A RaBitQ file and an
    f32 file of the same corpus will NOT share content_hash, so citations
    nest://content_hash/chunk_id are tied to a specific quantization. This is acceptable but
    must be documented; do not claim cross-precision citation stability.
  - DETERMINISM of the rotation: RaBitQ determinism hinges on a seeded orthogonal P AND
    identical floating-point ops across the three SIMD backends. If P^-1 q or the rotation
    matmul is computed with FMA on AVX2 but separate mul/add on scalar, sign() can flip near
    zero, breaking 'same chunks => byte-identical codes' and the reproducible-build guarantee.
    The codec generation (build-time) must be backend-independent; only the popcount scan may
    vary.
  - AutoRound/GPTQ determinism: SignSGD and Cholesky must use fixed seed, fixed iteration count,
    fixed column/group order (nest already mandates alphabetical/index order). Any
    nondeterministic BLAS threading in the python builder would break reproducibility. Pin it.
  - NO-PANIC RULE: every new codec parse path (rabitq/nf4/mxfp4) must return typed thiserror
    NestError on malformed payloads (bad payload_version, size mismatch, unknown variant),
    mirroring Int8EmbeddingsView::parse. No unwrap on untrusted mmap bytes. The unsafe i8/u8
    bitcast pattern in int8.rs is fine but the bit-unpacking must bounds-check section length
    first.
  - FILE HYGIENE: <=300 lines/file (333 hard cap), single-responsibility. RaBitQ encode + B-bit
    ex-code + rotation will not fit one file; split codec (format), kernel (runtime simd), and
    rotation helper. Do not bloat encoding/mod.rs.
  - SMALL-CORE / DEPENDENCY CREEP: do NOT vendor Eigen/cuVS/bitsandbytes; all are CUDA/C++ and
    would violate the offline single-file Rust runtime. Reimplement only the (patent-free,
    published) algorithm in pure Rust. The python builder may use numpy for the build-time
    GPTQ/quantile pass, but the rust runtime must stay dependency-light and socket-free.
  - QUERY-SIDE ROTATION COST: P^-1 q is one O(D^2) op per query (or O(D log D) with FHT)
    amortized over the probe list. For nest's small/embedded corpora the probe list may be
    short, so the rotation could dominate per-query latency. Benchmark vs the int8 flat scan
    before declaring a speed win; the compression win is real regardless, the speed win is
    corpus-size-dependent.
  - LICENSE diligence: RaBitQ algorithm is patent-free and openly published (SIGMOD 2024, arXiv
    2405.12497); upstream code is MIT/Apache but one extract could not confirm the library
    license from the README. nest only needs the algorithm (clean-room Rust), so this is a
    reference concern, but record the citation/DOI in provenance rather than copying code.
  - BM25/CJK gap is orthogonal but interacts: aggressive vector quantization makes the lexical
    path relatively more important for the PT-BR (and any CJK) corpora; don't let a 1-bit vector
    preset ship without bm25 in the hybrid path as a recall backstop.
