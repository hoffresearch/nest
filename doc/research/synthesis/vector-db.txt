================================================================================================
synthesis :: vector-db
vector databases and sqlite vector/columnar extensions
================================================================================================

state of the art and concrete nest recommendations for this category.

summary:     The entire vector-db field has converged on ONE pattern that nest already half-implements:
             rotate-then-quantize embeddings to 1-4 bits, score the tiny codes from mmap with
             integer/bitwise SIMD as a cheap candidate stage, then rerank a small over-fetched
             set against full-precision originals to return a true score. nest's mandatory
             exact-cosine rerank IS the rescore stage every one of these systems (qdrant,
             milvus/knowhere, chroma, weaviate, lance, pgvector, VectorChord,
             sqlite-vec/vector/vss) bolts on for safety; nest is therefore uniquely
             pre-positioned to adopt the most aggressive quantizers without a recall penalty.
             The frontier splits into two families. (1) DATA-OBLIVIOUS rotation quantizers
             (TurboQuant, RaBitQ, Weaviate RQ): a seeded fast Walsh-Hadamard / random orthogonal
             rotation makes any embedding's coordinates near-iid, so a single compile-time
             scalar codebook or a sign bit suffices -- NO trained codebook, NO corpus
             statistics. This family is the perfect fit for nest because seeded rotation keeps
             builds byte-identical/deterministic, which trained product quantization (milvus
             FastScan, lance PQ) fundamentally cannot guarantee without pinning k-means seeds
             and iteration order. (2) Beyond quantization, lance contributes the
             transparent-vs-opaque encoding taxonomy and byte-stream-split (the conceptual
             framework nest needs to add aggressive codecs without breaking the mmap hot path),
             plus FSST for O(1)-random-access text compression that preserves citation spans
             where block-zstd would destroy them; sqlite-columnar contributes zone-map
             block-skipping that can make nest's exact scan sublinear while still returning TRUE
             cosine. The decisive architectural finding from reading nest's own code: today
             score_subset reranks against the SAME embeddings section it scored, so once
             embeddings are stored at 1-2 bits the 'exact rerank' is no longer exact. Shipping
             sub-int8 quantization therefore REQUIRES a dual-section layout -- a tiny
             coarse-codes section for candidate generation plus a separate full-precision (or
             f16) rerank section -- which is itself a compression win because the coarse section
             can be brutally small. Highest-leverage path: RaBitQ/TurboQuant 1-2 bit codes as a
             new additive encoding id on a coarse embeddings sub-section, popcount/LUT SIMD
             kernels beside the existing dot kernels, a 'nano' preset well below the 0.283
             'tiny' floor, with the existing f32/f16 embeddings kept as the rerank source.

state of the art
------------------------------------------------------------------------------------------------
Convergent SOTA: a two-stage retrieve-then-rerank pipeline where lossy rotation-quantized
vectors live hot (mmap/page-cache) and full-precision originals are touched only to rescore a
small over-fetched candidate set. The compression frontier is rotation-based low-bit
quantization in two families. Data-oblivious (deterministic, the one nest needs): seeded fast
Walsh-Hadamard / structured random rotation in O(d log d) makes coordinates near-iid so a
fixed/compile-time codebook or a bare sign bit is near-optimal -- RaBitQ 1-bit (~28x, unbiased
O(1/sqrt(D)) estimator, AND+popcount ~111ns/code), Weaviate RQ 8-bit (4x, 98-99% recall,
decomposed int8 dot), TurboQuant 1/2/4-bit (compile-time Lloyd-Max codebook, asymmetric
full-precision query, SIMD nibble LUT). Trained (higher recall, NOT determinism-friendly):
milvus/knowhere FastScan 4-bit PQ with in-register LUT (pshufb/vpermb/vqtbl1q) + anisotropic
ranking loss, ~5x QPS, 8-64x. Multi-bit query bit-planes keep DATA at 1 bit while tuning query
precision. Adjacent: lance per-buffer compression cascade with transparent (O(1) access) vs
opaque (decode-required) taxonomy, byte-stream-split, FSST; sqlite-columnar zone-map
chunk-skipping (248-273x on range queries). Universal safety net is an exact full-precision
refine/rerank (qdrant rescore, knowhere reorder_k, weaviate rescoreLimit, lance refine_factor,
pgvector ORDER BY exact) -- identical to nest's mandatory exact-cosine rerank, which makes
aggressive quantization safe and validates nest's contract as prior art. Critical caveat from
nest's own code: the rerank currently reads the same section it scored, so sub-int8 storage
requires a separate full-precision rerank source to keep returns true-cosine.

top transferable innovations
------------------------------------------------------------------------------------------------
1. RaBitQ 1-bit quantization (chroma/VectorChord, SIGMOD 2024): seeded rotation + sign bit + 2
   corrective f32 scalars, unbiased O(1/sqrt(D)) estimator, ~28x compression, AND+popcount off
   mmap, data-oblivious so byte-identical builds -- highest-leverage codec for nest.
2. TurboQuant (qdrant/sqlite-vector/sqlite-vec, Google arXiv:2504.19874): Hadamard rotation +
   compile-time Lloyd-Max const codebook + asymmetric scoring, 1/2/4-bit, no training, beats
   int8 at half the bytes, scored via SIMD nibble LUT with zero decompression.
3. Weaviate 8-bit Rotational Quantization: rotate-then-int8 with decomposed dot, a drop-in
   upgrade of nest's int8.rs pushing recall@10 0.992 -> ~0.998 at the same 4x size; seed
   derivable from the existing model fingerprint.
4. Mandatory exact refine/rerank as a universal contract (all repos): validates nest's existing
   exact-cosine rerank as prior art and is what makes aggressive lossy quantization safe.
5. Multi-bit query bit-plane trick (VectorChord/TurboQuant): store at 1 bit/dim, tune recall on
   the query side -- decouples file size from query precision.
6. FastScan in-register LUT product quantization (milvus/knowhere/ScaNN, MLR 2020) + anisotropic
   loss: highest recall-per-bit, 8-64x, but trained k-means breaks determinism -- adopt only
   with pinned seeds.
7. Lance transparent-vs-opaque encoding taxonomy + byte-stream-split: the framework to add
   aggressive codecs without breaking the mmap hot path; BSS for high-ratio cold embedding
   archives.
8. FSST transparent text compression (lance): ~2x over raw text while preserving O(1)
   citation-span access that block-zstd destroys.
9. Zone-map block-skipping (sqlite-columnar): per-block centroid+radius prunes whole blocks
   before the SIMD scan, making the exact path pruned-exact while still returning true cosine.
10. Validity-bitmap tombstones + byte-identical dedup (sqlite-vec/pgvector): deletes and dedup
   without rewriting embeddings -- foundation for the real-time-edit north star; sqlite-vss
   monolithic-blob is the cautionary counter-example.

nest recommendations
------------------------------------------------------------------------------------------------
* Add a dual-section quantized-embeddings layout: a new RESERVED encoding id 4 = 'rabitq1'
  storing per-vector [sign-code dim/8 bytes][2 f32 corrective scalars] in a coarse embeddings
  sub-section, while keeping the existing f32 (or f16) embeddings as a separate full-precision
  rerank source. This is the structural prerequisite for ALL sub-int8 quantization, because
  today score_subset reranks against the SAME section it scored -- so 1-bit codes alone would
  make the 'exact' rerank no longer exact and silently break the 'returned score is real cosine'
  contract.
    where:  crates/nest-format/src/encoding/rabitq.rs (new, <=300 lines, mirror int8.rs layout); register id
            4 in layout/mod.rs SECTION_ENCODING_*; the rerank source needs either a second
            embeddings section (cleanest, needs a reserved section id 0x09 'embeddings_fp' since
            0x04 is fixed in CANONICAL_SECTIONS) OR a manifest flag pointing rerank at f16; wire
            candidate-gen vs rerank-source split in nest-runtime/src/search.rs score_subset.
            Seed the rotation from the model fingerprint already in the manifest so builds stay
            byte-identical.
    impact: Unlocks ~28x embedding compression (vs current 8x int8) on nest's largest,
            currently-incompressible section while preserving true-cosine returns -- the single
            biggest step toward 'compress more than everyone'. Enables a 'nano' preset well
            below the 0.283 'tiny' floor.
    effort: high
    from:   chroma RaBitQ, VectorChord RaBitQ, pgvector binary-quantize-then-rerank, sqlite-vec binary
            coarse + float rescore, qdrant two-stage rescore

* Upgrade int8.rs in place to Rotational Quantization (RQ): add a seeded fast Walsh-Hadamard
  rotation before the existing per-vector min/max int8 step, store the rotation seed (derived
  from model fingerprint) in the payload prefix, and use the decomposed dot product where only
  the int8.int8 term hits SIMD. Register as a NEW additive encoding id (e.g. 5 = 'rq8') so the
  FROZEN format and existing int8=3 stay byte-compatible.
    where:  crates/nest-format/src/encoding/int8.rs (add rotation; bump a payload sub-version, NOT
            NEST_FORMAT_VERSION); new fwht.rs helper module (<=300 lines, repr(C),
            little-endian, no panics) shared by rabitq.rs; the decomposed kernel lands beside
            dot_f32_i8 in crates/nest-runtime/src/simd/{avx2,neon,scalar}.rs.
    impact: Pushes the 'tiny' preset recall@10 from 0.992 toward 0.998+ at the SAME 4x size and ~2.3x faster
            scoring -- a near-free recall/latency win on the existing preset, and the FWHT
            helper is the shared primitive every other rotation codec reuses.
    effort: medium
    from:   weaviate RQ, VectorChord random rotation, qdrant Hadamard rotation

* Add a TurboQuant codec with a COMPILE-TIME-baked Lloyd-Max codebook as a Rust const (tq4=id 6,
  tq2=id 7), scored asymmetrically via a SIMD nibble lookup-table kernel (pshufb+maddubs on
  AVX2, NEON tbl, scalar fallback). Codes are scored in place with zero decompression, so this
  respects the never-decompress-embeddings-on-hot-path rule exactly.
    where:  crates/nest-format/src/encoding/turboquant.rs (const codebook keeps builds byte-identical, no
            corpus stats); LUT kernel in crates/nest-runtime/src/simd/ beside the dot kernels;
            reuse the shared fwht.rs rotator. Per-vector store = [scale:f32][packed 2/4-bit
            codes]; section header carries rotation seed + qbits surfaced by nest-cli
            inspect/stats.
    impact: 4-bit matches int8 at HALF the bytes with equal-or-better recall; 2-bit reaches 16x.
            Data-oblivious + const codebook is the only high-end quantizer that keeps nest
            deterministic without pinning k-means. Enables a 'micro'/'nano' preset.
    effort: high
    from:   sqlite-vector TurboQuant, qdrant TurboQuant, sqlite-vec, milvus FastScan LUT kernel

* Add a Hamming popcount kernel and a multi-bit query bit-plane scorer to the SIMD dispatcher,
  so 1-bit codes can be candidate-scored by AND+popcount and query precision tuned WITHOUT
  re-encoding the file (split the f32 query into weighted bit-planes at query time).
    where:  crates/nest-runtime/src/simd/mod.rs (new dot_hamming/score_bit_section beside dot_f32_i8) +
            avx2.rs (_mm256 popcnt path), neon.rs (vcntq_u8), scalar.rs (count_ones); wired as
            the coarse stage in search.rs feeding the existing rerank.
    impact: popcount is one instruction so the kernel is trivial across all three backends; ~35x cheaper per
            candidate than f32 dot. The bit-plane trick gives a recall knob that costs zero
            extra storage -- decouples file size from query precision.
    effort: low
    from:   VectorChord multi-bit query, TurboQuant query bit-planes, chroma AND+popcount, pgvector Hamming,
            sqlite-vec Hamming

* Add zone-map block-skipping to the exact scan: an OPTIONAL additive sidecar (reserved section
  id 0x09+) storing, per fixed block of ~1024 vectors, a centroid + max-radius bound. Before the
  linear SIMD loop, compute a per-block upper-bound cosine and skip blocks that cannot beat the
  current top-k threshold. Returns TRUE cosine, so the search-contract guarantee is untouched.
    where:  crates/nest-runtime/src/search.rs score_all/score_subset (add the prune check ahead of the dot
            loop); new sidecar encoder in crates/nest-format/src/sections/ (deterministic if
            centroids computed in fixed order); nest-cli stats reports blocks-scanned vs
            blocks-pruned.
    impact: Turns the unconditional O(n) exact scan into pruned-exact and accelerates the MANDATORY rerank
            after HNSW/BM25, without weakening any guarantee. The per-block centroid doubles as
            a residual-quantization anchor (vector = centroid + small residual) for a future
            structural codec, and the dirty-block model seeds the real-time-edit feature.
    effort: medium
    from:   sqlite-columnar zone maps, VectorChord IVF residual centroids, lance IVF clustering

* Add FSST as a transparent text codec id for the chunks_canonical section, replacing
  section-level zstd ONLY for the text section, so single chunks stay O(1) random-accessible by
  offset for citations while still getting ~2x compression.
    where:  crates/nest-format/src/encoding/fsst.rs (new transparent codec, new reserved encoding id);
            decode path in encoding/mod.rs::decode_payload must keep the transparent guarantee
            (currently raw/f16/int8 are Cow::Borrowed, zstd is Cow::Owned -- FSST needs per-span
            decode, not whole-section); citation reopen in nest-cli cite + nest-runtime
            materialize.
    impact: Advances compress-more-than-everyone on the text section WITHOUT breaking
            nest://content_hash/chunk_id span reopening that block-zstd currently forces a
            full-section decode for. Directly improves citation latency on compressed files.
    effort: medium
    from:   lance FSST, lance transparent-vs-opaque taxonomy

* Add a one-bit 'transparent' tag per section/encoding in the manifest+SectionEntry so
  nest-runtime knows whether a section permits zero-copy single-value extraction
  (raw/f16/int8/rabitq/FSST) vs needs a decode buffer (zstd block). Formalizes the constraint
  nest currently enforces only by convention and is the guardrail that lets future aggressive
  codecs be added safely.
    where:  crates/nest-format/src/layout/section_entry.rs (use a reserved bit/byte, additive),
            manifest/mod.rs, and reader/decode.rs; checked in reader/validate.rs so an opaque
            codec on the embeddings/hot-path section is rejected at open time.
    impact: Low byte cost, high architectural payoff: makes the never-compress-the-scored-embeddings rule
            machine-enforced rather than tribal knowledge, preventing a future codec from
            silently breaking the mmap hot path or citation spans.
    effort: low
    from:   lance transparent-vs-opaque taxonomy, sqlite-vss negative lesson (monolithic blob forbids random
            access)

* Add byte-stream-split as a COLD/archival-only embeddings encoding (de-interleave f32 into 4
  byte planes, then zstd) under a new reserved encoding id, used exclusively for a non-scored
  frozen variant -- never the mmap-scored path. Keeps the never-zstd-scored-embeddings rule
  intact while cutting size for archival .nest files.
    where:  crates/nest-format/src/encoding/bss.rs (new); guarded so the reader refuses to mark a BSS
            section as the scored embeddings section (cross-check with the transparent tag
            above); offered only via a dedicated 'archive' preset in nest-cli, decoded back to
            f32 on open.
    impact: High ratio on float embedding archives (exponent byte planes RLE/zstd hugely) for cold
            storage/transfer, advancing compress-more-than-everyone for the archival use case
            without touching the hot path.
    effort: medium
    from:   lance byte-stream-split, lance compression cascade

* Add validity-bitmap tombstones + byte-identical-embedding dedup to the writer: collapse
  duplicate vectors to one stored row (heaptids-style), and reserve a per-section validity
  bitmap so a future delete marks a chunk dead without rewriting embeddings -- treating
  tombstones as content keeps the build deterministic.
    where:  crates/nest-format/src/writer/build.rs + payload.rs (dedup at encode time, maps duplicate
            chunk_ids to a shared embedding row); reserved validity-bitmap sub-section;
            nest-runtime search skips dead rows.
    impact: Dedup shrinks corpora with repeated text (the PT-BR fake-news demo set has near-duplicates) at
            zero recall cost; the bitmap is the deterministic foundation for the real-time-edit
            north star without the O(N) rewrite that sqlite-vss/vss suffers.
    effort: medium
    from:   pgvector heaptids dedup, sqlite-vec validity-bitmap tombstones, sqlite-columnar dirty-chunk
            model

* Persist a small declarative index-spec string in the search_contract section (e.g.
  'hnsw(m=16,ef=200)+bm25(rrf)+rerank(exact)') so a .nest file self-describes deterministically
  how to search itself, generalizing the preset names into a portable contract.
    where:  crates/nest-format/src/sections/contract.rs (add an index_spec field to SearchContract,
            additive), cross-checked against the manifest in reader/validate.rs; nest-cli
            presets emit the spec.
    impact: Strengthens the sovereign/single-file/self-describing guarantee: the file carries its own search
            semantics, not the CLI version. Low risk, additive, makes presets future-proof as
            new quantized index types are added.
    effort: low
    from:   sqlite-vss Faiss factory-string DSL, lance vector-index decomposition (IVF x sub-index x
            quantization)

compression wins
------------------------------------------------------------------------------------------------
  - RaBitQ 1-bit on embeddings: ~28x vs f32 / ~8x vs current int8 (768-dim 3KB -> ~96 bytes +
    scalars), recall recovered by nest's existing rerank -- biggest single win on the dominant
    section.
  - TurboQuant 4-bit matches the int8 'tiny' preset at half the bytes (~8-16x) at
    equal-or-better recall; 2-bit 16x, 1-bit 32x, compile-time codebook so no determinism loss.
  - Rotational Quantization upgrade to int8: same 4x size, recall@10 0.992 -> ~0.998 -- free
    quality dividend buying room for a more aggressive global preset.
  - Dual-section split is itself a win: coarse section 1-2 bit + rerank source at f16 (2x)
    instead of f32 -> nano preset far below the 0.283 'tiny' ratio while keeping true-cosine
    returns.
  - FSST on chunks_canonical: ~2x over raw text while preserving O(1) citation-span access that
    block-zstd destroys.
  - Byte-stream-split + zstd for cold/archival embeddings: high ratio on f32 byte-planes for an
    'archive' preset, off the scored hot path.
  - Byte-identical embedding dedup: collapses duplicate vectors to one row at zero recall cost
    -- helps the near-duplicate-heavy PT-BR fake-news demo corpus.
  - Multi-bit query bit-planes: ship 1-bit storage (smallest file) and recover recall on the
    query side -- smallest file no longer forces worst recall.
  - Zone-map centroids double as residual-quantization anchors (vector = centroid + small
    residual) for a future structural codec beyond float16/int8.

watch-outs (conflict with nest constraints)
------------------------------------------------------------------------------------------------
  - DETERMINISM TRAP: trained PQ/IVF (milvus/knowhere, lance) needs k-means that is not
    byte-reproducible unless seed/init/iterations/tie-breaking are all pinned, and SIMD float
    non-associativity can still perturb centroids -- conflicts with nest's byte-identical-build
    constraint. Prefer the data-oblivious family; treat PQ as a later pinned-only option.
  - BROKEN-RERANK TRAP (in nest's own code): score_subset reranks against the SAME embeddings
    section it scored, so 1-2 bit storage silently makes the 'exact' rerank lossy and the
    returned score no longer real cosine. Any sub-int8 codec MUST ship a separate
    full-precision/f16 rerank source section.
  - FORMAT-FREEZE: every codec must be a new additive encoding id (reserved 4-255) and any new
    section a reserved id 0x09+, never bump NEST_FORMAT_VERSION; the rerank-source section must
    be a new OPTIONAL id kept OUT of content_hash so it cannot invalidate citations (embeddings
    is pinned at 0x04 in CANONICAL_SECTIONS).
  - HOT-PATH PURITY: RaBitQ/TurboQuant codes are scored in place (fine), but byte-stream-split
    and FSST are decode-required and must be restricted to cold/text sections, never the scored
    embeddings path -- enforce with the proposed transparent/opaque tag, not convention.
  - LICENSE: do NOT vendor VectorChord (AGPL/ELv2-style) or sqlite-vector/sqlite-columnar
    (Elastic License 2.0, source-available). Reimplement from the public papers; even permissive
    repos (qdrant/milvus/chroma/lance/pgvector) should be reimplemented, not copied.
  - SMALL-CORE: each codec/kernel <=300 lines (333 cap), repr(C), little-endian, typed errors,
    never panic; share ONE FWHT rotator across RQ/RaBitQ/TurboQuant; land incrementally (RQ
    first, then RaBitQ, then TurboQuant) to respect the ~3k/~4.9k loc budgets.
  - RECALL CLIFFS: 1-bit excels at high dim (1536+) but fails at low dim (sift-128, gist-960) --
    validate recall per demo model before any 1-bit default; keep int8/RQ as safe default, 1-bit
    opt-in nano.
  - DON'T copy sqlite-vss/sqlite-columnar on-disk shapes (monolithic blob caps at 1GB + O(N)
    write-amplification + no mmap; columnar store is 1.2x LARGER) -- steal only the algorithmic
    ideas.
  - Per-vector corrective scalars (2-3 f32) erode the ratio at low dim -- account for them so
    the nano size-ratio claim is honest.
