================================================================================================
synthesis :: data-pipeline
ML data lakes, dataset tooling, embedding benchmarks
================================================================================================

state of the art and concrete nest recommendations for this category.

summary:     Three reference systems define the state of the art for ML data-lake / dataset tooling, and
             their transferable value to nest is almost entirely architectural and
             metadata-layout, not codec: nest already wins on the embedding hot path (mmap SIMD
             dot, int8/f16 quantization, mandatory exact rerank). Deep Lake (Apache-2.0) is the
             highest-value steal: its run-length + cumulative-prefix-index encoders
             (ChunkIdEncoder/BytePositionsEncoder/ShapeEncoder) collapse per-sample sidecar
             metadata to O(distinct-runs) with O(log n) random access and no payload decode.
             This maps directly onto nest's cold-path metadata problem:
             crates/nest-format/src/sections/spans.rs today writes a full source_uri string plus
             two raw little-endian u64 per chunk for every chunk, so a 5k-chunk single-document
             corpus stores ~5k repeated URIs and ~80KB of offsets that are almost always
             contiguous (end[i]==start[i+1]) - structural redundancy zstd only partially
             removes. img2dataset (MIT) contributes the "shadow columnar sidecar" idea (tiny
             filterable SoA scalar columns separated from heavy payload, scanned without
             decoding the bulk) and the explicit 1:1 positional-alignment invariant; both fit
             nest's single-file model as a new additive section (reserved id 0x09+) plus a
             hardened frozen guarantee. MTEB (Apache-2.0) contributes a rigorous
             retrieval-quality protocol (nDCG@k / MRR@k / Recall@k via a trec_eval-equivalent
             metric set, content-addressed result caching, chunked exact top-k) that turns
             nest's anecdotal "tiny preset recall@10 0.992" into a reproducible, seeded,
             per-preset quality report and lets nest push compression harder with measured
             non-regression. None of the three offers a new entropy coder or quantizer to beat
             nest's embedding stack; the wins are structural-redundancy elimination in metadata,
             candidate pre-filtering before SIMD scoring, and a quality yardstick. All three
             respect nest's offline/deterministic/single-file constraints if the
             network/distributed machinery is dropped (img2dataset's downloader, MTEB's HF Hub
             cache tier) and re-implemented in-crate from the published ideas rather than
             vendored.

state of the art
------------------------------------------------------------------------------------------------
The data-pipeline category converges on one dominant pattern: separate heavy opaque payload from
tiny structured metadata, and make per-sample metadata grow with information content (distinct
runs) rather than with sample count. Deep Lake formalizes this with run-length +
cumulative-last-index encoders: each sidecar row is (value,
cumulative_last_sample_index_covered); consecutive identical values (same chunk, same shape,
same per-sample byte size) collapse to one row, and lookup is a binary search over the
cumulative column - so a fixed-shape 1B-sample tensor needs ONE shape row and ~150MB of chunk-id
encoder per 1PB, all addressable in O(log n) integer ops with zero payload decompression. It
splits sidecar metadata into a triplet (ChunkIdEncoder: sample->chunk, BytePositionsEncoder:
per-sample byte size with offsets recovered by prefix sum, ShapeEncoder: sample shape), stores
codec bytes verbatim (copy-without-recode when codecs match), packs variable-length samples into
~8MB bounded chunks, tiles oversized samples, and serves vectors with hnswlib HNSW that
exact-linear-scans under ~100k rows - the same mandatory-exact philosophy nest enforces.
img2dataset operationalizes the split as a "shadow sidecar": a parquet metadata file mirrors the
heavy WebDataset tar 1:1 (~1.6MB vs ~270MB tar in LAION-400M, >150x smaller), so all
filtering/stats/validation run on the small columnar file without touching payload, while a
deterministic positional composite key (SSSSSIIII = shard-id prefix + in-shard index) preserves
exact order alignment across tar/parquet/npy and makes builds resumable; multi-tier optional
hashing (md5/sha256/sha512) verifies samples. MTEB defines the quality-measurement state of the
art: a fixed BEIR-derived task schema (corpus, queries, relevant_docs as qid->cid->rel,
top_ranked candidate lists), chunked exact top-k similarity (corpus_chunk_size sub-batches keep
the matmul working set bounded so corpora larger than RAM still score), cosine implemented as
inner product on L2-normalized vectors, scoring via pytrec_eval (nDCG@k, MRR@k, Recall@k, MAP,
capped recall), and content-addressed per-(model,revision,task) JSON results in a tiered
HF-Hub/disk/in-memory cache so identical inputs never recompute. The unifying lesson for nest:
the scored array stays contiguous, raw, and order-aligned; everything else is small, columnar,
structurally de-redundant, and quality-certified.

top transferable innovations
------------------------------------------------------------------------------------------------
1. Deep Lake run-length + cumulative-prefix-index encoder: rows of (value,
   cumulative_last_index_covered), identical consecutive samples collapse to one row, O(log n)
   binary-search lookup with zero payload decode - eliminates structural redundancy in per-chunk
   metadata that zstd alone leaves on the table.
2. Triplet split of sidecar metadata (chunk-id / byte-positions / shape) with offsets recovered
   by prefix sum rather than stored verbatim - directly maps to nest spans where contiguous
   chunks satisfy end[i]==start[i+1] and need only a per-chunk length plus run boundaries.
3. img2dataset shadow columnar sidecar: tiny filterable SoA scalar columns (source_id, lang,
   byte_len, token_count, tag) stored apart from heavy payload, scanned to pre-filter candidates
   WITHOUT decoding text or touching embeddings (>150x size gap demonstrated).
4. Deduplicated value dictionary + run-length id stream for repeated strings (source_uri) - one
   run per source document instead of one verbatim string per chunk; insertion-stable dictionary
   keeps it deterministic.
5. Explicit 1:1 positional-alignment invariant across all parallel artifacts addressable by
   index i - nest's on-disk analog hardens the chunk_ids[i]/canonical[i]/spans[i]/embeddings[i]
   contract that nest://content_hash/chunk_id already relies on.
6. MTEB reproducible retrieval-quality protocol: nDCG@k / MRR@k / Recall@k via
   trec_eval-equivalent scoring over a fixed task schema, turning anecdotal recall claims into
   seeded per-preset reports that justify pushing compression harder.
7. MTEB chunked exact top-k (corpus_chunk_size sub-batches, descending sort, bounded working
   set) - formalizes nest's exact rerank as a cache-friendly streaming pass over mmap'd
   embedding sub-blocks for corpora larger than cache.
8. Content-addressed 'same inputs never recompute' result caching - nest's content_hash already
   delivers this for free; can self-certify recall inside the container.
9. Deep Lake native copy-without-recode (store codec bytes verbatim when codecs match) -
   principle for future nest payload types (pdf/audio/video) to avoid lossy re-encode
   round-trips.
10. img2dataset composite positional key (sortable shard-prefix + monotone index) enabling
   append-only incremental/extend rebuilds as new logical shard ranges without rewriting prior
   sections - aligns with nest's additive-only rule.

nest recommendations
------------------------------------------------------------------------------------------------
* Re-encode the chunks_original_spans (0x03) section with a deduplicated source_uri dictionary +
  run-length uri_id stream, plus delta/prefix-sum span encoding: for each contiguous run store
  (run_length, per-chunk length) and reconstruct absolute byte_start/byte_end by prefix sum
  exactly like Deep Lake's BytePositionsEncoder. Add a new section-encoding id (e.g.
  SECTION_ENCODING_SPANS_RLE = 4, within the reserved 4-255 range) so decode_payload dispatches
  to the new codec and decodes byte-identically to the current OriginalSpan vec.
    where:  crates/nest-format/src/sections/spans.rs (new encode/decode),
            crates/nest-format/src/encoding/mod.rs decode_payload dispatch + a new encoding
            module, crates/nest-format/src/layout/mod.rs encoding-id constant,
            crates/nest-format/src/writer/build.rs spans push site (replace maybe_zstd with the
            RLE encoder, still zstd-eligible on top).
    impact: high
    effort: medium
    from:   activeloopai/deeplake

* Add an optional additive 'chunk_scalars' section (reserve id 0x09) holding a compact columnar
  SoA of per-chunk filterable scalars (source_id u32, lang tag, byte_len/token_count varint,
  dataset tag) declared via a manifest capability, so nest-runtime can pre-filter candidate
  indices before SIMD scoring and nest-cli stats/filtered-search run as a pure metadata scan
  that never decodes chunks_canonical or touches embeddings. Columns are homogeneous,
  delta-friendly, and zstd-eligible. Optional sections already do NOT participate in
  content_hash, so citations stay valid and no version bump is needed.
    where:  crates/nest-format/src/layout/mod.rs (OPTIONAL_SECTIONS + id 0x09), new
            crates/nest-format/src/sections/chunk_scalars.rs (<=300 lines,
            single-responsibility), manifest capability flag in crates/nest-format/src/manifest,
            a candidate pre-filter hook in crates/nest-runtime/src/search.rs
            score_all/score_subset, and a filter flag in crates/nest-cli/src/cmd/search.rs +
            stats.rs.
    impact: high
    effort: medium
    from:   rom1504/img2dataset, activeloopai/deeplake

* Build a deterministic seeded retrieval-quality harness for the existing nest benchmark
  subcommand: adopt MTEB's task schema (corpus/queries/relevant_docs/top_ranked) and report
  nDCG@k, MRR@k, Recall@k vs the exact f32 baseline per preset, replacing today's single
  recall@k overlap number. One small metrics module per metric to honor the <=300-line
  single-responsibility rule; pure compute, no socket, fully offline and deterministic with a
  fixed seed.
    where:  crates/nest-cli/src/cmd/benchmark.rs (extend recall block into a metrics report), new
            crates/nest-runtime/src/metrics/ndcg.rs + mrr.rs + recall.rs modules, optionally
            exposed through nest-python.
    impact: high
    effort: medium
    from:   embeddings-benchmark/mteb

* Formalize the 1:1 ordered-alignment invariant (chunk_ids[i], chunks_canonical[i],
  chunks_original_spans[i], embeddings[i], and any new scalar column[i] all share index i) as an
  explicit frozen guarantee and assert it in the reader/validate path, strengthening the
  nest://content_hash/chunk_id resolution contract that materialize_hits already assumes when it
  indexes self.spans[idx] and self.chunk_ids[idx] in lockstep.
    where:  crates/nest-format/src/reader/validate.rs (cross-section length-equality assertions), documented
            in the layout module header and CONTRIBUTING conventions.
    impact: medium
    effort: low
    from:   rom1504/img2dataset

* Apply the same dictionary+RLE treatment to provenance and consider it for chunk_ids:
  provenance often repeats dataset-level fields across chunks; dedup them to one entry per
  distinct source. Leave chunk_ids' SHA-256 hex bodies raw (high-entropy, near-incompressible,
  correctly noted in build.rs) but RLE the structural framing if a sortable source-shard prefix
  is later adopted.
    where:  crates/nest-format/src/sections/provenance.rs, with the shared dictionary helper factored into
            crates/nest-format/src/sections/codec.rs to stay DRY and under the line cap.
    impact: medium
    effort: low
    from:   activeloopai/deeplake, rom1504/img2dataset

* Stream the exact-cosine rerank over mmap'd embedding sub-blocks using an MTEB-style
  corpus_chunk_size loop so the working set stays cache-resident on corpora larger than L2/L3,
  instead of one monolithic pass over all rows in score_all. Pure perf/locality refactor;
  results are byte-identical so determinism and the exact-rerank guarantee are untouched.
    where:  crates/nest-runtime/src/search.rs score_all (and score_subset for large unions), keeping the
            SIMD dispatcher in crates/nest-runtime/src/simd unchanged.
    impact: medium
    effort: low
    from:   embeddings-benchmark/mteb

* Optionally embed an additive eval-results section (reserve a later 0x09+ id) recording
  per-preset nDCG@k/Recall@k vs the exact f32 baseline, so a .nest container self-certifies its
  retrieval quality without re-running the harness; nest's content_hash already gives MTEB-style
  'same inputs never recompute' so the section is a cache of a deterministic computation.
    where:  crates/nest-format/src/layout/mod.rs (OPTIONAL_SECTIONS), new
            crates/nest-format/src/sections/eval_results.rs, populated by the nest-cli benchmark
            harness.
    impact: low
    effort: low
    from:   embeddings-benchmark/mteb

compression wins
------------------------------------------------------------------------------------------------
  - spans (0x03) dictionary+RLE: collapse ~5k verbatim source_uri strings to one dictionary
    entry per distinct document plus a run-length id stream - for single-document corpora this
    is near-constant instead of O(num_chunks), eliminating redundancy zstd only partially
    removes.
  - spans offset delta/prefix-sum: contiguous chunks satisfy end[i]==start[i+1], so store one
    run-length plus per-chunk length and recover absolute u64 offsets by prefix sum, replacing
    ~16 bytes of raw little-endian u64 per chunk (~80KB at 5k chunks) with a handful of bytes
    per run; the delta stream is also far more zstd-compressible than raw 64-bit offsets.
  - Eliminate structural redundancy BEFORE the entropy coder: zstd shrinks bytes but cannot
    remove the inherent redundancy of contiguous 64-bit offsets and repeated strings; doing
    dictionary+RLE first then zstd compounds the two, which is the core
    compress-more-than-everyone lever on the cold path.
  - Columnar SoA chunk_scalars section: homogeneous single-type columns (lang, byte_len,
    token_count) compress dramatically better under zstd than today's row-interleaved metadata,
    and delta-coding monotone columns shrinks them further.
  - Provenance dedup: one entry per distinct source instead of repeated dataset-level fields
    across every chunk reduces provenance from O(num_chunks) toward O(num_sources).
  - MTEB-style measured non-regression unlocks more aggressive embedding compression: with
    reproducible nDCG@k/Recall@k vs f32, nest can justify pushing int8 / smaller dims / tighter
    hnsw in the tiny preset (already 0.283 size ratio, recall@10 0.992) with proof rather than
    guesswork - quality measurement is itself a compression enabler.
  - All of the above target ONLY non-embedding cold-path sections (zstd-eligible, never the SIMD
    hot path) and are read once during materialize/cite, so they add zero query-latency cost
    while shrinking the file.

watch-outs (conflict with nest constraints)
------------------------------------------------------------------------------------------------
  - Do NOT vendor code: Deep Lake and MTEB are Apache-2.0, img2dataset MIT - re-implement the
    run-length/cumulative-index and metric ideas from the published descriptions (Deep Lake CIDR
    2023 paper) in-crate; the encoder/metric concepts are freely transferable but copying source
    pulls in license/attribution and bloat that conflict with the small clean-core goal.
  - Frozen-format discipline: any spans re-encoding must decode byte-identically to the current
    OriginalSpan representation so content_hash (over DECODED canonical sections) stays stable
    and citations keep resolving; use a new encoding id in the reserved 4-255 range or a
    transparent in-section re-encode, and never bump NEST_FORMAT_VERSION (that is reserved for a
    true v2 where an existing field changes meaning).
  - Determinism: the source_uri dictionary must be insertion-stable (not hash-ordered) and RLE
    runs must form deterministically, or byte-identical reproducibility (same chunks + same
    model fingerprint => identical file) breaks; mirror the existing alphabetical-bm25 /
    seeded-hnsw discipline.
  - Drop all network/distributed machinery: img2dataset's downloader/fsspec/pyspark and MTEB's
    HuggingFace-Hub remote cache tier violate offline-by-construction (runtime never opens a
    socket) - only the on-disk layout, positional-key, and metric ideas transfer; keep MTEB's
    tiered cache to local-filesystem + in-memory only.
  - Line/scope cap: each new piece (spans codec, chunk_scalars section, each metric) must be its
    own <=300-line single-responsibility module (333 hard cap); resist a monolithic
    'metadata-v2' module - factor the shared dictionary helper into sections/codec.rs.
  - Embeddings stay raw and mmap-scored: none of these ideas may touch the embeddings section
    encoding or the SIMD scoring path; Deep Lake's chunk-packing/tiling is for variable-shape
    tensors and must not fragment nest's contiguous, 64-byte-aligned, directly-scored embedding
    array.
  - Pre-filter must not weaken the exact-rerank guarantee: a chunk_scalars candidate filter
    changes WHICH chunks are scored, not HOW they are scored, and must be opt-in and documented
    so it never silently degrades the recall=1.0 exact ground truth the search_contract
    promises.
  - Additive-only for any new section: chunk_scalars / eval_results must be OPTIONAL sections
    (id 0x09+) that do not participate in content_hash, so adding them to an existing corpus
    does not invalidate prior citations; gate them behind a manifest capability flag.
  - bm25 tokenizer is still word-segmented (degrades on CJK/Thai) - a known gap unrelated to
    these steals; do not let a metadata-quality harness mask that the lexical path needs
    separate attention for the PT-BR/CJK demo corpora.
  - MTEB metrics depend on relevance judgments (relevant_docs); nest's demo corpus has none yet,
    so the quality harness needs a seeded synthetic or hand-labeled qrels set to be meaningful -
    budget for building that, or the nDCG/MRR numbers are vacuous.
