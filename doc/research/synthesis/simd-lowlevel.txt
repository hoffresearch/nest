================================================================================================
synthesis :: simd-lowlevel
SIMD, vectorization, portable intrinsics, fast string ops
================================================================================================

state of the art and concrete nest recommendations for this category.

summary:     This category is fundamentally a serve-side accelerator for nest's compression mission, not a
             compressor itself: none of the 12 repos add an entropy coder, but collectively they
             answer the one question that gates how far nest can push quantization: "can the
             smallest-on-disk embedding format also be the fastest to score directly off mmap,
             bit-identically on every CPU?" The state of the art has converged hard on one
             dispatch idiom that nest already implements correctly: detect CPU features once,
             cache in a OnceLock/atomic-bitset, then indirect-call a per-arch kernel with zero
             per-element CPUID cost (stdarch, Highway, memchr, StringZilla, ACL all do exactly
             this; nest's simd/mod.rs is a faithful copy). nest's current code is solid but
             leaves three concrete, code-confirmed wins on the table. (1) The AVX2 f16 path in
             simd/mod.rs lines 104-112 explicitly bails to scalar to dodge the F16C detection
             branch, taxing the compressed/tiny presets on x86; stdarch's vcvtph2ps
             (_mm256_cvtph_ps) converts 8 f16->f32 in one instruction. (2) The int8 path
             (avx2.rs lines 36-60, neon.rs 68-95) widens i8->i32->f32 then FMAs in f32, which is
             both slow AND reduction-order-dependent (float horizontal sum is not associative,
             so the cross-arch parity tests only pass within 1e-4, not bit-exact); ACL/stdarch
             show vpdpbusd (AVX-VNNI) and vdotq_s32 (NEON dotprod) do 4 int8 MACs/lane into i32
             in ONE instruction with reduction-order-INDEPENDENT integer accumulation, which is
             both ~4x faster on the tiny preset's hot path AND restores true bit-determinism (a
             nest hard requirement that float reduction currently only approximates). (3) Top-k
             selection is a full sort_by over all n scored pairs (search.rs lines 128, 213,
             260), where x86-simd-sort/Highway's branch-free compressstore partition + select
             gives a faster, branchless top-k that keeps the mandatory exact-cosine rerank cheap
             as corpora grow. The int8 codec's 8-byte prefix (payload_version + scale_kind
             discriminators, int8.rs lines 17-19) confirms asymmetric scale+zero_point quant and
             sub-byte formats (int4/binary) are genuinely additive - new
             scale_kind/payload_version values, no NEST_FORMAT_VERSION bump, no new encoding id
             needed. The deepest structural steal is the witness-token /
             write-once-generic-kernel pattern (fearless_simd, memchr's Vector trait): nest
             currently hand-maintains a 3 dtype x 3 ISA matrix of near-duplicate unsafe
             functions, and every new quantized dtype (int4, bf16, binary) multiplies that
             matrix; one generic dot_f32<S: Simd> body with thin per-arch shims plus a verified
             scalar oracle collapses it, keeps files under the 300-line cap, and removes unsafe
             from the hot path - the enabler for pushing the tiny preset below its current 0.283
             ratio without a portability tax. Watch-outs: never adopt faster's compile-time-only
             dispatch (pins the binary to the build host ISA, breaks the
             single-portable-offline-binary promise); vendor patterns clean-room rather than
             depending on experimental crates (fearless_simd is explicitly pre-stable) to
             protect the frozen-format/determinism guarantees; and the mandatory scalar fallback
             must remain a first-class verified sibling for sovereign portability to
             old-x86/RISC-V where the dispatcher drops straight to scalar.

state of the art
------------------------------------------------------------------------------------------------
The field has fully converged on "runtime feature dispatch over a write-once generic kernel":
compile every kernel variant once (per ISA), detect CPU capability ONCE via getauxval(AT_HWCAP)
on aarch64 / CPUID leaf 7 on x86, cache the result lock-free (atomic bitset in stdarch, OnceLock
function-pointer in nest/Highway/memchr), then indirect-call the chosen kernel per hot-path
entry with zero per-element branch cost. The frontier has moved to TWO refinements nest has not
yet adopted. First, FINE-GRAINED feature detection: not just "avx2" but f16c,
avxvnni/avx512vnni, aarch64 dotprod/i8mm as SEPARATE gates, because the single most valuable
instructions for quantized scoring (vcvtph2ps for f16->f32, vpdpbusd/vdotq_s32 for
4-int8-MACs-into-i32) live behind those finer flags. Second, INTEGER-DOMAIN quantized dot
products (ACL's GEMMLowp): accumulate int8*int8 into int32 with hardware dot-product
instructions and apply scale/zero_point only at the end, which is both ~4x faster than
widen-to-f32-then-FMA AND reduction-order-independent (hence bit-reproducible across CPUs,
unlike float horizontal sums). The portable-kernel-authoring frontier is the witness-token
pattern (fearless_simd: a ZST type-level proof of an enabled target_feature makes core::arch
intrinsics safe to call) and the write-once Vector-trait shim (memchr, Highway, SIMDe's
per-function cascade), both of which collapse the NxM (dtype x ISA) unsafe kernel matrix into
one generic body. Two reusable SIMD primitives recur as the engine behind everything else: the
nibble-LUT-via-byte-shuffle (pshufb/vpshufb/vtbl) for branchless byte classification (simdutf
UTF-8 validation at <1 instr/byte, StringZilla's 21 GB/s sz_lookup, base64 codecs), and
compressstore/Compress stream-compaction (vpcompressd on AVX-512, table-driven permute-LUT
emulation on AVX2, shuffle-table on NEON) for branch-free partition/top-k/filter (x86-simd-sort,
Highway vqsort). Correctness discipline has standardized on QEMU/SIMDE_NO_NATIVE differential
testing (the scalar path is a verified equivalence sibling, not an afterthought) and stdarch's
assert_instr (disassemble the compiled shim to prove the intended instruction was actually
emitted). The one anti-pattern the field flags explicitly is compile-time-only width selection
(faster, and any -C target-feature global build): it pins the binary to the build host's widest
ISA, which is incompatible with shipping one portable offline binary.

top transferable innovations
------------------------------------------------------------------------------------------------
1. Integer-domain int8 dot product via hardware dot-product instructions (ACL GEMMLowp):
   vpdpbusd (AVX-VNNI) / vdotq_s32 (NEON dotprod) do 4 int8 MACs/lane into int32 in one
   instruction, scale applied at the end. ~4x faster than nest's i8->i32->f32-widen-then-FMA AND
   reduction-order-independent, making the tiny preset both fastest AND truly bit-deterministic.
2. Fine-grained feature gates + single-instruction conversion (stdarch):
   is_x86_feature_detected!("f16c") -> _mm256_cvtph_ps (8 f16->f32 in one vcvtph2ps);
   avxvnni/dotprod gates. Fixes the perf gap nest's own mod.rs 104-112 documents.
3. Witness-token / write-once generic SIMD kernel (fearless_simd + memchr Vector trait): one
   dot_f32<S: Simd> body per dtype with thin per-arch shims and a verified scalar oracle,
   collapsing nest's 3x3 unsafe matrix and removing unsafe from the hot path.
4. Branch-free compressstore stream-compaction (x86-simd-sort + Highway): mask+compressstore for
   branchless top-k/threshold filter (vpcompressd / AVX2 permute-LUT / NEON shuffle-table),
   replacing the full sort_by top-k and keeping exact-cosine rerank cheap at scale.
5. Asymmetric scale+zero_point quantization (ACL): more fidelity per int8 than symmetric
   max_abs/127, enabling aggressive int4 without recall loss; additive via a new int8 scale_kind
   discriminator.
6. Default-value tail padding (faster): pad the final partial vector with the FMA identity so
   one full-width FMA finishes the dim, removing the hand-written remainder loops and per-query
   tail branch.
7. Lane-widening upcast/downcast + vtbl/pshufb bit-unpack (faster + StringZilla): the blueprint
   for int4 (2 lanes/byte) and binary kernels that push the tiny preset below 0.283.
8. Nibble-LUT-via-byte-shuffle (simdutf + StringZilla): <1 instr/byte UTF-8 validation before
   content_hash, plus the primitive for a codepoint-aware bm25 tokenizer that fixes the CJK/Thai
   gap.
9. Packed-pair rare-byte prefilter (memchr): allocation-free vectorized term scan over mmapped
   chunks_canonical for bm25/search-text, and selective prefilters over int8 dimensions.
10. MinHash/Rabin retrieve-then-rerank sketch (StringZilla): deterministic near-duplicate dedup
   to drop chunks before encoding (raising ratio) and a candidate pre-filter mirroring nest's
   HNSW+rerank contract.

nest recommendations
------------------------------------------------------------------------------------------------
* Add fine-grained feature tiers to the int8 hot path: gate
  is_x86_feature_detected!("avxvnni")/("avx512vnni") to use _mm256_dpbusd_epi32 (vpdpbusd) and
  is_aarch64_feature_detected!("dotprod") to use vdotq_s32, accumulating int8*int8 into i32 and
  multiplying by the per-vector scale ONCE at the end. Keep the current widen-to-f32 path as the
  fallback tier. Crucially this also makes int8 scoring reduction-order-independent (integer
  accumulation), restoring true cross-CPU bit-determinism that the current float-FMA path only
  approximates.
    where:  crates/nest-runtime/src/simd/avx2.rs (new dot_i32_i8_vnni alongside dot_f32_i8_avx2 lines
            36-60), crates/nest-runtime/src/simd/neon.rs (dot_i32_i8_dotprod alongside
            dot_f32_i8_neon lines 68-95), dispatch + new SimdBackend variants (Avx2Vnni,
            NeonDotprod) in simd/mod.rs; score path unchanged in search.rs
            score_all/score_subset DType::Int8 arms.
    impact: high: ~4x int8 throughput on the tiny preset (the most-compressed embedding format, 0.283 ratio,
            recall@10 0.992), turning the smallest-on-disk format into the fastest-to-search,
            AND restoring true bit-determinism on the int8 path
    effort: medium: two new kernels + scalar i32 reference + two dispatch tiers; integer accumulation
            simplifies the parity test (exact equality, not epsilon); stays under the 300-line
            file cap
    from:   https://github.com/ARM-software/ComputeLibrary, https://github.com/rust-lang/stdarch

* Add an F16C tier to the AVX2 f16 path so the compressed/tiny f16 presets stop falling back to
  scalar on x86. Gate is_x86_feature_detected!("f16c") and use _mm256_cvtph_ps (vcvtph2ps) to
  convert 8 f16 lanes to f32 in one instruction, then FMA against the f32 query, mirroring the
  existing NEON fcvtl path (neon.rs dot_f32_f16_neon lines 39-66).
    where:  crates/nest-runtime/src/simd/avx2.rs (new dot_f32_f16_avx2), wired into simd/mod.rs
            dot_f32_f16_bytes which currently bails to scalar at lines 104-112 with a code
            comment admitting the gap
    impact: high: removes a documented, self-flagged perf gap; gives the compressed preset (zstd/f16) a real
            x86 SIMD dot path instead of scalar, directly lowering per-query latency on the
            second-most-compressed embedding format
    effort: low: ~25 lines, one new feature tier, parity test already exists (tests.rs
            f16_simd_matches_scalar)
    from:   https://github.com/rust-lang/stdarch, https://github.com/nemequ/simde

* Replace the full sort_by top-k (over all n scored pairs) with a branch-free SIMD
  select/partition: compute scores in a register, mask=(score>=running_threshold), compressstore
  the surviving (score,index) pairs densely (vpcompressd on AVX-512, 256-entry permute-LUT on
  AVX2, NEON shuffle-table, scalar fallback), then a partial top-k on the survivors. Carry the
  index payload in lockstep with the score (x86-simd-sort key-value pattern) so the sorted top-k
  comes out without a separate gather.
    where:  new crates/nest-runtime/src/simd/compress.rs (table-driven Compress + select), called from
            search.rs sort_scores_desc/score_all top-k (lines 128, 260) and the ANN/hybrid
            rerank truncation (lines 163, 213-216)
    impact: medium: keeps the mandatory exact-cosine rerank cheap as corpora grow; branchless filtering
            pairs directly with the dot-product kernel; pure compute with fixed LUTs =>
            byte-identical deterministic results, respects additive-format/never-panic
    effort: medium-high: compressstore is AVX-512-native but must be permute-LUT-emulated on AVX2 and
            shuffle-table on NEON, plus a mandatory scalar fallback; this is the highest-effort
            item and only pays once n is large
    from:   https://github.com/intel/x86-simd-sort, https://github.com/google/highway

* Refactor the 3-dtype x 3-ISA unsafe kernel matrix into ONE generic body per dtype using a
  vendored (not crate-dependency) witness-token / Vector-trait pattern: dot_f32<S: Simd>,
  dot_f32_f16<S: Simd>, dot_f32_i8<S: Simd> with thin per-arch shims, the scalar path as a
  verified equivalence sibling. Factor the f16->f32 and i8->i32 widening steps (currently
  inlined in avx2.rs/neon.rs) into small shared inlined helpers so adding int4/bf16/binary
  becomes one widen-helper + one scalar reference, not a new per-arch matrix.
    where:  crates/nest-runtime/src/simd/ - collapse avx2.rs/neon.rs/scalar.rs duplication; keep the
            OnceLock+function-pointer dispatch in mod.rs unchanged (it is already the correct
            model)
    impact: medium: removes unsafe from the hot path (satisfies never-panic/clean-core), keeps every file
            under the 300-line cap, and is the structural enabler for cheaply adding sub-byte
            quantized dtypes that push compression below 0.283
    effort: medium: vendor the pattern clean-room (do NOT depend on the experimental fearless_simd crate);
            requires careful #[inline(always)] discipline (a missed inline silently
            de-optimizes); verify byte-identical machine code via assert_instr before/after
    from:   https://github.com/linebender/fearless_simd, https://github.com/BurntSushi/memchr,
            https://github.com/nemequ/simde

* Add an additive asymmetric int8 codec (scale + zero_point) as a new int8 scale_kind, plus
  design an int4 packed codec as a new payload_version, both behind the existing 8-byte int8
  prefix discriminators. Asymmetric quant packs more fidelity per int8, enabling more aggressive
  quantization toward int4 without recall loss. The integer-domain VNNI/dotprod kernels above
  fold the (a-zp_a)*(b-zp_b) expansion into a precomputed offset-correction term so the hot loop
  stays a single dot instruction.
    where:  crates/nest-format/src/encoding/int8.rs - new INT8_SCALE_KIND_ASYMMETRIC (=1) writing per-vector
            zero_point alongside scale; a future int4.rs as a new encoding id (4-255
            reserved/additive) or new payload_version; reader/validate.rs int8 parse arm;
            runtime dot_i32_i8 kernels consume the zero_point
    impact: high (compression frontier): more fidelity per byte than nest's current symmetric max_abs/127,
            the lever that beats the 0.283 tiny ratio while keeping real-cosine rerank and
            recall; genuinely additive (scale_kind/payload_version discriminators already exist
            in int8.rs lines 17-19), no NEST_FORMAT_VERSION bump
    effort: medium-high: codec + offset-correction math + parity/recall validation; sub-byte int4 unpack
            needs the vtbl/pshufb lane-widening kernel; must keep deterministic build (same
            chunks+model => byte-identical)
    from:   https://github.com/ARM-software/ComputeLibrary, https://github.com/AdamNiederer/faster,
            https://github.com/ashvardanian/StringZilla

* Kill the hand-written scalar remainder loops in the SIMD kernels with default-value tail
  padding: pad the embedding row's final partial vector with the FMA identity (0.0) so one
  full-width FMA finishes the dim, removing the per-query tail branch. (Embedding dims 384-1536
  are usually multiples of 8/4 but not guaranteed; padding makes the kernel uniform.)
    where:  crates/nest-runtime/src/simd/avx2.rs (remove tail loops lines 18-28 and 52-58),
            crates/nest-runtime/src/simd/neon.rs (lines 19-29, 57-64, 89-92)
    impact: low-medium: shrinks each kernel, removes a per-query branch on the row-scoring hot path that
            runs for EVERY row off mmap; faster's benches show uneven-within-1%-of-even after
            padding
    effort: low: a few lines per kernel, but must handle the mmap boundary safely (pad into a local buffer
            for the final partial vector, never read past the section), and re-run parity tests
    from:   https://github.com/AdamNiederer/faster

* Vendor simdutf's lookup-table UTF-8 validation pattern (or depend on the MIT/Apache
  rusticstuff/simdutf8 Rust port) to validate/normalize chunks_canonical at <1 instr/byte BEFORE
  computing content_hash, killing a class of non-deterministic decode bugs that would silently
  break content_hash stability across encodings.
    where:  crates/nest-format/src/sections/canonical.rs (validate before the content_hash surface),
            reachable from the writer encode path and reader/validate.rs
    impact: medium (correctness): hardens the content_hash STABLE-across-encodings guarantee, which is
            load-bearing for citations (nest://content_hash/chunk_id) and deterministic builds
    effort: low: rusticstuff/simdutf8 is a drop-in zero-dep crate with the exact lookup algorithm; respects
            offline/never-socket constraint
    from:   https://github.com/simdutf/simdutf, https://github.com/BurntSushi/memchr

* Adopt stdarch's assert_instr verification discipline plus SIMDe's NO_NATIVE differential-test
  idea in the SIMD test suite: a disassembly check that the int8/f16/f32 kernels actually emit
  vfmadd/vpdpbusd/vcvtph2ps/vdotq_s32, and a forced-scalar-vs-SIMD parity gate
  (NEST_FORCE_SCALAR already exists). For the new integer VNNI/dotprod int8 path, assert EXACT
  equality (not epsilon) since integer accumulation is reduction-order-independent.
    where:  crates/nest-runtime/src/simd/tests.rs (extend the existing parity tests at lines 45-99; the
            NEST_FORCE_SCALAR env hook is already wired in mod.rs detect_backend)
    impact: medium: catches a refactor that silently drops a fused instruction or de-optimizes (a real risk
            of the witness-token refactor); proves the three+ backends return identical results
            on the same .nest file, protecting exact-rerank ground truth and deterministic
            builds
    effort: low: test-only, zero runtime cost; assert_instr is a proc-macro shim
    from:   https://github.com/rust-lang/stdarch, https://github.com/nemequ/simde,
            https://github.com/DLTcollab/sse2neon

* Add a deterministic MinHash/Rabin-fingerprint sketch as an optional section (id 0x09+,
  reserved) and/or a build-time near-duplicate dedup pass: drop redundant chunks before encoding
  to raise the effective compression ratio, and use the compact sketch as a candidate pre-filter
  that shrinks the set before the mandatory exact-cosine rerank, mirroring nest's existing
  HNSW+rerank contract.
    where:  crates/nest-format/src/sections/ (new sketch section, deterministic alphabetical/seeded like
            bm25/hnsw); build-time dedup in nest-python build path; runtime pre-filter in

    impact: medium (compression + serve): dedup directly raises effective ratio toward

    effort: medium-high: new optional section + deterministic sketch construction + must preserve

    from:   https://github.com/ashvardanian/StringZilla

* Add a binary/Hamming embedding kernel as the most extreme tiny-class preset: pack embeddings
  to 1 bit/dim (sign), score with popcount(xor) (vpternlogq+vpopcntq on AVX-512, NEON cnt+addv,

    where:  new crates/nest-format/src/encoding/binary.rs (new encoding id, additive),
            crates/nest-runtime/src/simd/ binary dot kernel, search.rs DType::Binary arm feeding

    impact: high (compression frontier, speculative): 1 bit/dim is the single biggest lever to beat 0.283;

    effort: high: new codec + popcount kernels per ISA + recall validation + rerank integration; recall@10
            must be proven on the PT-BR corpus before shipping as a preset
    from:   https://github.com/AdamNiederer/faster, https://github.com/ARM-software/ComputeLibrary,

compression wins
------------------------------------------------------------------------------------------------
  - Asymmetric scale+zero_point int8 quantization (ACL GEMMLowp) packs more fidelity per byte
    than nest's current symmetric max_abs/127 scheme (encoding/int8.rs line 34), enabling more
    aggressive quantization toward int4 without recall loss - additive via a new scale_kind
    discriminator already reserved in the int8 8-byte prefix, no format bump.
  - Integer-domain VNNI/dotprod scoring (vpdpbusd/vdotq_s32) makes the smallest-on-disk int8
    format (tiny preset, 0.283 ratio, recall@10 0.992) ALSO the fastest to score off mmap,
    removing the latency tax that currently makes quantized dtypes slower per query than f32 -
    so nest can DEFAULT to harder compression without losing the serve-from-disk speed promise.
  - An int4 packed codec (new payload_version behind the existing int8 prefix) unpacked via the
    lane-widening vtbl/pshufb pattern: ~2x smaller than int8 on the embedding section (the bulk
    of bytes, never zstd-compressed because scored from mmap), the realistic next step below
    0.283 with a mandatory exact-cosine rerank guarding recall.
  - A binary/Hamming 1-bit-per-dim codec scored with popcount(xor) is the single largest
    embedding-size lever (32x smaller than f32); the mandatory exact-cosine rerank on survivors
    keeps the returned score real cosine, so recall is recoverable - the most aggressive path
    toward compress-more-than-everyone.
  - MinHash/Rabin-fingerprint near-duplicate dedup (StringZilla) drops redundant chunks BEFORE
    encoding, raising the effective compression ratio on the whole .nest file without any new
    entropy coder - a deterministic, seeded, reproducible-build-safe win.
  - Branch-free top-k/compressstore + faster dispatched kernels free up the rerank budget, which
    is what lets nest AFFORD finer per-block quantization (int4/int8 with SIMD dequant) at serve
    time without blowing the mandatory exact-cosine rerank latency target - the serve-side
    headroom that makes harder on-disk compression viable.
  - Sorted/clustered embeddings (cheap branch-free argsort from x86-simd-sort at build time)
    improve residual locality, so delta+int8 quantization of reordered rows compresses better -
    a real but second-order assist for the tiny/compressed presets.
  - Keeping more NON-embedding sections zstd-compressed is safe for latency because
    memchr/StringZilla give allocation-free vectorized term/substring scan over decoded text, so
    bm25/search-text stay fast even with compressed sections - buying ratio on the text side
    without hurting serve speed.

watch-outs (conflict with nest constraints)
------------------------------------------------------------------------------------------------
  - Do NOT adopt faster's (or any -C target-feature global) compile-time-only width selection:
    it pins the binary to the build host's widest ISA, directly breaking nest's
    single-portable-offline-binary promise. Borrow faster's tail-padding/lane-widening kernel
    tricks ONLY; keep nest's runtime OnceLock function-pointer dispatch, which is strictly
    better here.
  - Vendor patterns clean-room, never depend on the experimental crate: fearless_simd is
    explicitly 'extremely early experimental, no stability guarantees'; a frozen-format,
    deterministic-build database cannot pin its hot path to a pre-stable dependency. Same for
    any crate whose codegen could drift and break byte-reproducibility.
  - Float horizontal-sum reduction is NOT associative, so the current f32/f16/i8-widened paths
    are only ~1e-4 close across CPUs, not bit-identical - a latent risk to nest's deterministic
    guarantee if any caller ever hashes or compares raw scores. The integer-domain int8 path
    (VNNI/dotprod) FIXES this (reduction-order-independent); prefer it precisely for
    determinism, not just speed.
  - The mandatory scalar fallback must stay a first-class, parity-verified sibling (SIMDe
    NO_NATIVE discipline), because nest's dispatcher drops straight to scalar on old x86 /
    RISC-V / non-NEON ARM - sovereign portability means the scalar path is load-bearing, not an
    afterthought. Keep it shape-friendly (fixed chunked loops, fixed-width types) so it still
    auto-vectorizes off-target.
  - compressstore (vpcompressd) is AVX-512-native and must be permute-LUT-emulated on AVX2 and
    shuffle-table-emulated on NEON, with a mandatory scalar fallback - the top-k/compress steal
    is the highest-effort item and only pays once n is large; don't pay its complexity cost
    prematurely on small corpora.
  - Any new int8/int4/binary codec must keep the int8 prefix discriminators
    (payload_version/scale_kind) additive and must NOT touch existing field meanings, or it
    forces a true v2 NEST_FORMAT_VERSION bump. Confirmed safe today: int8.rs lines 17-19 already
    version the layout. Validate that the writer stays deterministic (same chunks+model =>
    byte-identical) for every new codec.
  - sse2neon-class semantic gaps are real on the quantized path: _mm_rsqrt_ps(0.0) is NaN on
    NEON vs INF on SSE, and min/max NaN ordering differs unless PRECISE flags are set. nest's
    NaN guard runs before rerank (search.rs validate_query lines 28-31) but any new SIMD
    reduction must preserve identical NaN/rounding behavior across backends or the cross-arch
    parity tests will (correctly) fail.
  - Sub-byte and SIMD kernels must not blow the <=300-line-per-file cap or the
    single-responsibility rule; the witness-token/generic-body refactor is what KEEPS them under
    the cap, so do that refactor BEFORE multiplying dtypes, not after. A missed
    #[inline(always)] in that pattern silently de-optimizes the hot loop - gate with
    assert_instr.
