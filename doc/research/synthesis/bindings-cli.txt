================================================================================================
synthesis :: bindings-cli
language bindings, CLI ergonomics, distribution/client surfaces
================================================================================================

state of the art and concrete nest recommendations for this category.

summary:     This category is about nest's client/distribution surface (nest-python pyo3 bridge, nest-cli
             clap surface) and how vector data crosses language boundaries. None of these repos
             contains an entropy coder, quantizer, or on-disk codec, so their direct compression
             contribution is zero; their value is to the "portable, cheap, light,
             install-anywhere, allocation-free-at-the-boundary" pillars of the north star. The
             collective state of the art has four pillars. (1) PyO3 stable-ABI distribution: one
             cp312-abi3 wheel per OS/arch loads on every CPython >= 3.12 (and via abi3t/PEP-803
             on free-threaded builds too), decoupling the binary from the interpreter patch
             version; paired with zero-copy buffer-protocol borrows
             (PyBuffer<f32>/PyReadonlyArray1) so a numpy query array is read in place as &[f32]
             instead of marshalled element-by-element. (2) Weaviate's tag-then-pack vector wire
             discipline: a vector is ONE contiguous little-endian float32 bytes blob plus a tiny
             side-enum (SINGLE/MULTI/quantized) - never `repeated float` proto framing (~5
             bytes/elt) - with element count recovered from byte-length (len//4) rather than
             stored, exactly mirroring nest's mmap-contiguous, scored-directly embeddings layout
             and confirming the win for vectors is layout+quantization, not entropy coding. (3)
             clap's "the binary is the source of truth": Jaro did_you_mean typo correction on
             the error branch, and a re-exec dynamic-completion protocol (CompleteEnv) that can
             read the actual file for candidate completion, plus feature-gated crate split for
             minimal binary size. (4) Weaviate's search-semantics knobs (minimum_should_match /
             OR operator, relativeScoreFusion min-max normalized weighted sum) and Helm's
             uniform-config-record + deterministic-fold pattern for declarative, reproducible
             build profiles. Critically, I verified against nest's source:
             nest_file.rs:22-24/35-37/54-56 do query.extract::<Vec<f32>>() (a full heap
             alloc+memcpy per search), every nest-runtime search fn (search.rs:124/147/181)
             already takes &[f32], the search is read-only over an immutable mmap (so
             Python::detach is sound and deterministic), nest-python is on pyo3 0.28 +
             abi3-py312 + cdylib (baseline correct), there is NO maturin/pyproject build path
             (pyproject.toml explicitly disclaims publishing), and nest-cli uses clap v4 with
             only the `derive` feature (no `suggestions`/`unicode`). So the steals are concrete
             upgrades, not green-field adoption.

state of the art
------------------------------------------------------------------------------------------------
Four converging pillars. ABI/DISTRIBUTION (PyO3): the stable ABI is a *build feature* not a
source macro - opting into abi3-pyXY makes the linker emit only Py_LIMITED_API symbols so one
.so loads on every CPython >= floor; PEP-803 abi3t extends this to free-threaded builds with an
opaque-PyObject variant forward-compatible to all future 3.X; maturin produces the single
cp312-abi3 manylinux/macos/windows wheel. ZERO-COPY FFI (PyO3): Bound<'py,T> = (Py<T> handle,
Python<'py> GIL token) drops the refcount on Drop; the buffer protocol via PyBuffer<f32> /
rust-numpy PyReadonlyArray1 borrows a contiguous backing store as &[f32] with no copy;
Python::detach releases the GIL around a pure-Rust compute so concurrent threads run. VECTOR
WIRE LAYOUT (Weaviate py/go clients): tag-then-pack - one struct.pack contiguous little-endian
f32 bytes blob + a side VectorType enum carrying dtype/layout out-of-band, count derived from
len//4, additive room for int8/fp16 tags without touching the byte run; this is the wire twin of
mmap-and-score-directly and explicitly avoids protobuf's ~5 bytes/float repeated-field overhead.
CLI ERGONOMICS (clap): the binary is the runtime source of truth for valid inputs - strsim::jaro
did_you_mean at 0.7 cutoff on the error path, CompleteEnv re-exec completion that can
interrogate real data, CompletionCandidate decoupling generation from per-shell rendering,
feature-gated crate split for binary-size minimization. SEARCH SEMANTICS + CONFIG (Weaviate +
Helm): minimum_should_match/OR BM25 operator and relativeScoreFusion (per-result-set min-max
normalize then weighted sum) as deterministic alternatives/additions to reciprocal-rank fusion,
both feeding a single rerank; and the uniform-config-record schema folded deterministically into
a feature manifest (Helm's ENABLE_MODULES fold, version-pinning-by-tag for reproducibility,
static pinned distribution channel).

top transferable innovations
------------------------------------------------------------------------------------------------
1. PyO3 buffer-protocol zero-copy borrow (PyBuffer<f32>/PyReadonlyArray1): read the numpy query
   array's backing memory in place as &[f32], eliminating the per-search Vec<f32> alloc+memcpy
   that nest_file.rs currently pays before the SIMD kernel - highest value, smallest surface,
   hot path.
2. abi3 + abi3t single-wheel distribution via maturin: one cp312-abi3 wheel runs on
   3.12/3.13/3.14+ and (with abi3t) free-threaded builds, directly closing nest's listed
   PyPI/maturin gap and delivering the 'install-anywhere' leg of the north star for the
   python-builds half.
3. Weaviate tag-then-pack vector layout (contiguous LE-f32 bytes + 1-byte dtype side-enum, count
   = len//4): validates nest's mmap-contiguous embeddings choice and gives the discriminator-tag
   pattern that lets nest swap f32->f16->int8 per named-vector with zero per-element decode and
   no NEST_FORMAT_VERSION bump.
4. Python::detach (release GIL) around the read-only mmap search: lets concurrent Python threads
   issue parallel deterministic searches against one open NestFile, since the file is immutable
   post-build - free throughput with no correctness/determinism cost.
5. clap Jaro did_you_mean (suggestions feature, deterministic 0.7 cutoff): typo correction over
   the 8 subcommand names AND extensible over real container chunk_ids so a missed `nest cite`
   suggests the nearest valid id, on the error branch only (zero hot-path cost).
6. clap CompleteEnv re-exec dynamic completion that reads the actual .nest file for
   content_hash/chunk_id/preset completion - offline, single-file, but MUST stay in pure-rust
   nest-cli/nest-runtime so the ~300-500ms python boot never lands on the completion path.
7. Weaviate search-semantics knobs: minimum_should_match/OR BM25 operator (alphabetical term
   order = reproducible) and relativeScoreFusion as a typed alternative to reciprocal-rank
   fusion, both feeding the SAME mandatory exact-cosine rerank so ground-truth scoring is
   unchanged.
8. Helm uniform-config-record + deterministic-fold: a declarative build profile (TOML) where
   each section/codec is a {enabled, encoding, params} record folded into the writer's section
   table, making 'add hnsw_index(0x07)/bm25_index(0x08)' one boolean and keeping reproducible
   builds honest via version-pinning-by-tag (model fingerprint + codec versions).
9. clap feature-gated crate split: make hnsw/bm25/pyo3 opt-in cargo features so the smallest
   sovereign binary ships only what a given deployment needs.
10. Count-from-byte-length trick (len//(dim*elt_size)): derive element/row counts from the
   section byte length instead of storing a redundant count, shaving header bytes - a micro-win
   consistent with nest's compress-more discipline.

nest recommendations
------------------------------------------------------------------------------------------------
* Replace query.extract::<Vec<f32>>() with a zero-copy PyBuffer<f32> borrow, passing the
  borrowed &[f32] straight to nest-runtime's search/search_ann/search_hybrid (all already take
  &[f32]). Use pure-pyo3 PyBuffer (abi3 buffer API available since 3.11, so the py312 floor is
  fine) - no numpy build dependency. Keep the Vec<f32> extract as a fallback for non-buffer
  inputs (plain Python lists) so the API stays ergonomic.
    where:  crates/nest-python/src/nest_file.rs lines 22-24, 35-37, 54-56 (the three .extract() sites);
            calls into nest-runtime/src/search.rs:124/147/181 unchanged.
    impact: Eliminates one heap alloc + element-wise memcpy per search call end-to-end; combined with the
            already zero-copy mmap read of stored embeddings, the hot path becomes
            allocation-free from numpy query in to SIMD dot-product out. Ensures int8/f16/zstd
            compression wins are not paid back as marshalling overhead at the python boundary.
    effort: low
    from:   https://github.com/PyO3/pyo3

* Wire maturin + a real [build-system] pyproject.toml (or maturin's own config) to produce ONE
  cp312-abi3 wheel for manylinux/macos/windows that loads on 3.12/3.13/3.14+, published to PyPI.
  Add the abi3t (PEP-803) feature path so the same wheel also loads on free-threaded CPython.
  Pin the model fingerprint + codec versions in the wheel/profile metadata so same-input =>
  byte-identical-file is auditable post-install.
    where:  New maturin build-system block replacing the current pyproject.toml disclaimer (lines 1-10);
            crates/nest-python/Cargo.toml features (add abi3t alongside abi3-py312); CI matrix
            for the three OS wheels.
    impact: Closes the listed PyPI/maturin known gap; delivers the 'portable, single-file, install-anywhere'
            leg of the north star for the python-builds half with one tiny artifact per OS
            instead of per interpreter patch version. Keeps distribution surface minimal
            (cheap/light pillar).
    effort: medium
    from:   https://github.com/PyO3/pyo3, weaviate/weaviate-helm

* Wrap the pure-Rust nest-runtime compute inside Python::detach (release the GIL) in
  NestFile::search/search_ann/search_hybrid, after the query buffer is bound. Safe because the
  file is an immutable mmap post-build (read-only), so concurrent Python threads can issue
  parallel searches against one open NestFile with identical deterministic results.
    where:  crates/nest-python/src/nest_file.rs search methods, around the self.rt.search* calls (after the
            PyBuffer borrow is materialized into an owned slice or held across detach via the
            buffer's lifetime discipline).
    impact: Free concurrency for multi-threaded Python callers with zero determinism cost; complements the
            abi3t free-threaded wheel. No new sockets, no panic surface.
    effort: low
    from:   https://github.com/PyO3/pyo3

* Enable clap's `suggestions` feature and add Jaro did_you_mean over the 8 subcommand names;
  then extend the same deterministic Jaro scorer over real chunk_ids (mmapped via nest-runtime)
  so a missed `nest cite nest://hash/<typo>` suggests the nearest valid chunk_id without
  altering the frozen format. Runs only on the error branch.
    where:  crates/nest-cli/Cargo.toml (add `suggestions` to clap features at workspace Cargo.toml:18);
            crates/nest-cli/src/cmd/cite.rs and main.rs error handling for the chunk_id
            suggestion.
    impact: Better CLI ergonomics (clean pillar) with zero hot-path cost; chunk_id suggestion improves
            citation UX against opaque hash-addressed ids. Deterministic (sorted by similarity).
    effort: low
    from:   https://github.com/clap-rs/clap

* Adopt clap CompleteEnv-style re-exec dynamic shell completion that reads the actual .nest file
  to complete content_hash, chunk_id, and preset names - but implement the candidate generation
  ENTIRELY in pure-rust nest-cli/nest-runtime (mmap read), never invoking the python embedder,
  so the ~300-500ms python boot overhead never lands on the completion path.
    where:  New crates/nest-cli/src/cmd/complete.rs (or clap_complete integration in main.rs); reads via
            nest-runtime MmapNestFile for chunk_ids/content_hash; must stay under the <=300-line
            file cap.
    impact: Offline, single-file-aware tab completion that improves the portable/clean pillars; binary
            re-exec is cheap for the Rust CLI. Strictly avoids the python-boot hot path.
    effort: medium
    from:   https://github.com/clap-rs/clap

* When nest adds named/multi-vector embeddings (text + image per chunk), copy Weaviate's
  tag-then-pack layout exactly: a per-section 1-byte dtype/encoding-id discriminator (reusing
  nest's existing SECTION_ENCODING ids raw=0/zstd=1/float16=2/int8=3) plus a uint16/uint32 LE
  row-dim prefix, then a contiguous blob the runtime mmaps straight into the SIMD kernel;
  recover the vector count from byte-length (len/(dim*elt_size)) instead of storing a redundant
  count. Keep it additive (new section id 0x09+ reserved space; no NEST_FORMAT_VERSION bump).
    where:  crates/nest-format/src/sections + encoding/mod.rs (new named-vector section, reuse
            SECTION_ENCODING_* tags); crates/nest-runtime/src/search.rs scoring path slices the
            mmap per named vector.
    impact: Lets nest swap f32->f16->int8 per named-vector by changing a 1-byte tag, never the byte layout -
            additive, reproducible, zero per-element decode. Shaves redundant count bytes from
            headers. Directly serves the compress-more axis without format churn.
    effort: medium
    from:   weaviate/weaviate-python-client, weaviate/weaviate-go-client

* Add two deterministic search-semantics knobs feeding the EXISTING mandatory exact-cosine
  rerank: (a) minimum_should_match / OR BM25 operator (alphabetical term order preserved =>
  reproducible) and (b) relativeScoreFusion (per-result-set min-max normalize then weighted sum)
  as a typed alternative to reciprocal-rank fusion in the hybrid preset. Surface both as clap
  flags on search-text/hybrid.
    where:  crates/nest-runtime/src/bm25/index.rs (min_should_match), crates/nest-runtime/src/search.rs:181
            search_hybrid (fusion selection); crates/nest-cli/src/cmd/search_text.rs flags.
    impact: More recall/precision control in the hybrid path with ground-truth scoring unchanged (both still
            feed exact cosine rerank). Fully deterministic. Improves search quality without
            touching the frozen container.
    effort: medium
    from:   weaviate/weaviate-go-client, weaviate/weaviate-python-client

* Replace ad-hoc preset/build flags with a single declarative build profile (TOML) where each
  section/codec is a uniform record {enabled, encoding, params} mirroring presets
  exact/compressed/tiny/hybrid; a deterministic fold collects enabled records into the writer's
  section table (Helm's ENABLE_MODULES-style reduce in declaration order). Record exact model
  fingerprint + codec versions in the profile (version-pinning-by-tag) so same-input =>
  byte-identical-file is guaranteed and auditable.
    where:  crates/nest-python/src/build_fn.rs (build entrypoint) consuming the profile; crates/nest-format
            manifest as single-source-of-truth (each section a self-describing record carrying
            encoding id + per-section checksum).
    impact: Makes adding hnsw_index(0x07)/bm25_index(0x08) one boolean instead of imperative wiring; an
            additive-format-friendly config surface nest lacks today. Reinforces reproducible
            byte-identical builds and accelerates codec/preset experimentation (meta-win toward
            compress-more).
    effort: medium
    from:   weaviate/weaviate-helm

* Mirror clap's feature-gated crate split: make hnsw (ann), bm25, and pyo3 opt-in cargo features
  so a minimal sovereign nest-cli binary can ship without ANN/BM25/python when not needed.
    where:  crates/nest-runtime/Cargo.toml and nest-cli/Cargo.toml feature flags gating ann::HnswIndex /
            bm25::Bm25Index modules; main.rs subcommand registration behind cfg.
    impact: Smallest possible sovereign binary (light pillar); deployments that only need exact cosine over
            text drop the HNSW/BM25 code entirely. No effect on the frozen format.
    effort: medium
    from:   https://github.com/clap-rs/clap

* Stream the bulk-build path with a producer/consumer + auto-flush + error-threshold batch
  lifecycle (Weaviate's context-manager batch ergonomics) so large-corpus builds (the PT-BR
  fake-news datasets and future whole-DB ingests) chunk and embed without holding the entire
  corpus in memory.
    where:  crates/nest-python/src/build_fn.rs build pipeline; bounded queue feeding the embedder +
            nest-format writer, flush on completion/error.
    impact: Bounded-memory builds for the 'compress whole databases/repos' north-star goal; decouples
            chunk-production rate from write rate. Determinism preserved (ordered emission).
    effort: medium
    from:   weaviate/weaviate-python-client

compression wins
------------------------------------------------------------------------------------------------
  - Count-from-byte-length (Weaviate): derive vector/row counts as len/(dim*elt_size) instead of
    storing a redundant count field per section - shaves header bytes on every
    embeddings/named-vector section, consistent with nest's compress-more discipline.
  - 1-byte dtype side-enum tag (Weaviate tag-then-pack): makes per-(named-)vector dtype
    fp32/fp16/int8 a single discriminator byte rather than a layout change, so nest can shrink
    an embeddings section by swapping codecs WITHOUT touching the byte run or bumping
    NEST_FORMAT_VERSION - keeps the format additive while the codec gets smaller (enables future
    per-vector int8 on the image side while text stays f16, etc.).
  - Zero-copy buffer-protocol borrow (PyO3): keeps the search hot path allocation-free
    end-to-end (mmap'd quantized/compressed embeddings in, borrowed query in), so the
    int8/f16/zstd compression wins in nest-format are NOT given back as alloc+memcpy marshalling
    overhead at the python boundary - protecting realized compression gains at serve time.
  - abi3/abi3t single-tiny-wheel distribution (PyO3): not a byte-codec, but the
    minimal-distribution-surface leg of 'compress more / be lighter than everyone' - one small
    artifact per OS serving every Python on every machine instead of N interpreter-specific
    binaries.
  - Validation that for vectors the win is layout + quantization, NOT entropy coding (Weaviate
    confirms `bytes`-not-`repeated-float` is the right call): reinforces nest's correct decision
    to keep embeddings as a raw contiguous mmap run scored directly (never zstd on embeddings)
    and to invest compression effort in better quantization (int8 today, candidates: per-vector
    scale int8, product/scalar quantization later) rather than entropy-coding the hot-path
    floats.

watch-outs (conflict with nest constraints)
------------------------------------------------------------------------------------------------
  - NEVER adopt any transport from the Weaviate clients: both are network clients (REST + gRPC
    over sockets, default :50051) - nest is offline-by-construction and must NOT open a socket.
    Steal ONLY the byte-layout (tag-then-pack), the count-from-length trick, the fusion math,
    and the batch ergonomics; leave gRPC/HTTP entirely.
  - clap dynamic completion (CompleteEnv) re-execs the binary - the ~300-500ms python boot
    overhead from search-text MUST never land on the completion path. Keep completion candidate
    generation in pure-rust nest-cli/nest-runtime (mmap reads only), never invoking
    python/embed_query.py.
  - abi3 has a small documented runtime cost vs version-specific builds (cannot inline against a
    known CPython struct layout). Acceptable for nest because the hot loop is pure-Rust
    nest-runtime, NOT across the FFI boundary - but do not move numeric/scoring work across the
    pyo3 boundary to 'use' the binding; PyO3 must stay confined to nest-python, with
    nest-format/nest-runtime pure Rust.
  - Keep the typed-thiserror -> PyValueError mapping intact when refactoring the query path:
    library code must never panic (HARD CONSTRAINT). A PyBuffer borrow that fails
    (non-contiguous, wrong dtype, wrong shape) must map to a typed PyValueError, not
    unwrap/expect.
  - relativeScoreFusion (min-max normalize) and minimum_should_match must remain fully
    deterministic to respect nest's reproducibility guarantee: preserve alphabetical BM25 term
    order and seeded behavior; min-max normalization is order-independent but verify
    tie-breaking is deterministic. Both MUST still feed the mandatory exact-cosine rerank -
    never return an ANN/BM25 proxy score.
  - Helm's value is meta only (declarative config + version-pinning), and the extract itself
    rates it low/none for compression - do not let the build-profile refactor balloon nest-cli
    or the manifest. Respect the <=300-line-per-file (333 hard cap), single-responsibility,
    edition-2024 conventions; a config compiler can easily violate the line cap.
  - The named/multi-vector layout steal is FUTURE work (nest stores a single embeddings matrix
    today). When added it MUST use a RESERVED section id 0x09+ and the additive-only rule - do
    NOT bump NEST_FORMAT_VERSION unless an existing field changes meaning. Reuse existing
    SECTION_ENCODING ids; do not invent a parallel dtype tag scheme that diverges from the
    encoding ids.
  - maturin/PyPI introduces a network-fetch install step and an external supply chain - this is
    for distribution convenience and does NOT compromise runtime sovereignty (the runtime still
    mmaps a local file, no socket). But pin everything (model fingerprint, codec versions, wheel
    hashes) so the 'same chunks + same model fingerprint => byte-identical file' guarantee
    survives the install boundary; an unpinned dependency would silently break reproducibility
    (Helm's explicit warning).
  - PyReadonlyArray1 (rust-numpy) would add a numpy build dependency and a heavier dep tree;
    prefer pure-pyo3 PyBuffer<f32> to keep the small-core/light pillar. Only add the rust-numpy
    feature path as an OPTIONAL feature if a numpy-native ergonomic API is demanded.
  - Python::detach requires the borrowed query data to be safely held across the GIL release;
    ensure the buffer's backing memory cannot be mutated/freed by Python during the detached
    compute (copy into an owned Vec before detach if the buffer's lifetime cannot be guaranteed)
    - getting this wrong is a use-after-free, the one place the zero-copy win must be traded for
    safety.
