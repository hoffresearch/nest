what:        A statically-allocated, fully deterministic, single-file financial accounting database (Zig)
             whose entire on-disk state is a hash-chained tree of fixed 0.5 MiB grid blocks
             protected by out-of-band 128-bit AEGIS checksums, with an LSM "forest" over a WAL
             ring buffer and a 4-copy superblock root.
innovation:  Byte-for-byte physical determinism turns integrity into content-addressing: every block is
             referenced by {address, 128-bit checksum} in its parent, so corruption recovery is
             "fetch a block matching checksum X" with no error path, and repair is single-block
             (physical) rather than recomputing whole structures.
techniques:
  - EWAH (Enhanced Word-Aligned Hybrid) run-length bitmap compression for the grid free-set:
    marker words encode runs of clean (all-0/all-1) words + literal dirty words,
    scannable/operable in place, guaranteed never >0.1% larger than raw bitset
  - Two-bitset free-set design (blocks_acquired + blocks_released) so deletions are deferred
    until a checkpoint is durable, giving crash-consistent reclamation without a full rewrite
  - AEGIS-128L as a (non-cryptographic-strength but fast) 128-bit checksum built on AES round
    instructions to saturate hardware AES on x86-64/aarch64; software fallback exists but is
    assumed unused
  - Out-of-band checksums: a block's checksum lives in its parent reference, not the block,
    defeating misdirected/torn writes and decoupling the checksum from the bytes it covers
  - Hash-chaining at every layer (WAL prepares chain, manifest log is a linked list of blocks,
    superblock chains predecessors) so a single root checksum authenticates all reachable state
  - 4-redundant superblock root with a per-copy `copy` field excluded from the checksum, so all
    copies share one checksum yet stay individually addressable; recovery picks the newest root
    with >=2 matching copies
  - Static allocation from CLI-derived worst-case upper bounds: zero alloc/free after startup,
    so memory and on-disk sizing are an explicit deterministic function of declared limits
  - Deterministically scheduled, evenly-amortized LSM compaction (fixed work-per-op) so layout
    and latency are reproducible from a seed; LSM forest = many fixed-value-size trees keyed by
    stable tree_id
nest steals: 1) nest-format hashing: TigerBeetle's out-of-band, content-addressed checksum model directly
             validates and sharpens nest's four-checksum scheme. Adopt the "checksum stored in
             the parent reference, not the bytes" rule for the manifest's per-section entries
             (layout.rs/manifest.rs/hashing.rs), and treat content_hash as a Merkle root over
             per-section content_hashes so a citation nest://content_hash/chunk_id can verify a
             single chunk against the root (partial verification without rehashing the whole
             file). 2) nest-format encoding: add an EWAH/word-aligned-hybrid bitset codec as a
             new RESERVED encoding id (>=4) or as an internal representation for sparse/boolean
             metadata -- e.g. a deletion/tombstone bitmap for real-time edit, an hnsw "live
             node" mask, or bm25 doc-presence sets -- giving near-free compression of sparse
             id-sets while staying scannable in place off mmap; deterministic by
             alphabetical/ascending id order, fits the <=300-line single-responsibility codec
             module. 3) nest-format additive section: the two-bitset (acquired/released)
             free-set is the blueprint for nest's missing edit story -- an additive section
             (0x09+) holding an EWAH live-set + released-set lets nest mark chunks
             deleted/superseded and reclaim space at the next deterministic rebuild without
             bumping to v2, preserving append-only + reproducible-build guarantees. 4)
             nest-runtime simd: evaluate AEGIS-128L (AES-NI / NEON AES) as an optional fast
             integrity check on the mmap hot path where SHA-256 is too slow for per-query
             re-verification -- keep SHA-256 as the canonical sovereign hash, expose AEGIS only
             as an internal fast-path detector of mmap corruption.
compression: Directly relevant via EWAH: extreme, in-place-scannable compression of the sparse boolean
             id-sets nest will need for edit/tombstones/hnsw-liveness/bm25-presence, with a hard
             "never materially larger than raw" guarantee -- ideal for the smallest-on-disk
             mission. The deterministic/content-addressed-block model also reinforces nest's
             reproducible-build and partial-verification story, which underpins trustworthy
             aggressive compression. AEGIS is a perf, not a size, lever (fast re-verification of
             compressed mmap'd bytes).
perf:        AEGIS-128L checksumming targets >GB/s by mapping onto AES round instructions on both x86-64
             (AES-NI) and aarch64 (NEON crypto); software fallback exists but is assumed never
             used (an assert guards non-AES CPUs). Direct I/O (O_DIRECT) bypasses the page cache
             to avoid fsync/EIO cache-coherency bugs and to manage its own cache; fixed 0.5 MiB
             blocks double as network messages (zero re-encode between disk and wire). Static
             allocation means no GC/alloc jitter; compaction work is evenly spread per op to
             bound tail latency. EWAH bitsets are operated on in compressed form (no decompress
             step) which is the property nest needs for off-mmap scanning.
