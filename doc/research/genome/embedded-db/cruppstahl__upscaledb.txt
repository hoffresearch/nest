what:        An embedded, page-based B+Tree key-value/analytical engine (single-file, multi-database, mmap'd)
             whose headline innovation is SIMD-accelerated integer-key compression inside B+Tree
             leaf KeyLists, plus analytical aggregates that run directly over compressed pages.
innovation:  Store sorted integer key columns as delta-coded, block-bit-packed streams (SIMD-BP128 / VarIntGB
             / StreamVByte / MaskedVByte) and operate on them WITHOUT full decompression: binary
             search, range scans, and analytical aggregates (SUM/COUNT/AVG) run directly over
             the packed blocks. Decode kernels are vectorized via per-control-byte SSE
             shuffle-mask lookup tables (StreamVByte) and per-block fixed-bit-width unpacking
             (SIMD-BP128), hitting 4-8 billion ints/sec. This is the 'compress columnar data AND
             serve it from the same compact bytes' pattern, co-authored by upscaledb's own
             Christoph Rupp with Daniel Lemire.
techniques:
  - SIMD-BP128 binary packing: split a sorted column into blocks of 128 ints, compute max
    bit-width b for the block, pack 128 ints into b 128-bit SSE words; decode via fixed
    shift/mask SIMD kernel (best case 1 bit/key, ~32x shrink)
  - Delta (differential) coding of sorted keys before packing so only small gaps are stored;
    reconstruct via vectorized prefix-sum (cumulative add)
  - StreamVByte: separate control stream (2 bits per int = byte length 1/2/3/4) from data
    stream; decode 4 ints/iteration via a 256-entry SSE pshufb shuffle-mask table indexed by the
    control byte (co-authored by Rupp)
  - VarIntGB / Group Varint: one control byte per group of 4 ints for branch-free length lookup;
    MaskedVByte for vectorizing classic varint streams
  - Frame-of-Reference (FOR) and patched PFOR / SIMD-FastPFOR: subtract a per-block reference
    value, bit-pack residuals, store rare exceptions out-of-band for fast random access
  - Per-block bit-width header lets binary search skip to the target block, decode only that
    block, then scan in-register
  - Analytical aggregates (SUM/COUNT/AVG) computed in B+Tree context across many packed keys at
    once without materializing records (millions/call)
  - Transparent record/journal compression (snappy/zlib/lzf) plus CRC32 page verification and
    AES page encryption layered under one page abstraction
nest steals: Add a fourth integer codec family to nest-format/src/encoding alongside raw/zstd/float16/int8: a
             delta+bit-packing codec (SIMD-BP128-style blocks of 128, or StreamVByte) for
             INTEGER sections, specifically chunk_ids and chunks_original_spans (offset/length
             pairs are monotone or near-monotone and delta-code to ~1-4 bits each, far below
             zstd on small-int arrays). Reserve a new encoding id in the additive 4-255 v1 range
             (no version bump). The decode kernel slots into nest-runtime's existing SIMD
             dispatcher (AVX2/NEON/scalar fallback already present) as a new vectorized unpack
             path: NEON tbl, AVX2 pshufb shuffle-mask tables. Critically for the hot path,
             StreamVByte's 'operate-in-register' property lets the runtime reconstruct span
             offsets during materialize() and resolve nest://content_hash/chunk_id citations
             without decompressing whole sections, mirroring upscaledb's
             binary-search-on-compressed trick. Keep it deterministic (fixed block size 128,
             sorted input nest already mandates) so reproducible-build byte-identity holds. Do
             NOT apply to embeddings (they stay raw/f16/int8 scored straight from mmap), exactly
             as nest already forbids zstd on embeddings.
compression: Directly central to 'compress more than everyone'. nest leans on zstd for non-embedding
             sections, but zstd is weak on arrays of small/monotone integers, which is exactly
             what chunk_ids and chunks_original_spans (span offset+length pairs) are. Delta +
             SIMD bit-packing reaches 1-4 bits/integer (vs zstd's byte-granular framing overhead
             on short int runs), shrinking structural sections while DECODING faster than
             memcpy. It is a true compress-and-serve codec: the runtime searches the packed
             bytes directly off mmap, preserving the offline/single-file/no-materialize hot
             path. Rare codec that improves both size and speed at once, which is precisely
             nest's mission.
perf:        Reference simdcomp decodes binary-packed ints at ~0.3 cycles/int (>8 billion/sec on Skylake);
             StreamVByte decode can exceed memcpy (up to 2x faster than varint-G8IU). SIMD-BP128
             saves up to 2 bits/int over prior vectorized schemes; whole-DB benchmark showed
             ~40% faster queries AND ~10x compression vs uncompressed B+Tree. Decode cost scales
             with bit-width (fewer bits = faster), so delta-coded near-sorted data is both
             smallest and fastest. Blocks of 128 ints map onto 128-bit registers (SSE/NEON
             128-bit lanes), portable to nest's AVX2/NEON dispatch; AVX2 runs two 128-bit lanes.
             Per-block bit-width metadata is tiny (1 byte/block).
