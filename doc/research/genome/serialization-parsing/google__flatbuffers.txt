what:        A zero-copy cross-platform serialization library whose buffers are read in place (mmap-friendly)
             via a vtable indirection scheme, plus a schema-less sibling format (FlexBuffers)
             that auto-narrows every scalar/container to the smallest of 8/16/32/64-bit widths
             and pools strings/keys.
innovation:  Random-access read directly off raw bytes (no parse, no allocation, no copy) achieved through a
             layer of relative offsets plus a shared, deduplicated vtable: many records with
             identical field layout point at ONE vtable, so per-record metadata cost amortizes
             to near zero. The complementary FlexBuffers idea - encode each element at the
             minimum bit-width that fits its value and pool repeated strings/keys - is a
             self-describing, mmap-readable layout that is often smaller than a typed format
             while still allowing O(1) indexed access via a parallel width-tagged offset table.
techniques:
  - vtable indirection: each table starts with a soffset to a vtable [vtable_size, object_size,
    field_offset_0..N]; absent field => offset 0 => return schema default (free optionality, no
    presence bitmap)
  - vtable deduplication/sharing: records with the same present-field set reference one
    identical vtable, so N homogeneous rows cost 1 vtable not N
  - three offset widths: uoffset_t (u32 forward to tables/vectors/strings), soffset_t (signed,
    vtable backref), voffset_t (u16 field slot), little-endian, self-relative so buffers are
    position-independent and DAG-shareable
  - shared subobjects via offset reuse: identical strings/vectors/subtables stored once and
    pointed to by multiple parents (string pooling / structural dedup) without a back-reference
    table
  - FlexBuffers minimum-width packing: a 1-byte type+bitwidth tag per value lets each
    int/float/offset use 8/16/32/64 bits, eliminating fixed-width padding on small values
  - FlexBuffers vectors carry a length prefix + a parallel array of equal-width offsets,
    enabling O(1) random indexing into a schema-less, mmap-resident blob
  - size-prefixed buffers + 4-byte file identifier magic for streaming framing and cheap
    type/format sniffing without a full header parse
  - build-backward construction (high to low address) so child offsets are known before parents
    are written, giving single-pass serialization with no fixups
nest steals: Two concrete steals into nest-format. (1) Offset-table layout for variable-length sections:
             today crates/nest-format/src/sections/{chunk_ids,canonical,spans}.rs write a count
             prefix then a flat run of length-prefixed strings, which forces a sequential scan
             to reach chunk N and gives no random access off mmap. Adapt FlatBuffers' uoffset
             vector: prepend a u32 (or width-narrowed) offset array so nest-runtime
             materialize/cite can jump to chunk N in O(1) directly from the mapped page without
             decoding earlier strings, the read-side enabler for nest://content_hash/chunk_id
             byte-span reopen. (2) Apply FlexBuffers minimum-width thinking as a new additive
             encoding id (reserved 4-255 space, no version bump) for the structural/metadata
             sections only: store per-chunk offset/length integers and provenance ints at the
             smallest width that fits (delta + varint or fixed 8/16/32-bit pick), shrinking
             non-embedding overhead at zero decode cost on the hot path. Most impactful for
             chunk_ids: stop storing sha256 as the 71-byte ASCII string 'sha256:<64 hex>'; store
             the 32 raw digest bytes (a 2.2x shrink before zstd) and reconstruct the prefix on
             read, a pure entropy win toward 'compress more than everyone'. Keep embeddings
             untouched (still scored from mmap). The vtable-default trick also informs
             provenance: omit absent optional fields and resolve to defaults rather than storing
             nulls. All of this respects single-file, offline, deterministic (offset tables are
             a pure function of inputs) and the additive format rule.
compression: Direct. Two distinct wins: (a) the sha256 raw-bytes-vs-hex-string fix is an immediate ~2.2x
             reduction on the chunk_ids section pre-zstd and removes redundant 'sha256:'
             prefixes, pure entropy reduction. (b) FlexBuffers-style minimum-width integer
             packing trims structural/offset/provenance overhead with zero hot-path decode cost,
             complementing zstd which nest already applies to non-embedding sections. The
             offset-table idea is compression-neutral but unlocks O(1) mmap random access that
             nest's cite/materialize path currently lacks, strategically required to serve
             compressed corpora without full-section decode.
perf:        Zero-copy reads: field access is one vtable lookup + one bounds check + one load, no allocation,
             no temp objects, good cache locality, ideal for mmap. All integers little-endian
             aligned to their own size; structs align to largest member (compiler-independent)
             so a memory-mapped struct can be cast and read in place on x86_64/aarch64 without
             misaligned-access penalties, matching nest's repr(C) + LE-unsigned discipline.
             Tradeoffs: FlexBuffers is slower to read than typed FlatBuffers (per-element
             type/width tag dispatch) and FlatBuffers trades some size for alignment padding;
             nest should apply min-width packing only to cold structural sections, never the
             embedding hot path. No SIMD in the format itself, it is a layout/encoding library,
             not a kernel.
