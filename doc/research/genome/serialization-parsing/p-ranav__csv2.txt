what:        A header-only C++17 CSV reader/writer that mmaps the whole file and lazily iterates cells via
             memchr-driven newline scans plus a branchy scalar quote state machine, hitting ~1
             GB/s zero-copy without materializing the dataset.
innovation:  Treat the on-disk byte buffer as the only data structure: never copy, never pre-tokenize.
             Iteration is fully lazy and offset-based -- a RowIterator finds the next row with
             one memchr('\n') call, and CellIterator only computes a cell's [start,end) span at
             deref time, returning a string_view straight into the mmap. The parsed "table" is
             just two cursors over bytes you already paid to map; cell values are decoded
             (unescape/trim) on demand, so unread columns cost nothing.
techniques:
  - memchr-based row scan: locate next \n in the mmap region with one libc SIMD-accelerated
    memchr call instead of a byte loop
  - Lazy offset-only cell boundaries: CellIterator stores start_/end_ and computes the next
    delimiter span on deref, returning string_view (zero allocation, zero copy)
  - Branchy scalar quote state machine: quote_opened flag + last_quote_location==i-1 test
    detects doubled-quote escapes; delimiter ignored while inside quotes
  - Compile-time dialect via templates: delimiter<','>, quote_character<'"'>,
    first_row_is_header<>, trim_policy -- monomorphized so the hot loop has no runtime config
    branches
  - mmap-the-whole-file zero-copy I/O via the bundled header-only mio wrapper (page-aligned,
    cross-platform POSIX/Windows, MIT)
  - Decode-on-demand value path: read_view() returns raw span; read_value() applies
    trim+unescape only when the caller wants the string
  - Naive append-only Writer: ostream_iterator + delimiter concatenation, no quoting/escaping by
    design (caller owns CSV-safety)
nest steals: Two concrete lifts. (1) nest-runtime materialize path + nest-cli: adopt csv2's lazy-offset
             cursor model for any row/columnar section we mmap. Today nest scores embeddings off
             mmap; csv2 proves we can also serve text-table payloads (csv/tsv/dataset rows the
             north-star wants to ingest) as &str slices into the mapped file with zero decode
             until a row is cited, mirroring our chunks_canonical/chunks_original_spans span
             discipline. (2) Ingestion-side tokenizer in nest-python build: replace any
             byte-by-byte CSV/field scanner with the Rust memchr crate (already SIMD on
             AVX2/NEON, deterministic) for row splitting, plus a small monomorphized
             delimiter/quote state machine instead of regex -- speeds import of the PT-BR
             fake-news corpora and future parquet/json/yaml dataset fronts. The decode-on-demand
             idea also reinforces nest-format: store cheap text columns as raw offset spans
             (like chunks_original_spans) so zstd table sections decompress lazily per accessed
             cell rather than whole-section, leaving the embedding hot path untouched.
compression: Low-to-indirect. csv2 is a speed/zero-copy parser, not a compressor -- no entropy coder, no
             quantization, no columnar dictionary encoding, so it does not advance 'compress
             more than everyone' directly. Its value is structural: the lazy-offset,
             decode-on-demand discipline lets a zstd-compressed table section in nest-format be
             unpacked one cell/row at a time rather than wholesale, lowering working-set memory
             during ingest and preserving the mmap-friendly layout all of nest's encodings
             depend on. It teaches layout-for-compression, not a new codec.
perf:        ~0.9-1.0 GB/s sustained cell iteration on an i9-11900KF (16 GB file in 16.5s; 11 GB / 262M rows
             in 10.8s). No explicit SIMD intrinsics in csv2 itself -- throughput comes from
             glibc memchr (hand-vectorized SSE/AVX), zero per-row/cell allocation, and template
             monomorphization stripping config branches from the inner loop. Footprint is
             essentially page cache for the mapped file plus two cursor structs; no parse tree,
             no row vector. Quote handling is fully scalar/branchy, so quote-heavy CSVs lose
             throughput -- a ceiling a true SIMD parser (simdcsv / Mison structural-index
             bitmaps) would beat.
