cloudflare/mmap-sync
category: serialization-parsing   |   steal priority: MEDIUM
================================================================================================

siblings: ./00-index.txt   |   map: ../../README.txt

what:        A Rust single-writer/multi-reader IPC library that combines rkyv zero-copy archives with a
             tmpfs-backed mmap double-buffer and a wait-free RCU/Left-Right swap protocol so
             readers parse data in-place off the mmap with no locks and no copy.
innovation:  A 64-bit packed atomic InstanceVersion (1 bit active-instance index, 39 bits data size up to 549
             GB, 24 bits truncated WyHash checksum) lets a writer atomically publish a new
             mmap'd buffer with a single SeqCst store while readers do wait-free zero-copy
             access; per-instance AtomicU32 reader counters plus a grace_duration timeout drain
             in-flight readers off the idle buffer before it is reused (and forcibly reset to
             handle crashed readers), giving lock-free publish-then-swap without ever blocking
             the read path.
techniques:
  - InstanceVersion: pack {idx:1 | size:39 | checksum:24} into one u64 via mask/shift, swapped
    with a single AtomicU64 SeqCst store (RCU/Left-Right publish)
  - Double-buffer of two mmap data files plus a 3rd state file; writer always writes the idle
    buffer then flips the active index
  - Per-instance [AtomicU32;2] reader counters: rlock=fetch_add(1,SeqCst),
    unlock=fetch_sub(1,SeqCst); writer waits for idle count==0
  - grace_duration drain: poll-sleep until idle reader count hits 0, else store(0) to reclaim
    from crashed/stalled readers (reset=true)
  - rkyv 0.7 zero-copy archives: serialize_value then
    archived_root::<T>/check_archived_root::<T> to read structs straight off mmap with no
    deserialize step
  - 24-bit truncated WyHash checksum embedded in the version word for cheap optional integrity
    validation on read (40ns checked vs 27ns unchecked)
  - RAII ReadGuard holds the reader-count increment and decrements on Drop, making reader
    bookkeeping leak-proof
  - tmpfs (/dev/shm) backing to drop mmap I/O latency to RAM speed
nest steals: Two distinct steals. (1) nest-runtime: adopt rkyv-style zero-copy archived structs as the
             in-memory view of mmap'd sections (chunk_ids, provenance, search_contract,
             hnsw/bm25 index nodes) so the reader casts repr(C) LE bytes to typed structs with
             zero parse cost on open, formalizing nest's existing mmap-cast pattern in
             nest-format reader.rs and nest-runtime materialize; nest's repr(C)/little-endian
             invariants already match rkyv's archived-layout discipline. (2) Bigger steal: the
             InstanceVersion + double-buffer + grace-period drain protocol as the foundation for
             nest's missing real-time edit / hot-reload. Keep the FROZEN .nest v1 container
             immutable but add an optional local atomic-version sidecar in nest-runtime so a
             rebuilt container is published and queried wait-free while old readers finish on
             the previous mmap; the 24-bit-checksum-in-version trick gives O(1) integrity gating
             per swap. Must stay offline/single-file: implement as an in-process atomic-swap
             layer, never a socket, and outside the frozen format. The packed-version u64 idiom
             also informs encoding size+checksum+epoch in one LE manifest/footer word.
compression: Low and indirect. mmap-sync does not compress (pins rkyv 0.7 raw aligned archives, no entropy
             coder, no quantization), so it does not advance the 'compress more than everyone'
             north star directly. Its value is to the SERVE half: it shows the canonical
             zero-copy mmap layout that exposes decoded sections (and never-compressed
             embeddings scored straight off disk) as typed structs at tens of nanoseconds, and
             its version-word checksum is a model for compactly embedding integrity metadata.
             Enables fast/real-time edit and concurrent serving (stated mission goals) without
             touching the codec stack.
perf:        i7-13800H: write 250.7 ns (3.96 Melem/s), read with WyHash checksum validation 40.1 ns (24.9
             Melem/s), read without validation 26.7 ns (37.5 Melem/s). All atomics SeqCst
             (conservative; nest could relax to Acquire/Release on the read fast path).
             Single-writer/multi-reader only. tmpfs backing keeps latency at RAM speed; 39-bit
             size field caps a single buffer at 549 GB.
