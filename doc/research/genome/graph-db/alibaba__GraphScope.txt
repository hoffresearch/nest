what:        A distributed property-graph compute stack (GAE/GIE/GLE on the vineyard zero-copy in-memory
             store) whose most transferable artifact is GraphAr: a chunked, columnar,
             CSR/CSC-semantic on-disk graph format that delta-encodes adjacency to reach ~27% of
             naive plain+offset storage.
innovation:  Store graph topology as sorted CSR split into a per-vertex offset table plus a destination
             adjacency column, then delta-encode the monotone internal vertex ids and offsets so
             columnar payload reaches ~27.3% of a plain id+offset baseline; dense contiguous
             internal ids are the enabler for both delta coding and zero-copy mmap.
techniques:
  - sorted CSR/CSC: edges ordered_by_source (CSR) or ordered_by_dest (CSC), with an offset table
    whose first entry is 0 recording each vertex's edge run start
  - delta encoding of monotone columns (continuous internal vertex ids + offset arrays) before
    columnar compression -> 27.3% of plain+offset size
  - vineyard compact_edges = variant (varint) + delta encoding of the CSR adjacency
  - dense contiguous internal vertex ids (= row index within a label) enabling a single
    zero-copy mmapped id space and O(1) offset lookup
  - chunking: vertex chunk 2^18, edge chunk 2^22, each physical chunk = one file, enabling
    selective/partial reads of one vertex or one chunk without reading the whole graph
  - self-descriptive YAML metadata that fully determines how to resolve the binary so CSR is
    stored directly with no serialize/deserialize round-trip
  - separation of topology (2-column adjList) from properties (separate columnar property
    groups) so a traversal reads only the adjacency, never property bytes
  - multiple coexisting adjacency orderings (CSR + CSC copies) selected per access pattern
nest steals: Add a reserved section to nest-format (section id 0x09, graph_adjacency) plus a delta+varint
             codec in crates/nest-format/src/encoding/ (a new delta_varint.rs sitting beside
             int8.rs/float16.rs/zstd_codec.rs, registered as a new encoding id in the reserved
             4-255 range, additive so NEST_FORMAT_VERSION stays 1). Layout: store a per-chunk
             offset array (u32/u64 LE, monotone) zig-zag delta-varint encoded, and a
             destination-id adjacency column where dst ids are delta-coded within each source's
             run; vertex ids are nest's existing dense chunk_ids row index, so no extra id map
             is needed. In nest-runtime, add ann::graph (a graph_search path next to
             ann::HnswIndex) that mmaps the offset+adjacency arrays and walks neighbors with
             O(1) offset lookups -- decoding varints lazily per row, never materializing the
             whole graph -- and feeds candidates into the existing mandatory exact-cosine rerank
             so graph traversal stays a candidate generator, not a score source (mirrors the
             hnsw contract). This unlocks the mission's stated 'graph search' goal while keeping
             single-file, offline, deterministic (sorted CSR + alphabetical/seeded order =
             byte-identical builds), and content_hash stable because the decoded adjacency is
             canonical regardless of varint packing.
compression: Directly on-mission. Delta+varint CSR is the canonical way to compress graph adjacency and is
             proven here at 27.3% of plain+offset. It is the missing codec for nest's 'graph
             search' north-star item and generalizes: the same monotone-column delta-varint
             codec also shrinks nest's own chunk_ids and chunks_original_spans (offset/span
             arrays are monotone), so it pays off even before any graph section ships. Unlike
             zstd it is decode-cheap and seekable straight off mmap, fitting the 'score/traverse
             directly from disk, never inflate' hot-path rule.
perf:        Columnar topology/property split means a traversal touches only the 2-column adjList, not
             property bytes (the dominant data). Offset table gives O(1) per-vertex neighbor-run
             lookup; varint decode is sequential and branch-light. Recommended chunk sizes
             (vertex 2^18, edge 2^22) balance file-count overhead vs parallelism; for nest's
             single-file model use one logical chunk per section so there is one mmap region,
             not thousands of files. Delta+varint is far cheaper to decode than general entropy
             coders, so it suits scoring-from-mmap; vineyard demonstrates the CSR can be mapped
             and shared zero-copy with no deserialize step.
license:     Apache-2.0 (GraphScope and the spun-out Apache GraphAr are both Apache-2.0); format spec and
             encoding ideas are freely adoptable, clean-room reimplementation in Rust is trivial
             since the technique is just delta+varint over sorted CSR.
