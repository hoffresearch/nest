what:        NebulaGraph is a distributed C++ property-graph database that translates graph operations into
             RocksDB key-value scans using a custom prefix-locality key encoding where a vertex
             and its out-edges share a sorted key prefix, plus bidirectional (out/in) edge
             materialization and fixed-offset schema-versioned property values.
innovation:  see core_innovation field
techniques:
  - prefix-locality key encoding
nest steals: Add an optional graph adjacency section to nest-format (reserve a v1 section id 0x09,
             additive-only) holding HNSW/k-NN edges as a CSR-style structure: a sorted offsets
             array indexed by chunk ordinal plus a flat neighbor-id array, mirroring Nebula's
             prefix-locality so one node's neighbors are a single contiguous mmap slice (no
             per-node random reads). nest-runtime/ann already builds the HNSW graph (build.rs,
             select_neighbors.rs) holding neighbor lists in memory; serialize those lists in
             this contiguous layout via nest-format/sections so the runtime mmaps adjacency
             straight off disk and walks it with zero allocation, matching the existing 'score
             directly from mmap' discipline. Borrow the Rank-as-sort-key trick to store the
             float16/int8 edge distance INLINE next to each neighbor id (delta-sortable),
             letting hnsw expansion skip a separate distance lookup. Borrow the
             sign-encoded-direction byte to fold bidirectional/typed edges (e.g. bm25
             term-postings vs hnsw vector edges) into one section without a second container,
             keeping single-file. Compression angle: neighbor-id arrays are monotone-ish within
             a node, so delta + varint/zigzag encode them in nest-format/encoding (new codec id
             4-255, reserved-range, never on the embedding hot path) -- adjacency is a
             NON-embedding section so zstd over delta-coded ids is fair game and shrinks the
             graph index materially, advancing the 'compress more than everyone' north star
             while keeping graph traversal as cheap sequential mmap reads. Schema-version-byte
             idea maps to nest's manifest: a per-section format byte lets the adjacency codec
             evolve additively without a true v2 bump.
compression: Direct: graph adjacency (HNSW edges, future graph-search index) is a non-embedding section, so
             delta+zigzag+varint over monotone neighbor ids then zstd compresses it hard while
             CSR prefix-locality keeps traversal as O(1) contiguous mmap reads. Co-locating
             fixed-offset distances inline avoids a parallel array. This is the cheapest path to
             add 'graph search' to nest's mission without inflating the .nest file or breaking
             the offline/single-file/mmap guarantees.
perf:        Nebula's design makes 'get neighbors' a single RocksDB prefix range scan rather than N point
             lookups -- the same asymptotic win nest gets from a CSR adjacency slice over mmap
             (sequential, cache-friendly, prefetchable, zero alloc). Bidirectional dual-write
             trades ~2x edge storage for O(scan) reverse traversal; nest can choose
             single-direction for vector graphs (HNSW is undirected-symmetric anyway, so store
             once) and reserve dual-write only for typed/directed graph-search edges.
             Fixed-offset property decode = O(1) field access, the analog of nest reading
             f32/f16/int8 lanes at known strides off mmap.
