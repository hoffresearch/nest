what:        A labeled fact-checking dataset (not software): 7,200 length-aligned Brazilian-Portuguese news
             articles (3,600 fake / 3,600 true) shipped as numbered plain-text files plus a
             fixed 25-field line-by-line linguistic-metadata schema per article and a
             stopword/diacritic-normalized preprocessed CSV variant.
innovation:  The pairwise size-normalization protocol: every fake article is matched to a true counterpart on
             the same topic, and the longer text in each pair is truncated (by word count) to
             the shorter one's length, producing a corpus where length cannot leak the label.
             This controlled-pair construction is the transferable methodological idea, not any
             compression or indexing technique.
techniques:
  - Length-aligned fake/true pairing: longer member of each pair truncated by word count to
    remove length-as-label leakage (size_normalized_texts/)
  - Fixed 25-field line-by-line metadata schema per doc: author, link, category, date, then 21
    numeric linguistic features
  - Hand-crafted truth features: pausality (punctuation count / sentence count), emotiveness
    (affective-term ratio), type-token diversity, spelling-error percentage, avg sentence/word
    length, POS counts (verbs, subjunctive/imperative, modal, pronouns)
  - Three parallel corpus variants from one source: full_texts (raw), size_normalized_texts
    (truncated), preprocessed (stopword-removed + accent-folded CSV)
  - Numbered filename convention (NNNN.txt / NNNN-meta.txt) as the join key aligning a doc, its
    label folder, and its metadata
  - Empirical baseline: SVM + bag-of-words reaches ~89% F-measure; the 21 hand-crafted features
    add almost nothing over BOW
nest steals: Two concrete uses. (1) Demo corpus: nest already ships PT-BR fake-news data; this is the
             canonical aligned source. Build a tiny-preset .nest (zstd/int8/hnsw) over the 7,200
             docs so chunks_canonical holds raw text, embeddings hold sentence-transformer
             vectors, and provenance records label+category+source-url per chunk -- a flagship
             offline single-file fact-check demo at ~0.283 size ratio. (2) Truth features as
             provenance: the 25-field metadata maps into nest-format's provenance section
             (additive, no format bump -- provenance is an existing v1 section whose meaning is
             unchanged). Store pausality/emotiveness/spelling-error-rate as per-chunk numeric
             provenance fields, surface them via nest-cli inspect/stats so a
             nest://content_hash/chunk_id citation shows credibility metadata next to the text
             span. Features are cheap deterministic single-pass counts (regex/POS over canonical
             text), computable at build time in nest-python with no model, fitting
             offline/deterministic constraints.
compression: Low to none. This repo contributes zero compression machinery -- no entropy coder, quantization,
             or on-disk format; data is uncompressed numbered .txt plus CSV. Indirect relevance:
             the size-normalization (truncate-to-shorter-pair) is a domain-specific length-cap
             heuristic, and the corpus is a realistic payload to benchmark nest's tiny preset
             (int8 + zstd-on-text + hnsw) and content_hash stability. The truth features are
             metadata to carry, not bytes to shrink.
perf:        Static dataset, no runtime. Small: 7,200 short-to-medium PT-BR articles (fake avg ~216 tokens,
             true avg ~1,268 tokens), on the order of a few MB of text, trivially mmappable and
             fully resident; ideal small fixture for deterministic-build and recall@10
             regression tests. The 21 linguistic features are O(n) single-pass token/punctuation
             counters, no SIMD or heavy compute needed.
license:     Academic/research use; corpus released with PROPOR 2018 (Monteiro et al.) and Expert Systems
             with Applications 2020 (Silva et al.). No explicit OSS license file in repo --
             treat as research-use, cite the papers; verify before redistributing inside a
             shipped .nest demo.
