what:        A curated, MIT-licensed "awesome list" / paper-and-dataset link index companion to two survey
             papers (TACL 2022 "A Survey on Automated Fact-Checking" and EMNLP 2023 multimodal
             survey) that organizes the automated-fact-checking field into a canonical pipeline
             taxonomy.
innovation:  The transferable artifact is not code (there is none) but a precise, widely-adopted
             decomposition of fact-checking into four pipeline stages -- claim
             detection/check-worthiness -> evidence retrieval -> verdict prediction (SUPPORTS /
             REFUTES / NOT-ENOUGH-INFO) -> justification production -- coupled to a taxonomy of
             evidence granularities (sentence-level, document-level, structured tables,
             multi-hop chains, web/social threads). This is the schema nest needs to model
             "truth features" and a retrieve-then-verify citation contract over its demo corpus.
techniques:
  - Four-stage AFC pipeline: claim detection/check-worthiness -> evidence retrieval -> verdict
    prediction -> justification
  - Three-label veracity schema (SUPPORTS / REFUTES / NOT ENOUGH INFO) from FEVER, with NEI as
    an explicit abstention class
  - Evidence-granularity taxonomy: sentence vs document vs table vs multi-hop chain vs
    conversation thread
  - Retrieve-then-verify framing where retrieval+verification are jointly 'factual verification'
    (maps onto nest's ANN-then-exact-rerank search contract)
  - Provenance-as-evidence pattern: claims bound to specific Wikipedia sentence ids/spans
    (analogous to nest's nest://content_hash/chunk_id span citations)
  - Multi-hop reasoning chains (HoVer/FEVEROUS) as ordered evidence sets -> motivates a future
    graph-search section linking chunk_ids
  - Check-worthiness as an importance-ranking/triage scoring stage before retrieval
nest steals: No crate steals code (this repo has none and is irrelevant to the FROZEN format). It informs
             three things. (1) nest-cli + demo docs: shape the PT-BR fake-news demo around the
             four-stage pipeline so a 'fact-check' is expressed purely as nest primitives --
             search-ann/search-text retrieve candidate evidence chunks, exact cosine rerank
             ranks them, and a citation nest://content_hash/chunk_id binds the verdict to an
             exact byte span (the provenance section already exists; this gives it semantic
             purpose). (2) provenance section schema (nest-format/src/sections): document a
             convention for a per-chunk 'claim/evidence role' plus a three-value veracity label
             (SUPPORTS/REFUTES/NEI) carried as provenance metadata key-values, staying
             additive-only (no new section id, no version bump). (3) roadmap only: multi-hop
             evidence chains are the concrete use-case justifying the mission's planned 'graph
             search' over chunk_ids, but this must wait for a reserved section id 0x09+ and is
             out of scope for v1. It unlocks a credible, citable fact-checking narrative without
             touching the frozen container or the compression path.
compression: n/a -- this is a link list with zero compression, encoding, quantization, or indexing
             implementation. It contributes nothing to the 'compress more than everyone' north
             star. Its only relevance is domain modeling for the demo corpus and the
             truth-feature narrative, which is orthogonal to the codec and on-disk format.
perf:        No runtime, no benchmarks, no throughput/SIMD/memory characteristics -- it is static markdown.
             Performance n/a. Only operational caveat: any dataset linked here that nest ships
             must be license-checked individually, independent of nest's own posture.
license:     MIT for the repository markdown; underlying datasets carry their own individual licenses (e.g.
             FEVER/FEVEROUS are Wikipedia-derived CC BY-SA share-alike) and must be
             license-vetted per-dataset before shipping any of them in a .nest demo corpus.
