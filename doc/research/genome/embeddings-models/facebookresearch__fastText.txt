what:        A C++ library for linear-bag-of-words text classification and subword word embeddings whose real
             gem for nest is its model-compression pipeline (fastText.zip): product quantization
             of the embedding matrix plus greedy coverage-based feature pruning, shrinking
             400MB+ models to single-digit MB with near-zero accuracy loss.
innovation:  Product Quantization of the embedding matrix: subvector k-means with 256 centroids (1-byte
             codes) plus decoupled scalar-quantized norms and asymmetric lookup-table scoring,
             enabling sub-byte-per-dimension storage scored without full decode.
techniques:
  - Product quantization: per-subvector-position k-means (k=256 -> 8-bit codes), dsub=2
    subvector dim, decouples norm (qnorm: scalar-quantize the L2 norm separately from the
    direction codes)
  - Greedy coverage-based feature pruning: keep the n-gram with highest L2 norm that covers each
    training doc, then top up by norm until a target feature budget is hit - retains only
    high-information rows before quantizing
  - Asymmetric distance computation: query stays full-precision; build a per-subvector lookup
    table of query-vs-256-centroids dot products, then scoring a code is m table lookups + adds
    (no decode)
  - Character n-gram subwords (3-6 chars, with < > word-boundary markers) hashed into a fixed
    bucket array for OOV-robust representations
  - FNV-1a hashing trick: n-grams mapped via h=2166136261, XOR+multiply by 16777619, mod
    bucket(=2M) into a fixed-size row table; n-gram rows placed after word rows to avoid
    word/ngram index collision
  - Hierarchical softmax over a Huffman tree of labels (frequent labels get shorter codes) for
    O(log k) classification
  - repr-stable little-endian binary model format (dictionary + hyperparams + quantized
    matrices) loadable by mmap
nest steals: Add a new embeddings codec encoding=4 ('pq') in crates/nest-format/src/encoding/ (new pq.rs
             sibling to int8.rs, registered in encoding/mod.rs and writer/encoding_choice.rs)
             using a reserved id in the 4-255 additive range - no NEST_FORMAT_VERSION bump.
             On-disk layout mirrors int8.rs prefix conventions: u32 payload_version, u32 dsub,
             the k-means codebook (m_subspaces * 256 * dsub f32 centroids, deterministic via
             seeded k-means to honor the reproducible-build constraint and alphabetical/seeded
             tie-breaks), per-vector scalar norm (reuse int8 norm machinery), then n*(dim/dsub)
             u8 centroid-index codes. In crates/nest-runtime the SIMD dispatcher gains a PQ
             scoring path: build the asymmetric lookup table (query dotted against the mmapped
             codebook with the existing AVX2/NEON/scalar dot kernels) once per query, then score
             every candidate as dim/dsub byte-indexed table lookups + adds straight off mmap -
             then feed into the MANDATORY exact-cosine rerank path so the returned score stays
             true cosine (PQ is only the ANN coarse filter, never the final score, exactly
             matching nest's search_contract). This makes a new 'nano' preset below tiny: at
             dsub=2 the embeddings section is ~half of int8 (approaching 0.14 size ratio
             territory) directly advancing 'compress more than everyone' while staying
             single-file/offline/deterministic. Optionally port the greedy coverage pruning into
             the python builder (nest-python/build path) to drop low-norm chunks/rows before
             encoding.
compression: Directly central. PQ is THE classic technique for pushing vector storage below 1 byte/dimension
             - it is what nest's current int8 codec (1 byte/dim, 4x) leaves on the table. At
             dsub=2,k=256 PQ stores 1 byte per 2 dims (8x base, ~16x vs f32 on the embedding
             bytes) with recall recoverable via the mandatory exact rerank. fastText.zip
             demonstrated ~250x model shrink (427MB -> 1.7MB) with negligible accuracy loss,
             validating that PQ + norm-decoupling + pruning is the highest-leverage path to beat
             everyone on embedding compression.
perf:        PQ scoring is cache- and SIMD-friendly: build one query lookup table (m_subspaces x 256 f32)
             using nest's existing AVX2/NEON dot kernels against the mmapped codebook, then each
             candidate costs dim/dsub u8-indexed loads + f32 adds - no float decode on the hot
             path, fits nest's score-off-mmap model. Codebook (m*256*dsub*4 bytes, e.g.
             dim=384,dsub=2 -> ~600KB) is tiny, stays hot in L2. Caveat: k-means training is the
             only added build-time cost and must be seeded for byte-identical deterministic
             builds; keep it in python builder, not rust library.
