what:        A Rust port of Hugging Face transformers built on the tch-rs libtorch bindings (with optional
             ONNX Runtime via ort), whose sentence_embeddings pipeline reproduces the
             Sentence-Transformers modules.json chain (Transformer -> Pooling -> optional Dense
             -> optional Normalize) to turn token sequences into fixed Vec<f32> embeddings.
innovation:  The exact, masking-correct reimplementation of the Sentence-Transformers post-processing chain
             in Rust: attention-mask-weighted mean pooling, optional dense projection, and L2
             normalization, driven declaratively by the model's own modules.config.json so the
             embedding is bit-faithful to the upstream Python model.
techniques:
  - Mask-weighted mean pooling: multiply token states by expanded attention mask, sum_dim over
    seq axis, divide by clamped mask-sum (min 1e-9) so padding never dilutes the mean
  - Alternative pooling modes in one struct: CLS (select(1,0)), max (masked_fill_ padding to
    -1e9 then max_dim), and mean-sqrt (divide by sqrt(mask_sum))
  - Declarative module chain parsed from modules.json/sentence_bert_config.json with enforced
    order (pos0 Transformer, pos1 Pooling, pos2-3 optional Dense/Normalize) via
    SentenceEmbeddingsModuleType enum
  - Dense post-projection layer (nn::Linear + activation) that can reduce embedding
    dimensionality before storage
  - L2 normalization making cosine similarity reduce to a plain dot product
  - tch-rs convert_model.py path: PyTorch .bin weights converted to a libtorch-loadable tensor
    store, cached under RUSTBERT_CACHE
  - rust-tokenizers multi-threaded WordPiece/BPE tokenization decoupled from the model
nest steals: nest never runs inference (python builds embeddings), so do NOT vendor tch/libtorch. The steal
             is narrow and goes into nest-python's build path plus nest-format provenance: (1)
             record the resolved Sentence-Transformers module chain (pooling mode, dense in/out
             dims, normalize bool) into the provenance section and search_contract as the model
             fingerprint, so two builds with the same chain are provably byte-identical and a
             consumer can verify the embeddings were L2-normalized. (2) If normalize=true is
             recorded in search_contract, nest-runtime's simd dispatcher can drop the per-vector
             norm in cosine rerank and run a pure dot product against the int8/f16 mmap'd
             embeddings section (the hot path), since cosine == dot for unit vectors. (3) The
             mask-weighted mean-pool semantics document exactly what a 'chunk embedding' means,
             hardening the deterministic contract; it is reference-level guidance, not Rust code
             to import into the small core.
compression: Low-to-indirect. rust-bert has no entropy coder, quantization, or on-disk compression to steal.
             The only compression-adjacent lever is the optional Dense projection layer, which
             is the upstream mechanism for shipping lower-dimensional embeddings (e.g.
             384->256): fewer dims directly shrinks nest's embeddings section, the largest
             tiny-preset payload. Recording normalize=true also lets the runtime store and score
             embeddings without keeping norms, marginally tightening the format.
perf:        Inference throughput is entirely libtorch/ONNX-bound (CPU or CUDA via .with_device()); no custom
             SIMD kernels, no quantized inference. Heavyweight C++ runtime dependency, opposite
             of nest's small-core/offline philosophy. The post-processing tensor ops (mean/max
             pool, normalize) are trivial and would be plain scalar/ndarray loops if ever
             ported.
