what:        A thin Rust port of sentence-transformers that runs DistilUSE/DistilBERT multilingual
             sentence-embedding models through libtorch (tch-rs/rust-bert), producing fixed-size
             embeddings via masked mean pooling plus a dense+tanh projection.
innovation:  The exact, reproducible embedding-head pipeline that turns per-token transformer outputs into
             one sentence vector: attention-mask-weighted mean pooling (sum of masked token
             embeddings divided by the clamped mask count) followed by a Dense linear+tanh
             projection. This is the canonical post-encoder math every sentence-transformer
             uses, and matching it bit-for-bit is what makes embeddings reproducible and
             model-aligned.
techniques:
  - masked mean pooling: input_mask_expanded = mask.unsqueeze(-1).expand_as(emb);
    (emb*mask).sum_dim(1) / mask.sum_dim(1) so padding tokens contribute zero
  - Dense embedding head: x.apply(linear).tanh() projecting hidden dim (768) to the model output
    dim, the learned reduction that defines the final vector space
  - dual tokenizer backends behind one API: HF tokenizers (wordpiece/BPE) and rust_tokenizers
    (sentencepiece), selectable as SBertHF vs SBertRT
  - batched forward over Vec<String> with rayon CPU parallelism sized by num_cpus
  - tch-rs/libtorch tensor ops (sum_dim_intlist, unsqueeze, expand_as, clamp) as the f32 compute
    kernel; output_attentions=true config flag exposes mask-aware tensors
  - offline model conversion via prepare_distilbert.py into a libtorch-loadable weights
    directory (Apache-2.0)
nest steals: nest-python is the embedding producer and MUST replicate this exact pooling+dense head so
             nest-runtime cosine scores are meaningful. Concretely: in nest-python's embedding
             build path, after running the encoder, apply the identical masked-mean formula
             (sum(token*mask)/clamp(sum(mask),1e-9)) then the model dense linear+tanh (or
             L2-normalize) head, and record the precise pooling mode plus dense weights identity
             inside the provenance section's model fingerprint. This locks determinism: same
             chunks + same model fingerprint => byte-identical embeddings. For nest-runtime,
             knowing the head is mean-pool+tanh (NOT L2-normalized by default here) clarifies
             that the SIMD dot-product hot path needs an explicit normalization assumption in
             search_contract; nest should pin 'embeddings are L2-normalized at build time' so
             the AVX2/NEON dot product equals true cosine with no per-query norm. The
             dual-tokenizer split (wordpiece vs sentencepiece) is also a direct fix for nest's
             bm25 CJK/Thai gap: adopting a sentencepiece-style subword tokenizer in nest-runtime
             bm25::Bm25Index removes the word-segmentation degradation while keeping
             deterministic alphabetical term ordering.
compression: Low and indirect. The repo has no entropy coder, quantization, or on-disk compression
             (embeddings are dense f32 tensors from libtorch). Its relevance to
             compress-more-than-everyone is upstream: pinning the exact pooling+dense head plus
             an explicit L2-normalize step is the precondition that makes nest aggressive
             embedding quantization (int8/float16 in tiny/compressed presets) safe -- once
             vectors are unit-norm, int8 scalar quantization preserves cosine recall (nest
             already reports recall@10 0.992 at 0.283 ratio). Without the deterministic
             normalized head, lossy embedding compression cannot be validated against a stable
             ground truth.
perf:        Runs on libtorch f32 via tch-rs 0.15 (heavy hundreds-of-MB native dependency, not embeddable --
             nest must NOT vendor this; reference-only for the math). CPU batching via rayon
             scaled by num_cpus. DistilUSE multilingual covers 13 languages, STS2017 score 80.1,
             output dim ~512 (768 hidden then dense projection). No SIMD kernel of its own;
             vector math delegated to libtorch BLAS. No quantization, no mmap, no custom on-disk
             format -- model is a plain converted libtorch weights directory.
