what:        A scalable client/server (gRPC, HTTP, WebSocket) for producing CLIP text+image embeddings and
             cross-modal rank scores, with swappable PyTorch / ONNX Runtime / TensorRT inference
             backends and DocArray protobuf transport.
innovation:  Decoupling the CLIP model into two independently-runnable towers behind a single L2-normalized
             shared embedding space, served through a portable ONNX Runtime backend so the same
             image-aligned text encoder (including XLM-RoBERTa-based multilingual M-CLIP) runs
             anywhere without the full PyTorch/CUDA stack. For nest the load-bearing idea is
             "the embedding model is a portable ONNX graph + a vocab, not a server" plus the
             cross-modal exact-score rerank pattern.
techniques:
  - ONNX Runtime backend: CLIP towers exported to a single .onnx graph run on CPU via
    onnxruntime with no PyTorch/CUDA dependency (TensorRT/JIT optional accelerators)
  - Two-tower shared embedding space: separate text and image encoders projecting into one
    L2-normalized 512/640/768/1024-dim space so cross-modal cosine is meaningful
  - M-CLIP multilingual: XLM-RoBERTa / LaBSE text tower aligned/distilled to the frozen CLIP
    image space, giving non-English (PT-BR, CJK) text image-aligned vectors
  - /rank cross-modal re-ranking: cheap candidate gather then exact joint CLIP-score (softmax of
    logit_scale * cosine) rerank, returning a real score not an ANN proxy
  - minibatch_size (default 32) encode batching decoupled from num_worker_preprocess (4) CPU
    preprocessing workers: separate preprocessing parallelism from the encode kernel
  - DocArray columnar protobuf serialization of ndarrays with streaming on-disk format and
    configurable ndarray_type/dtype for large batch transfer
nest steals: nest-python build path: adopt the ONNX Runtime CPU backend pattern so nest's embedding step is a
             portable .onnx graph + tokenizer instead of a torch dependency, keeping builds
             deterministic and shrinking the model payload shipped with the demo corpus. Adopt
             an M-CLIP-style XLM-RoBERTa/LaBSE multilingual text tower as a default text model
             fingerprint written into provenance: this fixes the documented bm25 CJK/Thai
             degradation at the embedding layer and matches the PT-BR fake-news datasets, all
             into the existing embeddings section. In nest-runtime the /rank pattern is
             conceptually identical to nest's mandatory exact-cosine rerank after hnsw/bm25 RRF,
             validating that design; a logit_scale*cosine softmax could be an optional scoring
             mode in search_contract. The image tower (ViT-B/32 exported to ONNX) is the
             concrete route to the mission's "fast image similarity": image vectors land in the
             same embeddings section and are scored by the existing SIMD dot-product dispatcher
             with zero new codec, since L2-normalized CLIP image embeddings cosine-search
             identically to text. Fully additive: no format bump, only embeddings +
             provenance(model fingerprint).
compression: Low-to-indirect for raw bytes-on-disk compression. clip-as-service has no entropy coder, no
             embedding quantization, and no on-disk index; it never compresses embeddings
             (mirroring nest's rule that embeddings stay raw for hot-path scoring). The
             compression-adjacent wins are second-order: a portable ONNX text+image model
             shrinks the build-side dependency/model payload vs a torch install, and a single
             shared 512-dim image-aligned space lets images and text reuse one embeddings
             section and one SIMD kernel instead of a separate image codec, keeping the format
             minimal. CLIP's native fp16 weights also confirm nest's float16 embedding preset is
             safe for these vectors.
perf:        Documented ~800 QPS on an RTX 3090 default config; throughput is GPU-bound and irrelevant to
             nest's CPU/mmap runtime. Transferable perf lessons: the preprocessing/encode split
             (num_worker_preprocess=4 vs minibatch_size=32), and that ONNX Runtime CPU inference
             of a ViT-B/32 tower is viable for batch indexing on commodity hardware. CLIP
             embeddings are L2-normalized so nest's cosine==dot-product fast path applies
             directly, and image and text vectors share the exact same SIMD dot kernel
             (AVX2/NEON/scalar) with no per-modality branch.
