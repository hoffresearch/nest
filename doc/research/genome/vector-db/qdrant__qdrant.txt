what:        A Rust vector database whose differentiating engine is a stack of rescore-backed quantization
             codecs (scalar int8, binary 1/1.5/2-bit, product, and the new data-oblivious
             TurboQuant) under an HNSW graph, where compressed vectors live hot and
             full-precision originals stay on disk purely for a two-stage rescore.
innovation:  TurboQuant (Google Research, ICLR 2026, as extended by qdrant): a DATA-OBLIVIOUS quantizer
             needing NO trained codebook. Apply a fast randomized Hadamard rotation (seeded
             deterministic sign flips + Walsh-Hadamard transform, O(d log d)) to each vector,
             which provably redistributes energy uniformly so every coordinate becomes
             ~Beta-distributed regardless of the embedding model. Then quantize every coordinate
             with ONE global precomputed Max-Lloyd (1-D k-means) codebook baked in at compile
             time. A per-vector scalar length-renormalization factor
             (orig_length/reconstruction_length, borrowed from RaBitQ) corrects the systematic
             length-shrink bias. Scoring is asymmetric: stored vectors pack to 1-4 bits, the
             query stays full precision and is rotated the same way, so one SIMD pass over
             packed codes yields a real distance estimate.
techniques:
  - Randomized Hadamard rotation: seeded sign-flip (LCG) + fast Walsh-Hadamard transform in O(d
    log d), making any embedding distribution coordinate-uniform so a single global codebook
    suffices (no training, deterministic)
  - Compile-time baked Max-Lloyd codebooks: precomputed optimal 1-D k-means quantizers for
    Beta-distributed coords at 1/1.5/2/4-bit; data-oblivious so reproducible
  - Per-vector length renormalization (RaBitQ trick): store one f32 scale =
    orig_len/quantized_len to cancel quantization's systematic length-shrink, applied at score
    time
  - Asymmetric quantization: compress stored vectors to k bits, keep query full precision ->
    higher recall at same storage; query rotated then encoded into a SIMD scoring form
  - Scalar int8 with algebraic dot decomposition: expand (alpha*i8+offset)*(alpha*i8'+offset) so
    offset/min cross-terms precompute per-vector, leaving ONLY raw int8.int8 dot at query time
    -> AVX-512 VNNI vpdpbusd / NEON sdot
  - Binary quantization via sign bit + XOR/popcount Hamming; 1.5-bit and 2-bit variants
    explicitly encode near-zero values to fix binary's weakest case
  - Two-stage retrieve-then-rescore: oversample 2x-4x candidates on cheap quantized distance,
    then rescore the small set against full-precision originals via async IO (all ids known, no
    random-access penalty) -> recall 0.98-1.0
  - Quantile-calibrated bounds (e.g. 0.99) to clip outliers before linear int8 mapping
nest steals: Add a TurboQuant codec to nest-format/src/encoding alongside int8/float16, applied ONLY to the
             embeddings section (new encoding id from the reserved 4-255 range, additive, no
             NEST_FORMAT_VERSION bump). Build pipeline (python side, nest-python): per vector ->
             normalize for metric -> pad to power of 2 -> seeded sign-flip + Walsh-Hadamard
             rotation -> assign coords against a codebook baked as a rust const -> pack to
             1/2/4-bit -> store one f32 renorm scale per vector. Compile-time const codebook
             keeps builds byte-identical/deterministic (nest's hard constraint) and needs NO
             corpus stats. nest-runtime gets a new asymmetric SIMD scorer in the simd
             dispatcher: rotate the f32 query once, dot against packed codes (AVX2/NEON/scalar
             fallback already exist). This PRESERVES nest's mandatory exact-cosine rerank:
             TurboQuant is the cheap oversample stage, and the search-contract rerank reads the
             original f32 embeddings (kept raw/mmap, never zstd) so the returned score stays
             true cosine. Unlocks a preset below the int8 'tiny' floor: TurboQuant-4bit ~halves
             embedding bytes vs int8 at comparable recall; 1-bit/1.5-bit go smaller than binary
             while beating it on recall -- directly advancing 'compress more than everyone'. The
             Hadamard rotation is a self-contained, seeded, reversible ~one-file util respecting
             <=300-line and never-panic rules.
compression: Directly central. TurboQuant is the single best lever for nest's 'compress more than everyone'
             goal on the embeddings section -- the largest, least-compressible part (zstd is
             forbidden there since vectors are scored from mmap). 4-bit gives ~2x over the
             current int8 'tiny' preset at similar recall; 1-bit/1.5-bit beat binary
             quantization on recall at smaller size. Being data-oblivious with compile-time
             codebooks, it is the ONLY high-end quantizer that keeps nest's
             deterministic/reproducible-build and no-training guarantees, and asymmetric
             full-precision query scoring plus the existing exact-cosine rerank make the
             compression lossless for the FINAL returned score.
perf:        Hadamard rotation O(d log d) per vector (one-time at build for stored vectors; once per query at
             search). int8 path: only raw int8.int8 dot at query time -> AVX-512 VNNI vpdpbusd
             (x86) / NEON sdot (aarch64), ~4x lane density vs f32, ~75% RAM cut, <0.3% recall
             loss, 28-60% latency win on qdrant benchmarks. Binary: XOR+popcount Hamming, up to
             40x speedup. TurboQuant 4-bit: scalar-quality recall at 2x compression;
             SIMD-accelerated for cosine/dot/L2 (L1 needs full reconstruction, slow). Rescore
             needs no random access -- all candidate ids known, originals streamed from disk, so
             cheap mmap/network disks suffice. nest already has AVX2/NEON/scalar dispatch, so
             the asymmetric scorer slots into existing infra.
