what:        A PostgreSQL extension (vchordrq) that indexes vectors as IVF posting lists where each vector is
             stored as a tiny RaBitQ-quantized bit-code, scanning compressed codes with binary
             popcount arithmetic and deferring full-precision math to an adaptive rerank stage.
innovation:  RaBitQ quantization: apply a random rotation (Johnson-Lindenstrauss / Fast Hadamard Transform)
             to the residual of a vector around its cluster centroid, take the sign bits to get
             a 1-bit-per-dim code, and store just two corrective float scalars per vector
             (centroid distance + the inner product between the quantized and normalized
             vector). The cosine/L2 estimate is reconstructed from a single binary dot product
             plus those two scalars, and crucially it is an UNBIASED estimator with a provable
             O(1/sqrt(D)) error bound (asymptotically optimal, Alon-Klartag). That is what
             separates it from product quantization, which is biased and silently fails on some
             datasets. The binary dot product is popcount(code AND query_bits); the multi-bit
             variant (RaBitQ4/8) reuses the same machinery by quantizing the QUERY into
             bit-planes q1,q2,q3,q4 and summing weighted popcounts: 1*popcount(code&q1) +
             2*popcount(code&q2) + 4*popcount(code&q3) + 8*popcount(code&q4) -- the data stays 1
             bit/dim while query precision is tunable.
techniques:
  - RaBitQ 1-bit quantization: random-rotation + sign-bit code + 2 corrective scalars
    (centroid_dist, <quantized,normalized>) giving an unbiased estimator with O(1/sqrt(D)) error
    bound
  - Residual quantization: quantize each vector relative to its IVF centroid and reformulate
    <o,q-c>=<o,q>-<o,c> so the query is rotated/quantized once per probe (~20% QPS)
  - Random rotation via Fast Hadamard Transform (O(D log D), no dense DxD matrix to store) to
    spread information before sign-bit extraction
  - Binary distance estimator = popcount(code AND query_bits); multi-bit = weighted-popcount
    over query bit-planes keeping data at 1 bit/dim
  - SIMD Fast Scan: bit-pack/transpose codes to estimate 32 vectors per kernel pass;
    single-vector popcount path beats PQ table-lookups ~3x
  - IVF posting lists instead of a global graph: insert=append code, delete=clear code, no
    cascading graph repair, deterministic and update-friendly
  - Adaptive two-stage search: scan all codes with cheap integer math, then full-precision
    rerank only a small top subset sized by the error bound
  - DiskANN + 2-bit RaBitQ (vchordg) alternate graph index trading update cost for higher QPS at
    high recall
nest steals: Add a RaBitQ-style codec as a new RESERVED encoding id (4-255, additive within v1, no
             NEST_FORMAT_VERSION bump) in nest-format/encoding, targeting the embeddings
             section. Per embedding store a 1-bit-per-dim sign code plus two f32 corrective
             scalars computed against a small set of seeded deterministic k-means centroids
             serialized alongside (seeded => reproducible, honors the determinism guarantee). In
             nest-runtime add a binary-popcount estimator kernel to the simd dispatcher
             (popcount is one instruction on AVX2/NEON, trivial scalar fallback) as the cheap
             first pass; nest already mandates an exact-cosine rerank on the hot path, which is
             precisely RaBitQ's two-stage model, so the search_contract is unchanged and the
             returned score stays real cosine. This unlocks an embeddings encoding far smaller
             than int8 (1 bit/dim vs 8 => ~8x on the dominant section) and the provable error
             bound lets you bound rerank candidate count instead of guessing. The Fast Hadamard
             rotator (O(D log D), nothing dense to persist) is the only new primitive and fits
             as one <=300-line module. Longer term, the IVF posting-list layout (centroid id ->
             contiguous code run) is a deterministic, cheap-to-build alternative to hnsw_index.
compression: Directly central to 'compress more than everyone'. Embeddings are the largest,
             least-compressible section in a .nest file (zstd is banned on them because they are
             scored from mmap). RaBitQ is the rare scheme that compresses embeddings 8-32x WHILE
             keeping them scoreable in place via popcount on the hot path -- no decode step
             before scoring, unlike a generic entropy coder. Combined with nest's existing
             mandatory exact rerank, recall is recovered for free, making this the
             highest-leverage way to shrink the dominant section without breaking the score
             contract.
perf:        Single-vector RaBitQ via popcount is ~3x faster than PQ in-RAM table lookups at equal accuracy;
             batch Fast Scan estimates 32 vectors per pass; estimate is integer/bitwise only,
             full-precision floats touch only the reranked subset. Storage claims: ~6x more
             vectors than Pinecone optimized storage, ~26x vs pgvector at equal cost; 1M 960-dim
             indexed in ~1.5 min, 100M under 20 min with precomputed centroids; residual
             reformulation ~20% QPS; Fast Hadamard rotation O(D log D) with no dense matrix to
             load, important for an mmap/disk design.
