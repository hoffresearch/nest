what:        Go-based vector database whose flagship compression is 8-bit Rotational Quantization (RQ): a
             RaBitQ-inspired scheme that applies a fast pseudorandom Walsh-Hadamard rotation to
             each vector so per-vector min/max scalar quantization to int8 becomes
             near-lossless, then guarantees recall via a mandatory full-precision rescore stage
             on HNSW candidates.
innovation:  Rotate-then-quantize: a deterministic fast pseudorandom rotation (three rounds of blocked Fast
             Walsh-Hadamard Transform with seeded element swaps + sign flips, O(D log D)) makes
             any embedding's coordinates approximately normally distributed before scalar
             quantization. This smooths the min-max interval and spreads similarity information
             uniformly across all dimensions, so naive per-vector min/max int8 quantization
             becomes near-lossless (98-99% recall@10) at 4x compression WITHOUT any trained
             codebook or k-means, so it stays fully deterministic and data-independent.
techniques:
  - 8-bit Rotational Quantization (RQ): per-vector store = D int8 codes + l_x (f32 min) +
    delta_x (f32 step) + squared-norm (f32), ~96 bits metadata overhead per vector
  - Fast pseudorandom rotation = 3 rounds of blocked Fast Walsh-Hadamard Transform, padded to
    multiple of 32/64, with seeded random element permutation and random sign flips per round
    (O(D log D), ~7us for D=1536)
  - Decomposed quantized inner product: <q,x> approx = d*lq*lx + lq*dx*sum(cx) + lx*dq*sum(cq) +
    dq*dx*<cx,cq>, where only the int8 dot product term needs the hot SIMD kernel (~2.3x faster
    than f32)
  - 1-bit RQ variant: sign-bit binary codes after rotation giving ~32x compression as D grows,
    Hamming distance via XOR+popcount
  - Binary Quantization (BQ): sign threshold to 1 bit/dim, distance via bitwise XOR + SIMD
    popcount, ~5% of f32 search latency
  - Mandatory two-stage rescore (rescoreLimit): HNSW walks on compressed distances, then top
    candidates get exact full-precision distance recompute for the returned score
  - Output dimension rounded up to nearest multiple of 64 so FWHT blocks and the SIMD int8 dot
    product stay aligned
nest steals: Upgrade crates/nest-format/src/encoding/int8.rs from naive per-section int8 to a rotation-aware
             per-vector RQ codec, registered as a NEW additive encoding id (4-255 reserved
             range) so the FROZEN v1 format and existing int8 stay byte-compatible. Store per
             embedding row: D int8 codes plus three f32 scalars (l_x, delta_x, sq_norm).
             Determinism is preserved because the rotation seed derives from the model
             fingerprint already in the manifest (no trained codebook, no k-means -- fits nest
             reproducible builds exactly, unlike PQ). Add a small FWHT helper (well under the
             300-line cap, pure repr(C)/little-endian, no panics) plus the decomposed int8
             inner-product kernel into the nest-runtime SIMD dispatcher (AVX2/NEON/scalar)
             beside the existing dot-product path. Near-perfect fit for nest's 'hnsw + mandatory
             exact cosine rerank' contract: RQ does the cheap candidate walk and nest's
             already-mandatory exact cosine rerank IS the rescore stage, so the returned score
             stays real cosine. Net: the 'tiny' preset int8 recall@10 should climb from 0.992
             toward 0.998+ at the same 4x size, and a 1-bit RQ mode unlocks a new ultra-tiny
             preset at ~32x embedding compression. nest-cli benchmark/stats surface the recall
             delta; nest-python needs no change.
compression: Directly central. RQ is the rare quantizer that is simultaneously (a) data-independent and
             deterministic (seeded rotation, no trained codebook), satisfying nest's
             reproducible-build and additive-format constraints where Product Quantization
             fails, and (b) near-lossless at 4x with a 1-bit path at ~32x. It pushes the 'tiny'
             preset toward best-in-class embedding compression at fixed recall, the literal core
             of the compress-more-than-everyone mission, while embeddings stay directly scorable
             from mmap on the hot path (int8 codes read raw, no entropy decode).
perf:        Rotation ~7-10us for D=1536 (O(D log D), three blocked-FWHT rounds, 64/256-element block
             kernels). Distance estimate ~2.3x faster than f32 since the dominant cost is an
             int8 inner product (Apple M4 NEON ~182 M ops/s for 64-dim 8-bit RQ vs ~145 M ops/s
             f32). Memory: 1M x 1536-dim drops 5859 MB -> 1465 MB (4x). 1-bit RQ and BQ use
             XOR+popcount, ~5% of f32 latency. Fixed 96-bit/vector metadata overhead is
             negligible at typical D but favors higher-dimensional embeddings.
