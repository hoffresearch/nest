what:        Distributed vector database whose single most transferable kernel is Knowhere/ScaNN's FastScan:
             4-bit product quantization scored by SIMD in-register lookup tables, combined with
             anisotropic quantization and a mandatory full-precision refine stage.
innovation:  FastScan = 4-bit product quantization where each sub-vector maps to one of 16 centroids (4
             bits/subspace), and the per-query distance lookup table is held entirely in SIMD
             registers so distance computation becomes register byte-shuffles (in-register ADC)
             instead of memory-bound table loads. Paired with anisotropic quantization, which
             trains the PQ codebook to penalize the residual component PARALLEL to each vector
             more than the orthogonal component, preserving inner-product/cosine ranking
             accuracy instead of minimizing raw reconstruction error. Both are made safe by
             over-fetching candidates and re-ranking the top reorder_k with exact full-precision
             distance.
techniques:
  - FastScan 4-bit PQ: 16 centroids per subspace packed at 4 bits, distance LUT kept in SIMD
    registers (in-register ADC) eliminating the memory-load bottleneck of classic PQ table
    lookups
  - Anisotropic vector quantization (Guo et al 2020 MLR): score-aware loss weighting parallel
    residual error higher than orthogonal, optimizing for MIPS/cosine ranking not L2
    reconstruction
  - Runtime SIMD dispatch via Google Highway generating AVX2/AVX512 from one source; AVX2 pshufb
    / AVX512 vpermb / NEON vqtbl1q for the 16-entry table gather
  - Mandatory exact refine stage (reorder_k / with_raw_data / FP32 refiner): over-fetch from
    lossy index then recompute true distance on raw vectors -- identical to nest's mandatory
    exact cosine rerank
  - SQ8 scalar quantization: per-dimension f32->uint8 affine map storing min/scale (~4x), with
    IVF clustering as a coarse quantizer
  - JSON shredding: classify keys into typed columns (frequent+consistent type), dynamic columns
    (frequent+mixed type, path-named like /user/name), and a shared binary-JSON column with an
    inverted index for sparse keys
  - Per-field columnar binlog: each column is its own file with a magic-number header + typed
    event stream and an ExtraBytes slot for additive format evolution without breaking
    compatibility
  - Storage Format V2 adaptive layout: 'narrow column merging + wide column independence'
    co-locates small scalar columns, keeps large vector columns independent, enabling random
    point lookups without Parquet I/O amplification
nest steals: Add a PQ codec to nest-format as a new encoding id (reserved 4-255 space, additive within v1)
             applied ONLY to the embeddings section -- the one place nest currently refuses to
             compress because it scores from mmap. FastScan flips that: the 4-bit PQ codes ARE
             the mmap'd hot-path data and the per-query LUT is built once into registers, so you
             keep zero-copy scoring while reaching 8-32x compression vs raw f32 (beyond today's
             int8 4x and zstd's no-op on embeddings). Concretely: (1) nest-format gains a pq
             codec module -- write side runs deterministic seeded k-means per subspace, stores
             tiny codebooks in a sub-section plus 4-bit codes. (2) nest-runtime simd adds a
             FastScan kernel building the 16-entry-per-subspace LUT per query, then AVX2 pshufb
             / AVX512 vpermb / NEON vqtbl1q in-register gather to accumulate distances --
             mirrors the existing AVX2/NEON/scalar dispatch shape, stays <=300 lines, typed
             errors. (3) Search path needs ZERO contract change because nest ALREADY mandates an
             exact cosine rerank: PQ becomes another approximate first stage, over-fetch then
             rerank against existing raw/f16 vectors so returned scores stay real cosine. (4)
             New preset 'micro' (zstd/pq/hnsw) targeting <0.1 size ratio below 'tiny'.
             Anisotropic codebook training is a pure build-time python change to the k-means
             loss (deterministic, no format change, better recall at same bytes). Separately,
             JSON shredding maps onto nest's roadmap to compress json/yaml/datasets: a future
             shredding codec for a structured-data section turns repetitive nested docs into
             typed columns that zstd compresses far better than raw text.
compression: Directly central to 'compress more than everyone'. Embeddings are nest's largest,
             currently-incompressible section (zstd skips them, int8 reaches only 4x). FastScan
             4-bit PQ reaches 8-32x on exactly that section while staying mmap-scored on the hot
             path, and anisotropic training recovers the recall PQ would otherwise lose -- the
             single biggest available win on nest's dominant byte cost. The exact-rerank safety
             net nest already enforces is precisely what makes aggressive lossy quantization
             acceptable.
perf:        In-register LUT turns PQ scoring from memory-bound to compute-bound; ScaNN reported ~5x QPS over
             IVF_FLAT on Cohere-1M. 4-bit codes pack 2 subspaces/byte: a 768-d vector with 96
             subspaces = 48 bytes vs 3072 bytes f32 (~64x raw, before tiny codebook overhead).
             AVX2 pshufb is a 16-byte shuffle (exact fit for 16 centroids); AVX512 vpermb;
             aarch64 NEON vqtbl1q. Refine cost scales with reorder_k only, not corpus size, so
             the exact-rerank tax stays bounded.
