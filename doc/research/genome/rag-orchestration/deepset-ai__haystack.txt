siblings: ./00-index.txt   |   map: ../../README.txt

what:        A Python LLM/RAG orchestration framework whose pipelines are serializable component DAGs (now
             with cycles), with a pure-Python InMemoryDocumentStore that holds an
             incrementally-maintained BM25 inverted index (BM25Okapi/BM25L/BM25Plus) and does
             dense retrieval via a single numpy matmul, persisting everything to a single JSON
             file.
innovation:  The incrementally-maintained, in-memory BM25 inverted index (mutable corpus stats updated per
             write/delete) is the transferable idea: it turns nest's frozen bm25 build into
             something that supports live edits.
techniques:
  - Incremental BM25 statistics: per-doc Counter(token)->freq + doc_len stored alongside doc;
    global _freq_vocab_for_idf (df map) and running _avg_doc_len updated on every write/delete
    instead of full reindex
  - Three BM25 scoring variants behind one interface: BM25Okapi vs BM25L vs BM25Plus, where
    L/Plus add a delta term (+delta in numerator/idf) to stop long-document over-penalization;
    tunable k1/b/epsilon
  - Configurable tokenizer as a single regex (r'(?u)\b\w\w+\b') captured in config, making
    tokenization a serialized, reproducible parameter
  - Dense retrieval as one BLAS call: stack all doc embeddings into a 2D array, scores =
    np.dot(query, embeddings.T) then top-k - identical math to nest's SIMD dot-product fan-out
  - to_dict/from_dict component contract: every component (incl. document store, retriever)
    serializes to a plain dict of construction params (e.g. store IP+db name, not the live
    client), enabling deterministic rebuild
  - Single-file persistence: save_to_disk/load_from_disk dump the whole store (config +
    documents + stats) to one JSON file
  - Pipeline-as-data: the entire orchestration graph (components + typed input/output
    connections) serializes to YAML and round-trips, with deserialize callbacks for component
    rewriting
nest steals: Steal the incremental BM25 maintenance model for nest-runtime crates/nest-runtime/src/bm25.rs:
             keep the on-disk bm25_index(0x08) as the frozen cold start, but add an in-memory
             delta layer holding per-chunk term-frequency maps, a global df map, and a running
             avg_doc_len so live edits (insert/delete chunk) update scores without a full Python
             rebuild - this directly unlocks the north-star "real-time edit + fast search"
             without breaking the frozen container (the persisted 0x08 stays
             additive/deterministic, alphabetical term order preserved). Secondly, adapt the
             BM25L/BM25Plus delta-smoothing formula into the existing Bm25Index scoring path as
             a config flag in search_contract (nest-format) so recall on long/heterogeneous
             chunks improves; keep alphabetical term order for determinism. Thirdly, mirror the
             to_dict/from_dict contract as nest's reproducibility surface: the search_contract
             section already fingerprints config, and Haystack confirms that capturing
             tokenizer-regex + bm25 params + similarity-fn as serialized scalars is exactly what
             makes builds replayable - validates nest's content_hash design. Low compression
             relevance: this is index/orchestration plumbing, not an entropy coder; nest already
             beats Haystack on storage (Haystack stores raw JSON + full-precision f32 embeddings
             with zero quantization, whereas nest has zstd/f16/int8/hnsw).
compression: Low/indirect. Haystack does no compression or quantization at all (save_to_disk is plain JSON,
             embeddings kept as full-precision f32 in a numpy array), so it offers nothing for
             the 'compress more than everyone' goal directly - nest is already far ahead here.
             Its relevance is to the adjacent north-star pillars (real-time edit, fast
             BM25/hybrid search), not to the entropy/quantization frontier.
perf:        Dense retrieval is a single numpy.dot (BLAS) over the full stacked embedding matrix then top-k -
             O(N*d) brute force, no ANN in the in-memory store (ANN is delegated to external
             vector DBs); fine at small N, does not scale, and is exactly the brute-force path
             nest already replaces with SIMD + HNSW. BM25 scoring is pure-Python over Counters
             (slow vs a compiled Rust scorer). No SIMD, no mmap, no quantization.
             Whole-store-in-RAM model; persistence is a full JSON rewrite, not append/mmap, so
             it has no zero-copy or partial-load story.
