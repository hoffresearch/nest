what:        An opinionated, YAML-configured LangGraph RAG engine (quivr-core) paired with MegaParse, a
             "lossless" document-to-markdown ingestion tool that combines layout models with
             vision-LLM table reconstruction, plus a deterministic iterative token-budget
             context-reduction algorithm.
innovation:  The MegaParse ingestion contract: normalize any source document (PDF/DOCX/PPTX/XLSX) into a
             single canonical, hierarchy-preserving markdown representation BEFORE
             chunking/embedding, by routing each region through a layout model (~90% table
             segmentation) and falling back to a vision LLM that crops hard tables and
             reconstructs them as markdown. The canonical text is the thing you chunk, hash, and
             serve -- decoupling messy source bytes from a stable normalized representation.
techniques:
  - MegaParse two-tier table extraction: layout-model segmentation (unstructured/doctr) for ~90%
    of tables, vision-LLM (gpt-4o/claude-3.5) crop-and-reconstruct fallback for complex tables
    -> markdown
  - Hierarchy-aware partition->chunk: split on document-format semantic units (headers, TOC,
    sections) first, only fall back to text-splitting (\n\n) when an element exceeds max chunk
    size (the 'unstructured' chunking model)
  - Deterministic combine_documents: assign sequential metadata['index']=0,1,2... to chunks so
    retrieved fragments can be re-ordered and mapped back to source position
  - retrieve_full_documents_context: rank by similarity score + chunk frequency, then
    reconstruct full-document context up to the highest chunk index per knowledge item
    (chunk->full-doc expansion)
  - reduce_rag_context: iterative arithmetic context fitting with an 85% security factor -- drop
    oldest chat-history pairs first, then drop chunks from the longest task, recomputing token
    count until it fits max_context_tokens
  - dynamic_retrieve: saturation-driven retrieval that multiplies k/top_n per iteration (max 3)
    until enough relevance-thresholded chunks are found
  - ContextualCompressionRetriever pattern: base vector retrieval ALWAYS followed by a pluggable
    reranker (Cohere/Jina) with IdempotentCompressor no-op fallback
  - YAML-declared RetrievalConfig/WorkflowConfig/NodeConfig as a portable, declarative
    description of the whole search pipeline
nest steals: nest-python ingestion + nest-format: adopt a MegaParse-style 'canonicalization-before-chunk'
             stage so PDF/DOCX/PPTX are first normalized to deterministic markdown, then that
             normalized text becomes chunks_canonical(text) while raw source byte spans feed
             chunks_original_spans -- this directly strengthens nest's content_hash STABILITY
             guarantee (hash the normalized canonical form, not the encoding-dependent source)
             and makes the 'compress and serve PDF/parquet/datasets' north-star tractable. The
             chunk->full-doc index reconstruction
             (combine_documents/retrieve_full_documents_context) maps cleanly onto nest's
             chunks_original_spans + nest://content_hash/chunk_id citation reopen: store the
             sequential chunk index and parent-doc id so a hit can rehydrate the surrounding
             original span. The reduce_rag_context 85%-factor iterative trimming is a tiny
             deterministic, panic-free pure-integer algorithm that belongs in nest-runtime
             materialize as a 'fit retrieved chunks into a token/byte budget' helper
             (drop-lowest-score-first, recompute, stop when under budget) -- offline, no LLM
             call, fully reproducible. The ContextualCompressionRetriever 'always rerank'
             pattern validates nest's existing mandatory exact-cosine rerank as the correct
             architecture.
compression: Indirect but real: MegaParse's normalize-to-canonical-markdown step is a precondition for
             extreme compression of heterogeneous formats -- you cannot
             deduplicate/zstd/entropy-code PDF or parquet effectively until you have lifted them
             into a single normalized text/structure representation. Canonicalizing before
             hashing also makes content_hash stable across source encodings (already a nest
             goal) and exposes far more cross-document redundancy for zstd on non-embedding
             sections. The chunk->full-doc index lets nest store one canonical body once and
             reference spans rather than duplicating overlapping chunk text. No new entropy
             coder or quantization scheme is offered here -- this repo is pure Python RAG glue,
             not a codec.
perf:        Pure-Python, langgraph/asyncio orchestration; no SIMD, no custom on-disk format, vectorstores
             are delegated to PGVector or Faiss. Heavy paths (vision-LLM table reconstruction,
             Cohere/Jina rerank) are network/GPU-bound external API calls -- antithetical to
             nest's offline-by-construction constraint, so only the ALGORITHMS (budget trimming,
             chunk indexing, hierarchy chunking) are stealable, not the runtime.
             dynamic_retrieve caps at 3 iterations; reduce_rag_context is O(n) per trim pass
             over chunks. No memory-mapping, no zero-copy; everything is in-RAM Python objects.
