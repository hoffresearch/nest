what:        A general-purpose LZ77-family compressor that pairs a fast match-finder with two entropy
             back-ends (Huff0 Huffman for literals, FSE/tANS table-based ANS for sequence
             symbols), plus trained dictionaries, long-distance matching, and a repeat-offset
             cache, all wrapped in a self-describing frame/block format.
innovation:  Trained dictionaries: zstd's ZDICT trainer (COVER/fastCover greedy segment selection) builds a
             small shared "prior" -- a synthetic past window plus pre-baked entropy tables
             (Huffman tree + FSE tables for literals/match-lengths/offsets + 3 seed
             repeat-offsets) -- prepended to the decode window so each tiny,
             independently-decodable payload compresses against shared cross-record statistics
             instead of starting cold. This is exactly nest's regime: many small
             structurally-similar records (chunk_ids, spans, provenance JSON, BM25 postings)
             compressed in isolation, where per-payload entropy tables and LZ history are pure
             overhead today.
techniques:
  - Two-stage entropy: Huff0 (canonical Huffman, max 11-bit codes, weight-encoded tree) for
    literals; FSE = table-driven tANS for literal-length/match-length/offset symbols, with an
    Accuracy_Log power-of-2 normalized distribution and per-symbol (Symbol, Num_Bits, Baseline)
    decode rows
  - 4 independent Huffman bitstreams decoded in parallel for ILP vs 1 stream; bitstreams read
    backward from the last byte
  - Repeat-offset cache: 3 most-recent offsets (rep1/rep2/rep3) with single-stepped wrapping
    rotation, so periodic data spends ~1 offset code instead of a full offset
  - Per-block FSE table modes: Predefined / RLE / FSE_Compressed / Repeat (reuse previous
    block's table) to amortize table cost
  - ZDICT dictionary trainer (COVER / fastCover): greedy frequent-segment selection building a
    shared prior + pre-baked entropy tables + seed repeat offsets
  - Long-distance matching (LDM): a coarse hash-chain over a large window (up to 2GB) catching
    far-apart duplicates before the normal match-finder
  - Self-describing frame: 4-byte magic + 2-14B header, 3-byte block headers, optional xxHash-64
    checksum, plus 16 skippable-frame magics (0x184D2A5x) for additive metadata old decoders
    skip
  - Configurable speed/ratio via levels incl. negative --fast levels; decode speed roughly
    constant across levels
nest steals: Three concrete moves, all in nest-format/src/encoding/zstd_codec.rs and the writer. (1)
             DICTIONARY: add zstd_encode_with_dict/zstd_decode_with_dict using zstd's dictionary
             API. Train ONE deterministic dictionary at build time over the small repetitive
             sections (chunk_ids, chunks_original_spans, provenance, search_contract, BM25
             postings/terms in 0x08) and store it as a new additive section (reserved id 0x09)
             or in the manifest. Determinism holds because ZDICT is a pure function of sorted
             samples (feed them in canonical/alphabetical order). (2) KNOBS: replace hardcoded
             encode_all(bytes, 19) with a ZstdParams struct (level +
             enable_long_distance_matching + window_log) set per preset (tiny -> level 22 + LDM
             for the whole-database/repo payloads in the north star). (3) SKIPPABLE-FRAME
             PATTERN as a format lesson for nest-format/src/layout: zstd's 0x184D2A5x magics are
             the canonical way an additive format lets old readers skip unknown extensions --
             mirror this for nest's reserved section ids 0x09+. Constraints respected: zstd
             never touches embeddings (hot SIMD path), section checksums still hash physical
             bytes, content_hash still hashes decoded bytes so a dict-compressed section yields
             the same content_hash as raw.
compression: Central to "compress more than everyone." nest already vendors zstd but uses its weakest config:
             level-19, no dictionary, no LDM, each small section compressed cold. Trained
             dictionaries are the single highest-leverage zstd feature for nest's
             many-small-similar-records workload and can sharply cut the non-embedding footprint
             at tiny corpus sizes; LDM extends the same engine to whole-repo/whole-database
             payloads. FSE/tANS and the repeat-offset trick are reference designs for any future
             nest-native entropy coder over postings or quantized residuals.
perf:        Reference C: ~510 MB/s compress, ~1550 MB/s decompress at level -1; decode speed is roughly
             level-independent (entropy-bound, not match-bound). The 4-stream Huffman split
             exists purely to exploit superscalar ILP. FSE/tANS decode is a tight table-lookup
             loop (1 lookup + bit-refill per symbol), branch-light and cache-friendly with a
             power-of-2 table. Dictionary decode adds a one-time window prefill, no steady-state
             cost. None runs on nest's hot path (embeddings never zstd-compressed), so all zstd
             cost is amortized one-time at build/cold-section decode.
