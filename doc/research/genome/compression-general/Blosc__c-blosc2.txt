what:        A meta-compressor that does not invent an entropy coder but front-loads a SIMD-vectorized,
             pipelinable byte-transform stage (shuffle / bitshuffle / delta / bytedelta /
             trunc_prec) ahead of stock LZ codecs (BloscLZ, LZ4, Zstd), restructuring numerical
             byte streams so the downstream coder sees long runs and small residuals, all
             wrapped in a documented blocked chunk/superchunk/frame container.
innovation:  Decouple "byte rearrangement / decorrelation" from "entropy coding" and make the transform stage
             a tiny, composable, SIMD-accelerated filter pipeline applied per fixed-size block.
             The shuffle filter groups the Nth byte of every typesize-N element together (a
             strided transpose), so the high-order bytes of a numerical array (mostly constant)
             form long zero/constant runs and the low-order bytes cluster, turning data Zstd can
             barely touch into data it crushes. bytedelta then deltas within each per-byte
             stream for gradually-varying series. The codec is unchanged; the win comes entirely
             from presenting it better-conditioned bytes. This routinely lifts float32 array
             ratios from ~3.9x to ~5.9x at near-memcpy speed.
techniques:
  - Byte shuffle: strided transpose grouping byte-position k of all elements of typesize T into
    contiguous planes (SoA-of-bytes), exposing constant high-order bytes as runs
  - Bitshuffle: same idea at bit granularity, transposing bit-planes within a block for more
    redundancy on low-entropy floats
  - bytedelta filter: SIMD delta within each shuffled byte-plane; forward uses
    simd_sub+simd_concat over 16-byte lanes, inverse uses a Kogge-Stone parallel prefix-sum scan
    to un-delta
  - trunc_prec: zero the low mantissa bits of f32/f64 before shuffle to manufacture
    trailing-zero runs (lossy, controllable precision)
  - Composable 6-slot block-level filter pipeline (shuffle->bytedelta, trunc_prec->bitshuffle)
    keeping temp buffers L1/L2-resident
  - Blocked chunk format with int32 bstarts offset table + csize sentinels (csize==0 = all-zeros
    block stored as nothing, csize<0 = RLE/special token)
  - Shared Zstd dictionary trained once and stored in the superchunk header, reused across all
    chunks to lift ratio on small blocks
  - Container hierarchy chunk->superchunk->frame (contiguous cframe header+chunks+index+trailer,
    or sparse sframe one-file-per-chunk) with MessagePack metadata + metalayers
nest steals: Add a pre-codec filter stage in nest-format/src/encoding/ (new shuffle.rs + bytedelta.rs, each
             <300 loc, pure deterministic functions, no panic). Wire it as a new
             SECTION_ENCODING id (the reserved 4-255 space is additive-safe within v1) that is
             shuffle+zstd: before zstd_encode, transpose section bytes by a typesize stored in
             the manifest, optionally bytedelta the planes, then zstd; reverse it in
             decode_payload. Highest-value targets are the COLD numerical sections that already
             accept zstd: chunks_original_spans (arrays of u32/u64 offsets whose high bytes are
             near-constant, so shuffle yields huge runs) and the int8 scales array in
             encoding/int8.rs (n contiguous f32 LE scales, the classic shuffle case). CRITICAL
             constraint: do NOT apply it to the embeddings body bytes scored from mmap on the
             hot path (shuffle destroys the row-contiguous layout the SIMD dot-product reads),
             so gate it strictly to non-hot-path sections via writer/encoding_choice.rs.
             trunc_prec is a separate future lever for a lossy archival embeddings variant. The
             SIMD prefix-sum un-delta maps onto nest-runtime's existing AVX2/NEON/scalar
             dispatcher if decode ever becomes hot.
compression: Directly central. This is the cheapest known multiplier on top of an existing entropy coder for
             numerical/binary sections: nest already ships zstd but applies it to raw bytes;
             inserting a deterministic byte-shuffle (and optional bytedelta) transform in front
             of zstd is a pure ratio win on the offsets/spans and scale arrays with zero new
             dependency and no format break (just a new additive encoding id). Blosc's own ERA5
             numbers (3.86x -> 5.86x) quantify the headroom. It is the textbook technique behind
             'compress data more than everyone' for structured numeric payloads.
perf:        Shuffle/bitshuffle and bytedelta are SIMD-vectorized (SSE2/AVX2 on x86_64, NEON on aarch64,
             scalar fallback) over 16-byte lanes, so transform overhead is near memcpy and
             bandwidth-bound. Block-level application keeps working sets in L1/L2. Tradeoffs
             measured by Blosc: with shuffle+bytedelta, Zstd compression time can roughly double
             at high levels and decompression can slow ~20% for most codecs (Zstd less affected)
             - acceptable since nest's targets are build-time (python writer) and cold sections,
             not the mmap scoring path. The all-zeros/RLE csize sentinels make sparse numeric
             data near-free.
