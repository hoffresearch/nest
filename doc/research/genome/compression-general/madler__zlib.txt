what:        The canonical C reference implementation of DEFLATE (RFC 1951) and its zlib/gzip wrappers: LZ77
             sliding-window matching via hash chains plus per-block dynamic Huffman entropy
             coding, with a table-driven multi-level inflate decoder.
innovation:  The two-stage table-driven Huffman decoder optimizing the common (short-code) case.
techniques:
  - LZ77 sliding window (32KB) with backward (length,distance) references
  - hash-chain match finder: head[HASH_SIZE] + prev[w_size] linked chains, capped by
    max_chain_length
  - lazy matching (Wams): defer a literal to check if a longer match starts at the next position
    (levels >=4)
  - tunable heuristics good_match/nice_match/max_lazy_match/max_insert_length to trade ratio vs
    speed per level
  - canonical Huffman: per-block dynamic trees (dyn_ltree, dyn_dtree) built from symbol
    frequencies via a heap, code lengths transmitted compactly via bl_tree
  - block-type selection: stored vs fixed-Huffman vs dynamic-Huffman, picking the cheapest per
    block
  - multi-level inflate decode tables: root table covers root_bits, sub-tables handle overflow
    codes (1-15 bits)
  - deflateSetDictionary: prime the window with a known dictionary so the first bytes can
    back-reference it (great for many small similar payloads)
nest steals: Two concrete steals. (1) The preset-dictionary idea (deflateSetDictionary) maps directly onto
             nest-format's encoding layer (crates/nest-format/src/encoding + sections): nest
             already zstd-compresses non-embedding sections, and chunks_canonical/provenance
             across a corpus share huge vocabulary overlap. Train one shared zstd dictionary
             (zstd has native zstd_compress_usingDict / trained dictionaries) over the corpus,
             store it once as a small additive sub-blob keyed under the existing zstd encoding
             id, and compress every text/json chunk against it. This is the single biggest win
             for nest's "compress more than everyone" north star on many-small-chunk corpora,
             and stays additive (no NEST_FORMAT_VERSION bump, deterministic if the dictionary is
             built deterministically). (2) The two-stage canonical-Huffman decode table is the
             reference design for any future bespoke entropy codec nest adds for a section type
             (e.g. a custom int8/residual codec): implement it in nest-runtime as a small
             repr-aligned decode table read straight from the mmap, keeping the no-panic,
             little-endian, <=300-loc-per-file constraints. The LZ77 hash-chain + lazy-match
             design is reference-level only (zstd already supersedes it for nest's actual
             codec).
compression: High for text/json sections: shared preset dictionaries are the proven lever for compressing
             many small, vocabulary-overlapping payloads (exactly nest's chunks_canonical +
             provenance), directly serving the "compress data more than everyone" goal.
             Irrelevant to embeddings, which nest deliberately never entropy-codes because they
             are SIMD-scored off mmap on the hot path. The table-driven decode is relevant only
             if nest builds its own entropy codec rather than leaning on zstd.
perf:        Decode hot loop is a bit-buffer + single table lookup for common codes, one extra indirection
             for rare long codes; root_bits sized "one bit above average code length" to
             minimize duplicate-entry fill cost. Encode speed is dominated by hash-chain walk
             length (max_chain_length) and lazy-match second searches; levels 1-3 skip lazy
             matching and limit hash insertions for speed. zlib-ng is the modern SIMD/perf fork
             (SIMD hash, faster CRC, slide) if kernel-level speed matters. CRC32 has a
             well-known slice-by-8/PCLMULQDQ vectorization but base zlib is largely scalar
             table-driven.
license:     zlib license (permissive, BSD-like, commercial-friendly, no attribution-in-binary requirement)
             -- vendor-safe for nest.
