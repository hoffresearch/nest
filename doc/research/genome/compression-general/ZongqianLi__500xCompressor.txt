ZongqianLi/500xCompressor
category: compression-general   |   steal priority: REFERENCE

siblings: ./00-index.txt   |   map: ../../README.txt

what:        An autoencoder-style neural prompt compressor that uses a frozen LLaMA-3-8B (with ~0.3%
             trainable LoRA params) as the encoder to squeeze up to ~500 natural-language tokens
             into the per-layer KV-cache values of a single learned special token, which the
             same frozen LLM then decodes for text regeneration or QA.
innovation:  Carry compressed information as the full per-layer key/value (KV) tensors of a handful of
             learned "gist" tokens rather than as a single final-layer embedding vector.
             KV-at-every-layer has far higher information capacity than one embedding, which is
             what unlocks the 6x-480x ratios; the decoder is the identical frozen LLM, so the
             compressor adds no decode-side parameters and "stores" nothing in weights (no data
             leakage).
techniques:
  - Autoencoder framing: encoder = frozen LLM + LoRA, decoder = same frozen LLM, only LoRA
    (~0.3%) trained
  - Soft/gist tokens: append N learnable special tokens; their attention-aggregated state
    becomes the compressed payload
  - KV-value carrier instead of last-layer embedding (the ICAE improvement) -- store K and V per
    transformer layer for each gist token
  - Two-phase training: (1) pretrain on text regeneration with teacher forcing + cross-entropy,
    (2) fine-tune on extractive QA
  - Non-selective compression: compresses ALL prompt tokens into the latent, vs hard methods
    (LLMLingua) that drop tokens
  - Lossy reconstruction measured by F1/EM, retaining ~62-84% of uncompressed-prompt task
    ability
nest steals: Mostly a REFERENCE, not a steal. This is lossy neural compression needing an 8B LLM forward pass
             at both compress AND decompress time -- it cannot live on nest's mmap+SIMD hot
             path, breaks determinism (float GPU kernels), breaks
             offline/single-file/small-rust-core constraints, and cannot losslessly reconstruct
             bytes, so it is unusable for chunks_canonical, provenance, or any required section.
             The ONLY transferable seed: the KV-as-carrier insight reinforces nest's existing
             embedding-quantization direction in nest-format encoding (the int8/float16 codecs)
             -- it argues a richer per-layer latent preserves more than a flattened vector,
             useful as academic background for any future learned/product-quantization codec but
             nothing nest can ship now. nest should cite 500xCompressor as the canonical reason
             neural/semantic text compression costs an LLM at read time and therefore stays OUT
             of the frozen v1 format and off the offline runtime. No code, section, or codec
             adopted.
compression: Low for nest's mission. Headline "500x" is lossy latent compression of prompts for LLM
             consumption, not lossless byte compression of stored data, and the decompressor is
             an 8B GPU model -- the opposite of nest's
             offline/single-file/deterministic/mmap-SIMD design. It compresses for an LLM to
             read, not for a byte-exact citation to reopen, so it cannot back content_hash
             stability or nest://content_hash/chunk_id span reopen. Useful only as the reference
             point for why neural/semantic text compression is incompatible with nest's frozen
             container and offline runtime.
perf:        Reported at 500x: ~27-90% reduction in attention FLOPs and ~55-83% KV-memory savings when
             generating 100-400 tokens, retaining ~70-74% F1 / ~77-84% EM vs uncompressed
             prompts. Base model LLaMA-3-8B-Instruct; LoRA adds ~0.3% params. All numbers assume
             GPU LLM inference at both ends -- irrelevant to nest's CPU mmap/SIMD throughput
             model and not a fixed-cost codec.
