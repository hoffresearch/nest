what:        A pure-Go suite of optimized compression codecs (zstd, S2/Snappy, flate/deflate) built on
             separable entropy primitives - huff0 (Huffman) and fse (Finite State Entropy /
             tANS) - with dictionary training, four match-finder tiers, and assembly-accelerated
             decode.
innovation:  Entropy coding and dictionary training are factored into reusable primitives independent of the
             LZ layer: fse (table-based asymmetric numeral systems) and huff0 (Huffman) are
             standalone packages, and a trained dictionary ships a precomputed shared entropy
             table plus a common-substring content prefix so a corpus of many tiny similar
             payloads stops re-transmitting its own statistics and re-discovering shared strings
             on every blob - exactly the regime of nest's thousands of short canonical chunks.
techniques:
  - FSE / tANS finite-state entropy coding (table-driven ANS) as a standalone codec for
    near-arithmetic-coding density at table-lookup speed
  - huff0 Huffman entropy coder with 1X and 4X interleaved-stream variants for parallel/SIMD
    decode
  - zstd dictionary training (ZDICT): mine common substrings across many small samples +
    precompute a shared FSE/Huffman entropy table, embed both as a reusable dictionary prefix
  - four-tier match finder (fast/default/better/best ~ levels 1/3/7/11) trading encode time for
    ratio via hash-chain variants
  - S2 seekable streams: a sparse index of frame offsets enabling random access /
    decompress-from-offset without inflating the whole stream
  - RLE detection and predefined/static FSE tables to skip header cost on tiny or low-entropy
    blocks
  - assembly matchLen and a 4-stage decoder pipeline (input / literal / sequence / output) for
    decode throughput
nest steals: Add a trained-dictionary codec to crates/nest-format/src/encoding/ alongside zstd_codec.rs. At
             build time (nest-python build_fn -> writer/encoding_choice.rs) train ONE zstd
             dictionary from the file's own canonical chunks, store it as a new additive section
             (reserved id 0x09+, NOT a v2 bump) plus a new SECTION_ENCODING id in the reserved
             4-255 range, then compress chunks_canonical (and spans/provenance) against it. For
             nest's many short PT-BR chunks this removes the per-section entropy-table and
             shared-substring overhead that zstd level-19-without-dict pays today, advancing the
             'compress more than everyone' north star while staying single-file (dict lives
             inside the container), deterministic (training is seedable + sorted input), and
             additive. Second steal: S2's seekable sparse-offset index is the blueprint for a
             future chunk-granular random-access codec so a single chunk decodes without
             inflating the whole section. Decode stays on the existing zstd crate (it reads
             dict-prefixed frames natively) so no new decode dependency; embeddings remain
             untouched on the mmap SIMD hot path per nest's hard rule.
compression: Directly central. Dictionary training is the single biggest unrealized ratio win for nest's
             actual payload shape (thousands of short, mutually-similar text chunks) where
             whole-section zstd-19 wastes bytes re-encoding shared statistics per blob;
             fse/huff0 as separable primitives are the longer-term path to a custom nest entropy
             stage.
perf:        zstd decode has x86-64 + ARM64 assembly (~2x); decoder runs a 4-stage concurrent pipeline,
             encoder uses light 2-goroutine concurrency. huff0 4X variant interleaves 4
             bitstreams for parallel decode; static decode buffer ~30% faster. matchLen and FSE
             decode are hand-written asm on amd64. For nest these are build-side one-time costs;
             decode and dict-prefix reads are cheap and stay off the SIMD scoring hot path since
             embeddings are never entropy-coded.
