what:        A speed-first LZ77 byte compressor that emits a stream of tag-byte-prefixed elements (literals +
             back-reference "copies") with no entropy coding, hitting ~250 MB/s compress / ~500
             MB/s decompress at ~1.5-4x ratio, plus a chunked framing format with per-chunk
             masked CRC-32C for streaming.
innovation:  The transferable idea is the tag-byte element stream: every element begins with one byte whose
             low 2 bits select element type (00 literal, 01/10/11 copy with 1/2/4-byte offset)
             and whose high 6 bits pack the small-case length/offset inline, so the common case
             costs exactly one control byte with zero entropy-coding state. This makes the
             format branch-cheap, alignment-tolerant (LE unaligned loads), and table-free to
             decode - the opposite of zstd/FSE which need decode state. Paired with it: a
             base-128 varint preamble (7 data bits + continuation bit) for total length, and an
             independent chunked framing layer (4-byte header = 1 type byte + 3-byte LE length)
             where each chunk carries a masked CRC-32C of its UNCOMPRESSED bytes so streams are
             splittable, concatenable, and verifiable per-chunk.
techniques:
  - tag-byte element encoding: low 2 bits = type {literal, copy1B, copy2B, copy4B}, high 6 bits
    = inline length/offset for the common small case
  - three copy classes by offset width: 1-byte offset (0-2047, len 4-11, 3 high offset bits in
    tag), 2-byte offset (0-65535, len 1-64), 4-byte offset (full 32-bit), trading control-byte
    size against reach
  - literal length escape: high-6-bits 0-59 = (len-1) inline; 60-63 = read 1-4 following LE
    bytes as the length, keeping long literals cheap
  - LE base-128 varint preamble for total uncompressed length (7 payload bits + MSB
    continuation)
  - single-probe hash table of 4-byte fragments for match finding (no lazy match, no entropy
    coder) - source of the speed/ratio tradeoff
  - framing: back-to-back chunks, 4-byte header (1 type byte + 3-byte LE length), ids
    partitioned into reserved-skippable (0x80-0xfd) vs reserved-unskippable (0x02-0x7f) for
    forward-compatible extension
  - masked CRC-32C per chunk over UNCOMPRESSED data, mask = ((x>>15)|(x<<17)) + 0xa282ead8 to
    avoid CRC-of-CRC weakness
  - format assumes cheap unaligned LE 32/64-bit loads, enabling overlapping copies and
    word-at-a-time literal moves
nest steals: Two adaptations, both in nest-format. (1) Adopt Snappy's reserved-id partitioning for nest's
             section/encoding id space: Snappy splits skippable vs unskippable extension ranges
             so old decoders behave predictably on unknown chunks. nest v1 is additive-only with
             section ids 0x09+ and encoding ids 4-255 RESERVED; formalize a "skippable optional
             vs unskippable required" bit on section entries in crates/nest-format/src/layout
             and reader so a future v1 file with an unknown OPTIONAL section (e.g. a new graph
             index) still validates and serves on an older runtime, while unknown REQUIRED
             sections error cleanly via NestError - extending the additive guarantee without a
             v2 bump. (2) Use Snappy's tag-byte stream as the blueprint for a pure-Rust,
             panic-free, deterministic LZ77 fallback codec in crates/nest-format/src/encoding
             (new module behind a reserved SECTION_ENCODING id, never applied to embeddings) for
             when nest must drop the zstd C dependency to stay fully sovereign/offline in one
             binary. Import only the stream layout (varint preamble + 1/2/4-byte copy classes),
             not Snappy's CRC, since nest's four SHA-256 surfaces already cover integrity. The
             same varint+tag scheme is directly reusable to shrink small metadata sections
             (chunk_ids, chunks_original_spans) where deltas are tiny and zstd's container
             overhead dominates.
compression: Indirect, not on the hot ratio path. nest already uses zstd level 19, which compresses TEXT
             meaningfully better than Snappy (Snappy explicitly trades 20-100% larger output for
             ~10x speed and applies no entropy coding), so Snappy's codec must NOT replace zstd
             for the headline "compress more than everyone" goal. Its relevance is structural:
             (a) a sovereign zero-C-dependency fallback codec when nest vendors everything into
             one binary; (b) the tag-byte/varint scheme as low-overhead encoding for small
             metadata sections where zstd container overhead dominates; (c) the
             skippable/unskippable extension discipline that protects the additive-format
             guarantee as the format grows toward repos/audio/video.
perf:        ~250 MB/s compress, ~500 MB/s decompress single-core 64-bit x86; ratios ~1.5-1.7x plain text,
             2-4x HTML, ~1.0x already-compressed (jpeg/png). Speed comes from word-at-a-time
             unaligned LE loads, overlapping copy loops, and single-probe hash-table match
             finding (no lazy matching, no entropy coder). Format assumes cheap unaligned
             32/64-bit LE loads - already true on nest's x86_64+aarch64 targets and aligned with
             nest's repr(C) little-endian-unsigned convention. Decompression is allocation-light
             and streamable, matching nest's mmap model.
