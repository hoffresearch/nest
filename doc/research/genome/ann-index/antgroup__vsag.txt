what:        VSAG is Ant Group's production C++ graph-ANN framework (HNSW/HGraph/IVF/SINDI) whose standout
             component is RaBitQ binary quantization, a randomized 1-bit-per-dimension codec
             with a provably unbiased distance estimator and a popcount-based SIMD hot path.
innovation:  RaBitQ: quantize each L2-normalized, centroid-centered, randomly-rotated vector to its sign bits
             (1 bit/dimension), then estimate the true inner product with an UNBIASED estimator
             (error O(1/sqrt(D)), asymptotically optimal) using only bitwise AND + popcount
             instead of float math or PQ lookup tables. The query is split into Bq bit-planes
             (default 4) so the dot product becomes a weighted popcount sum: result =
             1*popcount(code&q1) + 2*popcount(code&q2) + 4*popcount(code&q3) +
             8*popcount(code&q4). Unlike PQ it needs zero training/codebook learning and has a
             real theoretical error bound, which is exactly the guarantee a deterministic,
             sovereign database needs.
techniques:
  - RaBitQ 1-bit binary quantization: random orthogonal rotation (Johnson-Lindenstrauss) then
    sign extraction -> D-bit code per vector
  - Unbiased distance estimator <o_bar,q>/<o_bar,o> with per-vector precomputed factor <o_bar,o>
    + per-vector norm + dataset centroid stored as f32 side metadata
  - Popcount bit-product distance: AND + popcount over bit-planes weighted by 2^j
    (AVX512VPOPCNTDQ / NEON CNT, 1-cycle ops, ~3x faster than PQ LUT)
  - Bq-bit query decomposition (default 4 bit-planes) trading accuracy vs speed without
    re-encoding the database
  - Extended/multi-bit RaBitQ: binary MSB code first for coarse estimate, ex-code refines
    incrementally; 4/5/7 bits -> 90/95/99% recall
  - FastScan SIMD layout: transposed bit-plane packing for batched quantizer scans
  - SQ4/SQ8 scalar quantization and fp16/bf16 SIMD operators as a tiered quantizer ladder
  - Automatic build-parameter generation from vector dimension and dataset scale
nest steals: Add a new additive encoding id (reserve id=4 in the 4-255 range) `rabitq` in
             nest-format/src/encoding/rabitq.rs, mirroring the existing int8.rs layout:
             versioned u32 prefix, then per-vector side data (f32 norm + f32 <o_bar,o> factor +
             one shared f32 centroid block + the seeded rotation), then packed D-bit sign codes
             row-major. Because nest mandates an exact-cosine rerank in nest-runtime/src/search,
             RaBitQ only ranks the candidate SET; the returned score stays real cosine, so
             RaBitQ's ANN-proxy nature never violates the search contract. Add a
             dot_rabitq_popcount kernel to nest-runtime/src/simd (avx2.rs popcount/LUT, neon.rs
             vcnt, scalar.rs u64::count_ones) dispatched from simd/mod.rs alongside dot_f32_i8.
             Determinism is preserved by seeding the rotation from the model fingerprint (same
             chunks + model => byte-identical rotation => byte-identical codes), matching nest's
             reproducible-build and deterministic-hnsw rules. Wire into
             writer/encoding_choice.rs and a new bq/micro preset.
compression: Directly serves the north star: RaBitQ is 1 bit/dimension = 32x smaller than f32 and 8x smaller
             than nest's current int8 embeddings, the single largest section in any vector
             container. It is the most aggressive embedding compression with a real error bound
             (not heuristic), so it can push nest's tiny preset below its current 0.283 size
             ratio while nest's mandatory exact rerank keeps recall@10 near-lossless. Clearest
             path to compress embeddings more than everyone without sacrificing
             deterministic/sovereign/single-file guarantees.
perf:        RaBitQ distance estimation reduces to AND+popcount, ~1 cycle on Intel IceLake+/AMD Zen4+ via
             AVX512VPOPCNTDQ (NEON CNT on aarch64), benchmarks ~3x faster than PQ RAM table
             lookups at equal accuracy. Codes are D bits (vs PQ 2D default) so smaller AND
             faster. No training pass so encode time is comparable to scalar quantization.
             Popcount kernel is mmap-friendly: codes are dense contiguous bytes scored straight
             off disk like nest's current i8 hot path. Side metadata is tiny (few f32/vector +
             one shared centroid + deterministic rotation).
