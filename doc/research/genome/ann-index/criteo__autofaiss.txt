what:        A Python wrapper over FAISS that auto-selects and tunes a KNN index (the faiss factory string +
             nlist + PQ subquantizers + nprobe/efSearch) from nb_vectors, dimension, a strict
             memory budget, and a query-latency target, via threshold heuristics plus binary
             search against measured recall.
innovation:  A closed-form memory/compression cost model for Product Quantization (each vector costs pq + 8
             bytes; compression ratio = 4*dim / (pq+8)) that lets you invert a target memory
             budget into a quantization scheme deterministically, then a learned OPQ rotation
             that decorrelates dimensions before PQ so the same byte budget buys higher recall.
             The compression target drives codec choice, not the other way around.
techniques:
  - Product Quantization (PQ): split D-dim vector into m subvectors, each coded to one of 256
    (8-bit) centroids learned by k-means; vector stored as m bytes; distance via asymmetric
    distance computation (ADC) over precomputed lookup tables
  - OPQ: a learned orthonormal rotation matrix applied before PQ (factory 'OPQ{m}_{y}',
    y=(min(dim//pq,6)+1)*pq) that minimizes quantization distortion by aligning subspaces to the
    PQ grid
  - PQ-budget inversion: choose m from pq_values=[256,128,64,48,32,24,16,8,4] such that
    (4*dim)/(pq+8) >= target_compression_ratio = 4*N*dim / max_memory_bytes
  - nlist heuristic: nb_clusters = 4*sqrt(N) rounded to nearest power of 2 (<1M); fixed ladders
    for larger N; switch to IVF{nlist}_HNSW32 coarse quantizer when nlist>=1000
  - k-means train-size heuristic: ~100 points/cluster (floor 31, range 30*nlist..256*nlist),
    2^code_size*1000 for PQ codebooks
  - Two-phase greedy tuning: binary_search_on_param over nprobe/efSearch to find min param
    hitting 99% neighbor coverage, then maximize recall under a max_speed_ms wall-clock bound
  - Index-type decision tree by data scale: flat brute force <1000 vectors, no quantization
    <10000, IVF-Flat <1M, IVF-PQ/OPQ above, gated by a should_be_memory_mappable flag
  - Memory-mappable IVF index path: index built and served from disk via mmap with optional
    direct-map for reconstruction (~8 bytes/vec id overhead)
nest steals: Two concrete steals. (1) Add a PQ/OPQ embedding codec to nest-format encoding.rs as a new
             RESERVED encoding id (additive within v1): store per-vector m-byte codes plus a
             small codebook (new section 0x09+ or folded into search_contract). This is nest's
             path past int8's hard 4x ceiling toward 16-100x embedding compression (m=32 on a
             768-dim f32 vector is ~96x). It does NOT break nest's 'score f32 from mmap on the
             hot path' rule because nest already runs a MANDATORY exact-cosine rerank: use PQ
             ADC tables in nest-runtime as the cheap ANN candidate generator (alongside hnsw),
             then rerank top-k against full-precision vectors so the returned score stays real
             cosine. PQ codes are mmap-friendly: ADC is a gather over a small in-cache codebook.
             (2) Port the budget->codec inversion and nlist=4*sqrt(N) power-of-2 heuristic into
             nest-python's builder so the user passes a target .nest size or recall floor and
             the builder deterministically solves codec+params, replacing the fixed
             exact/compressed/tiny/hybrid presets. The binary-search nprobe/efSearch tuner
             adapts directly to deterministic HNSW efSearch selection feeding search_contract.
             Keep determinism by seeding PQ/OPQ k-means and emitting codebooks in fixed order so
             same chunks+model => byte-identical file.
compression: Directly central. PQ+OPQ is the single highest-leverage embedding compression technique nest
             lacks: it breaks the int8 4x ceiling and reaches 16-100x on the embeddings section,
             which is usually the largest part of a .nest file. nest's mandatory exact rerank in
             search_contract is exactly what makes lossy PQ safe (returned score stays real
             cosine), so this slots into the design instead of fighting it. The budget-driven
             codec inversion turns 'compress more than everyone' into a solvable optimization
             instead of fixed presets.
perf:        PQ ADC computes a distance by summing m table lookups (one per subquantizer) from a 256*m
             precomputed query-distance table that fits in L1/L2; a gather+accumulate that is
             SIMD-friendly (faiss PQ4 fast-scan packs 32 codes and uses shuffle-based lookups).
             Per-vector storage is exactly m bytes (+8 byte id) vs 4*dim for f32. OPQ adds a
             one-time D*D matmul per query (negligible). Build cost is the tradeoff: k-means
             over training subvectors (~100 points/cluster) plus optional Spark distribution for
             >RAM data; autofaiss reports a 10GB index from a 1TB/200M-image corpus at 10ms
             query in ~3h.
