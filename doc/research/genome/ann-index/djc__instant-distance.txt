what:        A pure-Rust HNSW (Hierarchical Navigable Small Worlds, Malkov-Yashunin) approximate nearest
             neighbor index with fixed-arity neighbor arrays, generational visited tracking, the
             Malkov-Yashunin diversity pruning heuristic, and an optional serde serialization of
             the whole graph.
innovation:  Represent every HNSW node as a flat, fixed-size array of u32 PointIds (UpperNode([PointId; M])
             on upper layers, ZeroNode([PointId; M*2]) on layer zero) so the entire graph is a
             contiguous Vec of plain integer records with no per-node pointers or heap
             allocations -- a layout that serializes trivially and could be mmap'd zero-copy,
             while the M*2-vs-M layer split bounds the on-disk graph size to a known constant
             per point.
techniques:
  - Fixed-arity neighbor records: UpperNode([PointId; M]) with M=32, ZeroNode([PointId; M*2])
    with M*2=64, PointId = u32 newtype, INVALID = u32::MAX sentinel padding unused slots
  - Two-tier storage: Hnsw { ef_search, points: Vec<P>, zero: Vec<ZeroNode>, layers:
    Vec<Vec<UpperNode>> } -- separates the dense base graph from sparse upper layers
  - Generational Visited set: struct Visited { store: Vec<u8>, generation: u8 } gives O(1) reset
    by bumping the generation counter instead of clearing the buffer between searches
  - Malkov-Yashunin diversity/select_heuristic pruning: drops a candidate when it is closer to
    an already-selected neighbor than to the query, with optional keep_pruned, to bridge
    clusters and raise recall at fixed degree
  - Deterministic level assignment: SmallRng::seed_from_u64(seed) with ml = 1/ln(M) controls the
    exponential layer distribution -> byte-reproducible graph from same seed+points
  - Layer-aware descent: ef=1 / num=M on upper layers, ef=ef_search / num=M*2 on layer zero;
    greedy descent then ef-bounded beam search on the base layer
  - Candidate { distance: OrderedFloat<f32>, pid: PointId } heap entries; ordered-float for
    total ordering of f32 distances without NaN UB
  - serde + serde-big-array derive serializes the full graph (points + zero + layers) as one
    blob; MIT OR Apache-2.0 licensed
nest steals: nest-format already reserves section 0x07 for hnsw_index; instant-distance's flat fixed-arity
             layout is the exact on-disk encoding nest should adopt. Store ZeroNode as a packed
             [u32; M*2] and UpperNode as [u32; M] arrays, all little-endian repr(C), so the
             graph section is a pure POD byte block that nest-runtime mmaps and walks with zero
             deserialization (no serde, no allocation), matching the offline/mmap hot-path
             constraint. The M-vs-M*2 split and u32::MAX padding give a constant, predictable
             section size that compresses well under zstd (the index section is NOT on the SIMD
             scoring hot path, so unlike embeddings it CAN be zstd-encoded, helping the
             tiny/hybrid presets shrink further). Port the deterministic SmallRng::seed_from_u64
             + ml=1/ln(M) level assignment into nest-runtime::ann::HnswIndex to satisfy nest's
             seeded-determinism rule, and adopt the generational Visited { Vec<u8>, generation }
             pattern to avoid per-query allocation. The select_heuristic diversity pruning is
             what lets nest's tiny preset hit recall@10 0.992 at low degree; keep it. Crucially,
             nest's mandatory exact-cosine rerank means the graph only needs to be a good
             candidate generator, so nest can push M lower than 32 (smaller index, more
             compression) and lean on rerank to recover precision -- a direct lever for
             'compress more than everyone' without losing the real-cosine guarantee. Split
             across files to respect the <=300 line cap: types (node structs), build (seeded
             insert), search (descent + visited), and an encode/decode codec in nest-format.
compression: High and direct: the fixed-arity [u32; M] / [u32; M*2] node layout is a POD byte block with
             constant per-point size that zstd-compresses well and mmaps zero-copy; lowering M
             (safe because nest always exact-reranks) directly shrinks the 0x07 index section,
             improving the tiny preset's 0.283 size ratio without harming recall.
perf:        No SIMD distance kernel exists (open issue #20 requests generalizing SIMD to n-length vectors);
             distance is user-supplied via the Point trait, so nest's existing AVX2/NEON
             dot-product dispatcher is strictly ahead and should NOT be replaced by anything
             here. Performance wins come from the cache-friendly flat Vec<ZeroNode> layout
             (sequential u32 reads, no pointer chasing), bounds-check elision over fixed arrays,
             generational visited (no clear cost), and rayon-parallel construction. Build is
             parallel (rayon + parking_lot RwLock on zero layer during insert); query is
             single-threaded beam search. ordered-float avoids NaN ordering hazards.
