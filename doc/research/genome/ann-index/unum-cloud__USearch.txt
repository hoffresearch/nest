what:        A single-C++11-header HNSW vector-search engine whose proximity graph and quantized vectors are
             packed into a contiguous, memory-mappable byte tape so an index is served zero-copy
             directly from disk, using compact uint40_t node IDs and transparent f16/i8/b1
             downcasting.
innovation:  Treat the entire HNSW index as a flat contiguous on-disk byte tape (per-node: level header +
             per-level neighbor lists + inline vector, laid out so absolute node offsets are
             computable from precomputed constants) plus uint40_t neighbor references, so the
             graph is served zero-copy via mmap with no in-RAM deserialization and minimal
             per-edge overhead.
techniques:
  - uint40_t: 5-byte little-endian node IDs in neighbor lists (37.5% smaller than u64, addresses
    up to 1T nodes) - cuts the dominant cost of an HNSW graph, the edge arrays
  - Contiguous node tape: each node = {level, per-level neighbor count + neighbor IDs, inline
    vector} packed back-to-back; precomputed_constants_t (neighbors_bytes, neighbors_base_bytes)
    make node offsets computable for zero-copy view()
  - Minimalist serialized header: 5x u64 only (size, connectivity, connectivity_base, max_level,
    entry_slot); metric/scalar/key types kept in a separate dense head, so graph blob format is
    stable across metrics
  - i8 quantization recipe: L2-normalize to unit length, scale to [-127,127], store int8, score
    in int8 with upcast accumulate; valid only for cosine/IP - 4x smaller than f32 at ~95%
    recall
  - b1x8 binary quantization: 1-bit-per-dim sign packing into bytes, scored via
    Hamming/Jaccard/Tanimoto/Sorensen popcount - 32x smaller than f32 for candidate generation
  - Transparent up/down-casting: same add/search path auto-converts f64/f32/bf16/f16/i8 so
    storage precision and compute precision are decoupled
  - AVX-512 / Arm SVE masked loads (SimSIMD/NumKong) to eliminate scalar tail loops in distance
    kernels; Horner's method for vectorized polynomial approximations
nest steals: nest-format: redesign the hnsw_index (0x07) section to mirror USearch's flat tape - a 5-field LE
             u64 header (node_count, connectivity_M, connectivity_base, max_level, entry_slot)
             followed by a contiguous node region where each node is {u8 level, then per-level:
             u16 neighbor_count + neighbor_count x uint40 IDs}. Adopt uint40_t (a repr(C) [u8;5]
             LE) for neighbor IDs - for nest's tiny preset this shrinks the graph payload ~37.5%
             vs u64 and standardizes a compact edge encoding; vectors stay in the separate
             embeddings section (mmap-scored, never zstd'd) so 0x07 and embeddings stay
             decoupled as nest requires. nest-runtime ann::HnswIndex computes node offsets from
             precomputed constants and reads neighbor IDs straight off the mmap with zero
             deserialization (matches the score-off-disk hot path). The i8
             unit-norm-then-[-127,127] recipe is the exact spec for nest's int8 embedding
             encoding; add b1x8 sign-bit packing as a future candidate-generation encoding (32x
             smaller) feeding the mandatory exact-cosine rerank nest already runs, so binary
             codes never affect the returned score. USearch's header carries no RNG state, so
             nest's seeded build + alphabetical term order stays the source of truth. All
             additive (0x07 internals + new encoding id within reserved 4-255), no
             NEST_FORMAT_VERSION bump.
compression: High. (1) uint40 neighbor IDs make the HNSW graph itself ~37.5% smaller than naive u64 edges,
             and the graph is often the second-largest section after embeddings. (2) b1x8 binary
             codes (32x) and the i8 unit-norm recipe (4x) give a tiered storage ladder where
             1-bit/8-bit codes drive ANN candidate generation while the mandatory exact rerank
             preserves real cosine - smaller indexes without lying about scores.
perf:        Claims ~10x faster HNSW than FAISS and ~20x over IndexFlatL2 brute force via SimSIMD/NumKong
             kernels using AVX-512 and Arm SVE masked loads (no scalar tail loop) - relevant to
             nest's AVX2/NEON/scalar dispatcher. i8 cuts 1536-d OpenAI vectors 75% at ~95%
             recall; in a 100M x 128-d case f32(50GB)+graph(25GB) drops to 19GB with i8.
             view()/mmap serves billion-scale indexes from disk with near-zero RAM, the same
             zero-copy posture nest targets.
