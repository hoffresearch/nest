what:        FAISS is a C++/Python library of composable ANN indexes and vector codecs (PQ, additive
             quantizers, scalar quantization, IVF, HNSW) whose distinguishing feature is extreme
             lossy compression of vectors into short codes that remain searchable directly via
             SIMD lookup-table kernels, with a built-in two-stage approximate-then-rerank search
             contract.
innovation:  PQ4 FastScan: quantize each vector into M 4-bit product-quantization codes, lay the codes out in
             interleaved 32-vector blocks (bbs=32, 2 sub-quantizers per 32-byte block), quantize
             the per-query distance lookup tables to 8-bit integers, and evaluate distances with
             SIMD byte-shuffle instructions (AVX2 pshufb / NEON vqtbl) accumulating in 16-bit
             lanes -- a 16-entry LUT lives entirely in a vector register and 32 candidate
             distances are computed per pair of shuffles, with no RAM lookups on the hot path.
             Pair this with a mandatory exact rerank of the top k*k_factor candidates to recover
             the accuracy lost to 4-bit quantization. This is the same
             approximate-then-exact-rerank contract nest already enforces, applied to a far more
             aggressive code than int8.
techniques:
  - PQ4 FastScan: 4-bit product quantization codes (16 centroids/subquantizer) packed in
    interleaved 32-vector blocks for register-resident SIMD shuffle lookups
  - 8-bit-quantized lookup tables with formula A*(dist-B), 16-bit non-saturating accumulators,
    even/odd sub-quantizer split to avoid AVX cross-lane ops (SCANN-derived)
  - Additive quantizers: Residual Quantizer (greedy beam-search encoding) and Local Search
    Quantizer (simulated annealing); x = sum of M codebook entries, beat PQ accuracy at 64-128
    bits
  - use_beam_LUT distance decomposition into precomputable norm/cross-product/query tables to
    avoid explicit residual computation during encoding
  - Scalar quantization tiers SQ8/SQ6/SQ4/SQfp16 as a simple per-dimension uniform codec (nest
    has int8/f16, missing 4-bit and 6-bit)
  - OPQ / random-rotation / Hadamard transform (O(d log d)) preprocessing to decorrelate
    dimensions before PQ, raising recall at fixed code size
  - Composable index-factory string grammar (e.g. OPQ16_64,IVF4096,PQ16x4fs,RFlat) describing
    transform + coarse quantizer + encoding + refine as one declarative recipe
  - RFlat/Refine/RefinePanorama two-stage retrieve-then-rerank with early pruning during the
    exact reranking phase
nest steals: Two concrete steals. (1) Add a PQ codec to nest-format encoding (a new RESERVED encoding id in
             4-255, additive-only, no NEST_FORMAT_VERSION bump): store learned codebooks plus
             4-bit codes for the embeddings section. Codebooks are tiny (M*16*subdim f32) and
             codes are ~M*0.5 bytes/vector, beating int8's d bytes/vector by 4-16x -- directly
             serving the north-star goal on the largest section. Determinism is preserved by
             fixing k-means seed and Lloyd iteration count and storing codebooks in the
             manifest, so the build stays reproducible (same chunks + model fingerprint =>
             identical codebooks => byte-identical file). (2) In nest-runtime's simd dispatcher
             add a pq4_fastscan kernel mirroring nest's existing AVX2/NEON/scalar trifurcation:
             interleaved 32-vector block layout + pshufb/vqtbl LUT shuffle to score PQ codes
             straight off mmap, feeding candidates into the EXISTING mandatory exact-cosine
             rerank (nest already does this for hnsw/hybrid), so search_contract semantics are
             unchanged -- returned score stays real cosine, PQ is only a candidate filter. This
             makes a new 'nano' preset feasible (zstd text + pq4 embeddings + hnsw), pushing
             well below the tiny preset's 0.283 ratio while exact rerank holds recall. Keep
             files under 300 loc by splitting codec (nest-format/src/encoding/pq.rs) from kernel
             (nest-runtime/src/simd/pq4.rs).
compression: Directly central. PQ4 takes embeddings (nest's dominant byte cost) from int8's d bytes/vector to
             ~M/2 bytes/vector -- a 4-16x reduction on the section nest deliberately leaves
             uncompressed because it must be SIMD-scored from mmap. FastScan's whole point is
             that the compressed code IS the searchable representation via register-resident
             LUTs, dissolving nest's current tension between compressing embeddings and scoring
             them directly off disk. Additive quantizers (RQ/LSQ) offer an even-higher-accuracy
             code at 64-128 bits for a future tier. This is the single most impactful lever
             toward beating competitors on size while keeping the
             offline/single-file/deterministic guarantees.
perf:        FastScan reaches ~1M QPS without rerank and ~280k QPS with rerank (cited 2x faster than HNSW at
             2.7x less memory since no graph is stored). Critical caveat: the
             4-bit/256-bit-register kernel is AVX2-tuned; ARM NEON needs the
             two-128-bit-registers-bundled-as-256 trick (arXiv:2203.02505, Matsui et al.) to
             match -- relevant since nest targets aarch64 NEON as a first-class path. LUT must
             be quantized to 8-bit because shuffle operates on small ints, and accumulation must
             be 16-bit to avoid overflow. Scalar fallback works but emulates vector registers in
             memory and is very slow, so nest's scalar tier should keep a plain unpacked PQ loop
             rather than emulating the block layout.
