================================================================================================
embeddings-benchmark/mteb
category: data-pipeline   |   steal priority: MEDIUM
================================================================================================

siblings: ./00-index.txt   |   map: ../../README.txt

what:        MTEB is a Python embedding/retrieval evaluation harness that standardizes datasets
             (corpus/queries/relevant_docs/top_ranked), runs chunked top-k similarity search
             over multiple metrics, scores with pytrec_eval (nDCG@k, MRR@k, Recall@k, MAP), and
             persists results as content-addressed per-(model,revision,task) JSON in a tiered
             remote/disk/in-memory cache.
innovation:  A standardized, reproducible retrieval-quality measurement protocol: a fixed task schema
             (corpus, queries, relevant_docs as query_id->corpus_id->relevance, top_ranked
             candidate lists) feeding a chunked exact top-k search that computes
             cosine/dot/euclidean and reports the best, scored by an established trec_eval
             metric set (nDCG@k, MRR@k, Recall@k, capped recall), with results stored under
             deterministic content-keyed paths so an identical (model, revision, task) never
             recomputes.
techniques:
  - RetrievalEvaluator: chunked exact top-k via corpus_chunk_size, sub-batch similarity matmul,
    per-query (corpus_id, score) collected then descending sort, avoiding O(N) memory blowup
  - Multi-metric scoring: compute cosine, dot, and euclidean and report the best; cosine = inner
    product on L2-normalized vectors
  - pytrec_eval (trec_eval bindings) for nDCG@k / MRR@k / Recall@k / MAP, plus custom recall_cap
    (cap by #relevant) and calculate_pmrr (MRR delta under instruction change)
  - BEIR-derived task schema: dataset[subset][split] = {corpus, queries, relevant_docs:
    qid->cid->rel, top_ranked: qid->[cid]}
  - Content-addressed result cache: composite key = hash(benchmark name + language tuple);
    layout results/{model_path}/{revision}/{task}.json with experiments/{name}/ subtree
  - TaskResult validation on load: required-split checks (test/train) reject stale cache that no
    longer matches task requirements
  - SearchProtocol index()/search() interface accepting encode_kwargs so custom indexes (e.g.
    PLAID) plug into the same eval loop
  - Tiered cache: HuggingFace Hub remote -> local filesystem JSON -> in-memory object cache,
    rooted at MTEB_CACHE / ~/.cache/mteb
nest steals: Three steals. (1) nest-cli benchmark subcommand: adopt MTEB's retrieval-task schema
             (corpus/queries/relevant_docs/top_ranked) and pytrec_eval-equivalent metrics
             (nDCG@k, MRR@k, Recall@k) as a deterministic Rust quality harness over a .nest
             file, turning today's anecdotal 'tiny preset recall@10 0.992' into a reproducible
             seeded per-preset report; pure compute, no socket, fits offline/deterministic
             constraints and the <=300-line single-responsibility rule (one metrics module per
             metric). (2) nest-runtime search path: MTEB's chunked exact top-k
             (corpus_chunk_size sub-batches, descending sort) mirrors nest's mandatory
             exact-cosine rerank; formalize a corpus_chunk_size loop in the SIMD dispatcher so
             the exact rerank streams over mmap'd embedding sub-blocks (bounded working set,
             cache-friendly) rather than one big pass, hardening the search_contract guarantee.
             (3) nest-format: an optional additive eval-results section (reserved id 0x09+)
             recording metric scores lets a .nest container self-certify its recall vs the exact
             f32 baseline without re-running; nest's existing content_hash already delivers
             MTEB-style 'same inputs never recompute' for free.
compression: Low-to-indirect. MTEB has no entropy coder, quantization codec, or on-disk compression to steal;
             it stores results as plain JSON. Its value to nest's compress-more-than-everyone
             goal is as a rigorous quality yardstick: it lets nest prove that aggressive
             compression (int8, f16, hnsw in the tiny preset) preserves retrieval recall
             (nDCG@k/Recall@k vs the exact f32 baseline), so compression can be pushed harder
             with measured, non-regressing quality rather than guesswork.
perf:        RetrievalEvaluator's corpus_chunk_size keeps the similarity matmul working set bounded so
             corpora larger than RAM are scored in sub-batches; cosine is implemented as inner
             product on L2-normalized vectors (one normalization, then BLAS/SIMD dot), matching
             nest's mmap SIMD dot kernels (AVX2/NEON/scalar). Scoring throughput is dominated by
             pytrec_eval (C trec_eval), not Python. MTEB itself ships no SIMD or quantization;
             it relies on the model and FAISS/numpy for heavy linear algebra.
