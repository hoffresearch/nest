what:        A C++11 library of vectorized integer-array codecs (SIMD-BP128, FastPFor/SIMD-FastPFor,
             StreamVByte, VByte, Simple9/16, varint-G8IU) that decode 4+ billion 32-bit ints/sec
             (~15 GB/s) by combining frame-based binary bit-packing with patched
             frame-of-reference exception handling over fixed blocks of 128 integers.
innovation:  Patched binary packing: split an integer array into fixed 128-int blocks, pick a single
             bit-width b per block so most values fit in b bits, vertically bit-pack all 128
             lanes at width b (compression ratio 32/b, decoded branchlessly with SIMD
             shift+mask), and store the rare values exceeding b bits ("exceptions") out-of-band
             in a separate compressed exception stream keyed by position + high-bits. Combined
             with delta coding for sorted lists, this turns monotone ID arrays into a few bits
             per element while keeping decode fully vectorizable and branch-free.
techniques:
  - SIMD-BP128: vertical bit-packing of 128 ints at a uniform bit-width b, decoded with SSE2
    shift/mask (32/b ratio, no branches in hot loop)
  - FastPFor / SIMD-FastPFor: patched frame-of-reference -- per-block bit-width minimizing total
    bits, exceptions (values >= 2^b) stored separately as position bytes + packed high-bit
    residuals
  - Delta / differential coding with a stored offset so sorted ID lists become small gaps before
    packing; SIMD 4-lane delta for vectorized prefix-sum on decode
  - StreamVByte: byte-oriented varint with 2-bit length control codes in a separate stream so
    payload bytes are gathered via SSSE3 pshufb
  - Simple9 / Simple16: pack as many ints as fit into a 32-bit word with a 4-bit selector
    describing the layout
  - Self-delimiting block framing: 'length u32 then that many 32-bit ints, repeat'
  - Hand-tuned unrolled per-bit-width (1..32) bitpack kernels, also shipped standalone as the
    simdcomp C library
nest steals: Two concrete targets, both storing raw u32 arrays today with zero compression. (1)
             nest-runtime/src/ann/codec.rs HnswIndex::to_bytes writes every neighbor id as a
             4-byte LE u32 ('for &id in nbrs { out.extend_from_slice(&id.to_le_bytes()) }');
             per-layer neighbor lists are small bounded id sets -- sort each list then
             delta+bitpack (SIMD-BP128 style) so each id costs ~b bits not 32, shrinking section
             0x07. (2) nest-runtime/src/bm25/codec.rs Bm25Index::to_bytes writes each posting as
             doc:u32 + tf:u32; doc ids per term are strictly increasing, the canonical
             FastPFor/delta case -- delta-code doc gaps then FastPFor-pack, bitpack tf
             separately, shrinking section 0x08. Implement as a pure-Rust scalar port of
             SIMD-BP128+FastPFor (new nest-runtime module, single-responsibility, <=300 loc; no
             SIMD needed for correctness, decode stays deterministic). Both are additive: index
             payloads are versioned (HNSW_PAYLOAD_VERSION / BM25_PAYLOAD_VERSION), so bump the
             per-section payload version, NOT NEST_FORMAT_VERSION, keeping v1 frozen. Also seeds
             a future general 'bitpacked/varint' section encoding id (4-255 reserved) for other
             integer-heavy sections like chunks_original_spans offsets.
compression: Directly on-mission for 'compress more than everyone': the tiny/hybrid presets ship hnsw (0x07)
             and bm25 (0x08), both storing integer id arrays at a fixed 32 bits each -- the
             largest uncompressed integer surface in a .nest file. zstd is deliberately NOT on
             the embeddings hot path, but these index sections are cold-decoded once at load, so
             FastPFor-style delta+bitpack can cut them several-fold (sorted doc-id gaps
             routinely pack to 4-8 bits) with no recall loss, pushing the tiny-preset size ratio
             below today's 0.283 while preserving deterministic/offline/single-file guarantees.
perf:        Reference C++ decodes >4e9 ints/s (~15 GB/s) on x64 via SSE2/SSSE3; SIMD-BP128 ~2x faster than
             varint-G8IU/PFOR while saving up to 2 bits/int; SIMD-FastPFor within ~10% of
             Simple-8b compression at ~2x decode speed. For nest, a scalar Rust port loses SIMD
             throughput but index sections are tiny and cold-loaded once at mmap time, so even
             scalar decode is negligible; memory cost is one 128-int block buffer. NEON/AVX2
             kernels could later mirror nest-runtime's existing simd dispatcher pattern.
