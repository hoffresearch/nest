what:        A single header-only C/C++ file (~11.7k LOC) that reimplements the entire x86
             SSE/SSE2/SSE3/SSSE3/SSE4.1/SSE4.2/AES/CRC32 intrinsic surface (xmmintrin.h through
             wmmintrin.h) on top of ARM NEON, preserving x86 semantics so SSE codebases compile
             and run on aarch64/armv7 unchanged.
innovation:  Semantics-preserving cross-ISA intrinsic emulation: every x86 SIMD op gets a hand-tuned NEON
             instruction sequence that reproduces exact x86 corner-case behavior (sign-bit
             packing order, masked-lane multiply-by-zero, IEEE-754 rounding, saturation), with
             compile-time precision flags trading speed for bit-exact fidelity. The transferable
             kernel patterns are the NEON replacements for x86 ops that have no NEON equivalent:
             movemask via shift-and-horizontal-add, and 128-bit-compare-to-bitmask via
             shift-right-narrow-by-4 (vshrn).
techniques:
  - movemask_epi8 on aarch64: vshrq_n_u8(x,7) isolates MSBs, vshlq_u8 by a per-lane shift table
    {0..7,0..7}, then vaddv_u8 over each 64-bit half packs 16 sign bits into a 16-bit integer
  - movemask on armv7 (no vaddv): cascaded vsraq_n_u64 shift-right-accumulate at offsets 7,14,28
    folds MSBs into one byte per half
  - compare-mask-to-bitmask via vshrn_n_u16(mask,4): shift-right-narrow turns a 128-bit
    all-ones/all-zeros compare result into a 64-bit nibble mask, then ctz/clz gives first-match
    length (cmpestri string ops)
  - _mm_shuffle_epi8 (pshufb) via vqtbl1q_s8 with index pre-masked by 0x8F so the high bit
    zeroes the lane, matching x86; armv7 falls back to vtbl.8 over even/odd D registers
  - _mm_maddubs_epi16 / madd via vmull widening multiply + vrshrn rounding-narrow-shift-right;
    mulhrs uses vrshrn_n_s32(mul,15) for round-to-nearest fixed-point
  - compile-time fidelity knobs: PRECISE_DIV/SQRT add Newton-Raphson iterations, PRECISE_MINMAX
    fixes NaN ordering, PRECISE_DP forces masked-lane multiply-by-zero in dot product
  - AES emulation from vqtbl1q_u8 table lookups (ShiftRows/ror32by8 permutation constants) when
    hardware crypto extensions are absent
  - QEMU-based cross-ISA differential test harness: same inputs through real SSE and the NEON
    emulation, compared bit-for-bit across armv7/armv8 aarch32/aarch64
nest steals: nest-runtime simd dispatcher (src/simd*.rs): nest already ships AVX2 + NEON + scalar dot-product
             kernels. Steal two NEON micro-patterns to harden/extend the aarch64 path. (1) The
             vshrn_n_u16(cmp,4) compare-to-nibble-mask trick: use in a NEON int8 cosine/dot
             kernel to find/skip zero lanes and to build candidate masks if nest adds
             SIMD-accelerated bm25 tokenization or pattern scanning over chunks_canonical (the
             known-gap word-segmented tokenizer). (2) The movemask shift-and-vaddv pattern:
             needed any time the NEON path reduces a per-lane boolean (quantization clamp
             detection, NaN guard before exact rerank). Also adopt sse2neon's compile-time
             precision philosophy: nest's int8 preset scores quantized embeddings directly off
             mmap, so a NEON vmull+vrshrn rounding-narrow widening-multiply (instead of plain
             truncation) gives bit-closer agreement with the AVX2/scalar reference on aarch64,
             protecting deterministic-build and exact-rerank guarantees across architectures.
             Reference its QEMU differential-test method to prove nest's three SIMD backends
             return identical dot products on the same .nest file.
compression: Low-direct: a portability/correctness library, not a compressor, so it does not shrink the .nest
             file. Indirect relevance is real: extreme compression in nest leans on aggressive
             quantization (int8 today, possibly sub-byte later), and quantized vectors are only
             useful if the on-disk codes decode and score identically on every CPU. sse2neon's
             rounding-narrow multiply kernels and cross-ISA differential-testing discipline are
             exactly what keeps a denser quantization scheme bit-faithful across
             AVX2/NEON/scalar, so the compression frontier can advance without breaking
             deterministic builds or the exact-cosine ground truth.
perf:        Header-only, zero runtime cost (all FORCE_INLINE). Most ops are 1-3 NEON instructions; expensive
             emulations are documented (_mm_maddubs_epi16 ~13 instructions; dp_ps and cmpestr*
             are multi-instruction). aarch64 movemask uses cheap vaddv horizontal add while
             armv7 needs the 3-stage vsra cascade. Per-op cost tracked in perf-tier.md. Known
             semantic gaps: _mm_rsqrt_ps(0.0) returns NaN on NEON vs INF on SSE; min/max NaN
             ordering differs unless PRECISE flags set. NEON is 128-bit only, so AVX2 256-bit
             ops are out of scope (sse2neon stops at SSE4.2/128-bit lanes).
