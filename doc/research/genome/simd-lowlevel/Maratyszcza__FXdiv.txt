what:        A ~1-file MIT C99/C++ header that replaces integer division by a runtime-invariant divisor with
             one widening multiply-high plus two shifts, using the Granlund-Montgomery (1994)
             "division by invariant integers via multiplication" magic-number scheme, with
             portable mulhi backends per platform.
innovation:  Precompute a per-divisor "magic" reciprocal struct {value, m, s1, s2} once, then turn every
             later n/d and n%d into branch-free q = (mulhi(n,m) + ((n - mulhi(n,m)) >> s1)) >>
             s2 and r = n - q*value. This converts a 20-40 cycle hardware UDIV (which most SIMD
             ISAs lack for integers) into a 3-5 cycle mul+shift sequence that IS vectorizable,
             amortized across millions of dividends sharing the same divisor.
techniques:
  - Granlund-Montgomery magic-number reciprocal: m = floor(2^(N+l)/d)+1 with l = ceil(log2(d)),
    giving exact quotient for all N-bit n
  - Round-up correction split into two shifts s1=1 and s2=l-1 to avoid an (N+1)-bit intermediate
    without a wider integer type
  - mulhi (high half of NxN product) abstracted over backends: __umulh/_umul128 (MSVC), unsigned
    __int128 shift (gcc/clang), __umulhi/__umul64hi (CUDA), mul_hi (OpenCL), and a 32x32->64
    split-and-recombine portable fallback
  - Highest-set-bit via __builtin_clz / _BitScanReverse with a bit-twiddle fallback to compute l
    in O(1)
  - Trivial divisor==1 special-case (m=1, s1=s2=0)
  - Branch-free fxdiv_round_down(n,g) = (n/g.value)*g.value for size/offset alignment
  - POD divisor struct hoisted as loop-invariant and broadcast across SIMD lanes (used in
    NNPACK/QNNPACK to vectorize tiling index math)
nest steals: Adopt as a tiny internal Rust module in nest-runtime, NOT a change to the current dot-product
             kernels. Today the hot loop in crates/nest-runtime/src/search.rs and ann/build.rs
             addresses embedding rows with i*row_size / i*dim (pure multiply, no divide), so
             FXdiv buys nothing there. Its payoff is forward-looking: (a) a future
             tensor/Parquet/video section that maps a flat mmap offset back to (row,col,channel)
             and would need /dim and %dim per element; (b) product-quantization codecs (relevant
             to the tiny preset and extreme compression) where decoding sub-vector indices needs
             divide/modulo by codebook count; (c) deterministic seeded RNG / hash bucketing
             needing fast unbiased range reduction. In each, precompute a usize/u32 magic
             divisor once per build and reuse branch-free mul+shift, keeping kernels
             SIMD-friendly (AVX2/NEON have no integer UDIV) and integer-exact/identical across
             x86_64/aarch64/scalar, satisfying byte-reproducibility and never-panic. Port is ~60
             lines of safe Rust using u128 widening mul ((n as u128 * m as u128) >> 64), well
             under the 300-line cap; MIT lets nest reimplement rather than vendor.
compression: Indirect. It does not compress bytes itself; it is an enabling primitive for compression schemes
             that add integer division/modulo on the decode hot path -- specifically product
             quantization / residual codebooks (sub-vector = idx % K, codebook = idx / K) and
             packed multi-dim tensor layouts. If nest ships PQ for sub-int8 embedding
             compression (a real lever for beating the 0.283 tiny ratio), FXdiv-style magic
             division keeps the dequant loop branch-free and vectorizable. Until PQ/tensor
             sections exist, relevance to compress-more-than-everyone is latent, not active.
perf:        Replaces a ~20-40 cycle non-pipelined integer UDIV with mulhi (3-5 cycle latency, fully
             pipelined) plus two 1-cycle shifts; the divisor struct is loop-invariant and stays
             in registers. x86 AVX2 and ARM NEON have NO integer divide instruction, so this is
             the only way to vectorize per-lane integer divide/modulo. Header-only, zero
             allocations, divisor struct is 8-24 bytes POD. Used in production inside NNPACK /
             QNNPACK / XNNPACK for convolution tiling index arithmetic.
