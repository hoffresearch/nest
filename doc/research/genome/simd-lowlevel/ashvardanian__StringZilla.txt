what:        A portable C/C++ string library exposing CPU-feature-dispatched SIMD microkernels (NEON, AVX2,
             AVX-512, SVE, SWAR fallback, CUDA) for substring search, AES-NI hashing,
             Rabin-rolling-hash MinHash sketches, Levenshtein/Needleman-Wunsch alignment,
             argsort, and lookup-table byte transforms.
innovation:  Runtime CPU-capability dispatch over a family of hand-written SIMD microkernels with named
             per-uarch variants (sz_find_skylake / sz_find_haswell / sz_find_westmere /
             sz_find_neon) selected once at load, each kernel built around the principle "you
             already fetch every cache line, so the only win is reducing comparisons per cache
             line": pick rare/anomalous needle bytes at strategic offsets, broadcast-compare
             them with one SIMD op, and only confirm full matches on the survivors.
techniques:
  - AES-NI based non-cryptographic sz_hash: feed bytes through hardware AESENC rounds for a
    fast, well-mixed 64-bit hash (plus streaming sz_hash_state_t and sz_hash_sha256 for crypto
    checksums)
  - Rabin-style 64-bit rolling hash reused for both whole-string and substring (fingerprint)
    hashing, giving O(D*(T-N)) MinHash cost independent of window width N
  - MinHash / Fingerprints sketches: D rolling-hash functions over multiple window widths (e.g.
    4,6,8,10), keeping per-dimension minima as a compact D-dim document signature; 52-bit hash
    variant in v4
  - Substring search via rare-byte + multi-offset SIMD comparison (compare characters at
    strategically chosen needle offsets to cut false positives), Boyer-Moore-Horspool with Raita
    heuristic for long needles, bit-parallel for mid needles, brute SIMD for 1-4 byte needles
  - Offset-based 'tape' layout (Strs): one contiguous byte tape plus a u32 offsets array, ~4
    bytes overhead per string for sub-4GB datasets, zero-copy mmap and PyArrow-serializable,
    lazy split_iter avoids materialization
  - vpshufb / NEON vtbl lookup-table transform (sz_lookup) mapping bytes through a 256-entry
    table at ~21 GB/s, 80x std::transform, usable as int8 codec / case-fold / dna decode
  - Radix/parallel sz_sequence_argsort returning a permutation over a string collection (beats
    std::sort and 4x numpy.argsort) without moving the underlying bytes
  - Two-tier retrieve-then-rerank architecture: cheap MinHash fingerprints for candidate
    retrieval, expensive exact Levenshtein/NW scoring only on reranked survivors
nest steals: Four concrete steals. (1) nest-runtime simd dispatcher: adopt StringZilla's named-per-uarch
             runtime dispatch pattern (currently nest has AVX2/NEON/scalar) so the dot-product
             kernel picks AVX-512/AVX2/SSE/NEON/scalar once at mmap time behind one fn pointer,
             keeping the never-panic typed-error boundary; optionally vendor StringZilla
             (Apache-2.0) for sz_hash. (2) nest-format hashing: replace or augment SHA-256
             surfaces' hot-path data-integrity needs with AES-NI sz_bytesum/sz_hash for a fast
             non-crypto pre-check while keeping SHA-256 as the canonical content_hash (additive,
             no format bump). (3) nest-format new optional section (id 0x09+, RESERVED today): a
             deterministic MinHash 'sketch index' built from Rabin rolling fingerprints over
             chunks_canonical, giving an ultra-compact pre-filter that shrinks the candidate set
             before the mandatory exact-cosine rerank, mirroring nest's existing HNSW+rerank
             contract and StringZilla's retrieve-then-rerank design. (4) nest-format chunks
             layout + int8 codec: the offset-tape (u32 offsets + byte tape) is exactly nest's
             chunks_canonical/chunks_original_spans shape, and vpshufb/vtbl sz_lookup is a ready
             SIMD kernel for the int8 encoding decode path and for a SIMD bm25 tokenizer that
             fixes the CJK/Thai word-segmentation gap via byte-level scanning.
compression: Indirect but real. StringZilla does not add a new entropy coder, so it does not directly beat
             zstd on ratio. Its compression-mission value is (a) MinHash sketches as a tiny
             deduplication/near-duplicate detector to drop redundant chunks before encoding,
             raising effective ratio; (b) the offset-tape layout minimizes per-string overhead
             (4 bytes) in the text sections; (c) vpshufb LUT transform accelerates int8
             quantization decode so the tiny preset stays fast off mmap. The decisive
             contribution is making the serve path cheaper (AES hashing, dispatched SIMD,
             fingerprint pre-filter), which lets nest keep aggressive compression without
             hurting search latency.
perf:        sz_find ~10.6 GB/s x86 / 7.1 GB/s ARM (vs libc strstr 7.4 / 2.0); sz_lookup ~21 GB/s (80x
             std::transform); AES sz_hash ~3x OpenSSL hashlib on mmap'd files; argsort 1.91s vs
             std::sort 2.79s and numpy 7.58s on 8M words; Levenshtein 3.4B CUPS x86 / 93.6B CUPS
             CUDA. Kernels are scalar-fallback-safe (SWAR on 64-bit words), header-only C with
             stable ABI, zero-alloc in-place ops, and the per-uarch backends are disablable via
             SZ_USE_X86_AVX512 / SZ_USE_X86_AVX2 / SZ_USE_ARM_NEON compile flags.
