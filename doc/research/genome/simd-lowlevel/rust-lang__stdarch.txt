what:        stdarch is the implementation home of Rust's `core::arch` / `std::arch` vendor intrinsics plus
             `std_detect` runtime CPU feature detection, organized as one
             `#[target_feature(enable=...)]`-gated intrinsic per machine instruction, with
             detection cached lock-free in an atomic bitset and verified by an `assert_instr`
             macro that disassembles the compiled shim to confirm the expected instruction was
             emitted.
innovation:  The two-layer "safe runtime dispatch" contract: each architecture-specific kernel is an `unsafe
             fn` carrying `#[target_feature(enable = "feat")]` (which lets LLVM emit that ISA's
             instructions for just that function without -C target-feature), and it is reached
             only behind an `is_x86_feature_detected!`/`is_aarch64_feature_detected!` guard
             whose result is computed once and cached in a lock-free atomic bitset, so a
             portable least-common-denominator binary picks the fastest available kernel at
             runtime with zero per-call CPUID cost. The matching trick is per-instruction
             granularity: one intrinsic == one named instruction, so capability can be detected
             and dispatched at the finest possible level (f16c, avxvnni, dotprod separately from
             avx2).
techniques:
  - #[target_feature(enable="avx2,fma")] per-function ISA enablement (no global -C
    target-feature needed)
  - is_x86_feature_detected!/is_aarch64_feature_detected! macros over std_detect; detection
    cached in a lock-free atomic-usize bitset with an initialized sentinel bit so
    CPUID/getauxval(HWCAP)/sysctl runs exactly once
  - fine-grained gates: f16c (_mm256_cvtph_ps -> vcvtph2ps) for hw f16->f32, avxvnni/avx512vnni
    (_mm256_dpbusd_epi32 -> vpdpbusd) for single-instruction int8 dot, aarch64 dotprod
    (vdotq_s32) for NEON int8 dot
  - _mm256_fmadd_ps / vfmaq_f32 fused multiply-add accumulators (the core of a dot product)
  - #[assert_instr(vfmadd)] proc-macro emits a #[test] shim, compiles it, and greps the
    disassembly to prove the intended instruction was generated
  - static vs dynamic dispatch duality: same kernel reachable via #[cfg(target_feature)] or
    runtime guard
  - repr(simd) Simd<T,N> newtype over [T;N] with simd_fma/simd_cast LLVM intrinsics as the
    portable lowering substrate
nest steals: nest-runtime/src/simd already copies the stdarch idiom (OnceLock-cached is_x86_feature_detected
             dispatch + #[target_feature(enable=\"avx2,fma\")] kernels calling
             _mm256_fmadd_ps/vfmaq_f32), so the steal is three fine-grained-feature upgrades the
             code itself flags as gaps. (1) In mod.rs the f16 path dot_f32_f16_bytes (lines
             107-111) explicitly bails to scalar to avoid the F16C detection branch -- add an
             is_x86_feature_detected!(\"f16c\") tier in avx2.rs using _mm256_cvtph_ps
             (vcvtph2ps) to convert 8 f16 lanes to f32 in one instruction, giving the
             compressed/tiny presets a real AVX2 f16 dot path. (2) The int8 path dot_f32_i8_avx2
             (lines 36-60) widens i8->i32->f32 then FMAs -- gate an avxvnni/avx512vnni tier
             using _mm256_dpbusd_epi32 (vpdpbusd) for int8 accumulate-to-i32 in one instruction,
             multiplying by the per-vector scale once at the end, accelerating the tiny preset
             (zstd/int8/hnsw, 0.283 ratio) hot path. (3) In neon.rs add an
             is_aarch64_feature_detected!(\"dotprod\") tier using vdotq_s32 for the same int8
             win on Apple silicon. Adopt stdarch's verification discipline in simd/tests.rs by
             vendoring the assert_instr disassembly check so a refactor that silently drops
             vfmadd/vpdpbusd is caught. Add Avx2F16c/Avx2Vnni/NeonDotprod variants to the
             SimdBackend enum so nest stats reports the active tier. All additive, offline,
             deterministic (exact rerank stays ground truth); no format change.
compression: Indirect but real: extreme compression in nest comes from the int8 and float16 codecs (tiny =
             0.283 ratio), but those quantized formats are only viable on the hot path if they
             decode/score fast off mmap. stdarch's f16c (vcvtph2ps) and VNNI/dotprod
             (vpdpbusd/vdotq_s32) single-instruction kernels remove the widen-and-convert
             overhead that currently makes the compressed dtypes slower per query than f32, so
             the most-compressed presets stop paying a latency tax. This lets nest push
             quantization harder (e.g. default tiny) without losing the serve-from-disk speed
             promise, advancing compress-more-than-everyone while keeping fast search.
perf:        target_feature enablement is per-function, so kernels emit AVX2/FMA/F16C/VNNI/NEON-dotprod
             instructions while the rest of the binary stays portable (no -C target-feature, no
             per-CPU recompilation). Detection is one atomic bitset read after first call; nest
             already amortizes via OnceLock + function-pointer dispatch (one indirect call per
             query). _mm256_cvtph_ps converts 8 f16->f32 in one vcvtph2ps; _mm256_dpbusd_epi32
             does 32 int8 MACs into 8 i32 lanes per vpdpbusd (~4x the current
             cvtepi8_epi32->cvtepi32_ps->fmadd chain); vdotq_s32 does 16 int8 MACs into 4 i32
             lanes per instruction on aarch64 dotprod. assert_instr adds zero runtime cost
             (test-only shim).
