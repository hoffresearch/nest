================================================================================================
linebender/fearless_simd
category: simd-lowlevel   |   steal priority: HIGH
================================================================================================

siblings: ./00-index.txt   |   map: ../../README.txt

what:        A Rust portable-SIMD library that encodes "this CPU feature is available" as a zero-sized
             type-level witness token (implementing the Simd trait), so write-once generic
             kernels monomorphize per instruction-set level
             (Fallback/Sse4_2/Avx2/Neon/WASM-simd128) and call intrinsics with no unsafe at the
             call site.
innovation:  The witness-token + inline-always dispatch pattern lets one generic SIMD kernel safely compile
             to optimal per-arch intrinsics, eliminating the unsafe NxM kernel matrix.
techniques:
  - Witness/token safety pattern: ZST Level/Simd-trait markers as type-level proof of enabled
    target_feature, making core::arch intrinsics safe to call (relies on target_feature 1.1 +
    safe arch intrinsics, MSRV 1.86/1.88)
  - dispatch!(level, simd => kernel(simd, ...)) macro: one runtime Level::new() detection, then
    monomorphized #[inline(always)] specializations per SIMD level so target_feature propagates
    via inlining
  - Portable fixed-width vector types f32x4/f32x8/f32x16, f64x2/4/8, i8x16/u8x16, i16x8, i32x4
    plus mask8x16/16x8/32x4 with overloaded +,*,FMA lowering to optimal intrinsics
  - Trait stack: SimdBase (load/store/arith), SimdFloat, SimdInt, SimdMask,
    Select(if-mask-then-a-else-b), SimdCombine/SimdSplit, SimdCvtFloat/SimdCvtTruncate for
    int<->float quantization
  - fearless_simd_gen code generator stamps the low-signal repetitive per-arch impls so the
    hand-maintained core stays tiny
  - kernel!() macro + safe_wrappers feature: token-gated escape hatch to arch-specific
    intrinsics beyond the portable set, still safe under the witness
  - WASM strategy: build two bundles (+simd128 vs scalar) and select at load since wasm lacks
    runtime feature detection
nest steals: Target crate nest-runtime, module crates/nest-runtime/src/simd/. nest today hand-rolls a 3x3
             matrix of unsafe #[target_feature] kernels (scalar.rs + avx2.rs + neon.rs, each
             with dot_f32 / dot_f32_f16 / dot_f32_i8) behind an OnceLock+enum dispatcher in
             mod.rs (lines 86-132 each match on detect_backend() then call an `unsafe fn`).
             Adopt the witness-token+dispatch pattern (vendored, not the unstable crate) to
             replace those ~5 files with ONE generic dot_f32<S: Simd>, dot_f32_f16<S: Simd>,
             dot_f32_i8<S: Simd> kernel set. This: (1) removes unsafe from the hot path,
             satisfying nest's never-panic/typed-error and clean-core constraints; (2) keeps the
             single up-front detection (matches nest's OnceLock model) so per-query cost stays
             one branch; (3) unlocks f32x16/AVX-512 and WASM simd128 lanes for free, widening
             portability of the i8/f16 quantized scoring loop (score_int8_section, search.rs
             exact-cosine rerank) which is THE compression-critical path; (4) the
             SimdCvtFloat/SimdCvtTruncate traits map directly onto nest's int8 dequant (v ~=
             i8*scale) and float16 unpack, letting the dequant be vectorized portably instead of
             the current portable-unpack-only f16 fallback. Determinism is preserved because the
             math is identical per lane and the dispatch is deterministic; the kernels stay well
             under the 300-line file cap.
compression: Indirect but real. fearless_simd is not a compressor, but nest's compression wins (tiny preset:
             zstd/int8/hnsw at 0.283 size ratio) hinge on scoring quantized int8/f16 embeddings
             directly off mmap on the hot path. The witness pattern lets nest add wider/portable
             SIMD lanes (f32x16, WASM, future AVX-512) and clean vectorized dequant for int8/f16
             WITHOUT growing the unsafe surface, so nest can push to more aggressive
             quantization (int8, and later int4/binary-packed) confident the scoring loop stays
             fast and portable across the sovereign/offline targets. It removes the
             SIMD-portability tax that would otherwise discourage harder compression schemes.
perf:        Per-query cost target identical to nest now: one indirect/branch at dispatch, then fully-inlined
             target_feature code (FMA-fused dot products: _mm256_fmadd_ps on AVX2, vfmaq on
             NEON). The pattern's whole point is that monomorphization + #[inline(always)]
             yields machine code byte-comparable to hand-written intrinsics (it powers Vello's
             Sparse Strips renderer and is philosophically the pulp/faer approach). int8 path
             widens i8->i32->f32 in-lane (matches nest avx2.rs _mm256_cvtepi8_epi32 +
             _mm256_cvtepi32_ps). No heap, ZST tokens carry no runtime cost. Caveat: 128-bit
             minimum vector width; relies on aggressive inlining (a missed #[inline(always)]
             silently de-optimizes).
license:     Dual MIT OR Apache-2.0 (Linebender standard), permissive - safe to vendor/adapt into nest.
             Caveat: crate is explicitly "extremely early experimental, no stability
             guarantees," so vendor the pattern rather than depending on the published crate to
             protect nest's frozen-format and determinism guarantees.
