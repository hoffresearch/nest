what:        A GPU-native (NVIDIA cuVS) fork implementing IVF-RaBitQ: it fuses inverted-file clustering with
             RaBitQ quantization, which compresses each D-dim float32 vector to ~1 bit/dim plus
             two scalar factors and estimates distances with a provably unbiased,
             asymptotically-optimal-error estimator via random rotation, so no raw-vector
             reranking is needed.
innovation:  RaBitQ replaces a trained codebook (PQ) with a SINGLE random orthogonal rotation P shared by
             every vector: normalize the residual-to-centroid o, then store only the sign bit of
             P^-1 o per dimension (the binary code x_bar is the nearest vertex of a
             randomly-rotated +/-1/sqrt(D) hypercube). Because the codebook is random, the
             cross-term <o_bar, q> yields an UNBIASED estimator of the true dot product, <o,q>
             ~= <o_bar,q>/<o_bar,o>, with sharp O(1/sqrt(D)) error -- asymptotically optimal
             (matches Alon-Klartag FOCS17). This means 1 bit/dim gives reliable enough distances
             and confidence intervals to skip touching the original float vectors entirely,
             which is the compression-without-recall-collapse that ordinary binary quantization
             cannot achieve.
techniques:
  - 1-bit-per-dimension sign quantization of randomly-rotated residual: store sign(P^-1(o-c)) as
    a D-bit string, total per-vector = D bits + 2 f32 factors
  - Shared random orthogonal rotation P (Johnson-Lindenstrauss transform) -- no per-corpus
    codebook training, fast variant uses Fast Hadamard Transform instead of dense matmul
  - Two stored scalar factors per vector: <o_bar,o> (code-to-data inner product, the
    unbiasedness normalizer) and ||o-c|| (residual norm to centroid)
  - Unbiased distance estimator <o,q> ~= <o_bar,q>/<o_bar,o> with provable O(1/sqrt(D)) error
    bound enabling rerank-free retrieval
  - Asymmetric bit budget: data side stays 1 bit/dim, query is rotated then scalar-quantized to
    B_q bits (e.g. 4) and decomposed into B_q bit-planes
  - Bitwise distance kernel: per query bit-plane, AND with the code then popcount, summed with
    plane weights -- 3x faster than PQ LUT scan on CPU, maps to GPU as AND+__popc
  - FastScan-style layout packing 32 binary codes per batch with 4-bit quantized 8-bit LUT
    entries for SIMD/warp-parallel filtering
  - Two-stage filter-then-refine: cheap 1-bit code filters candidates, 'ex-code' (extra low
    bits) refines survivors; extended B-bit RaBitQ (Sep-2024) for multi-bit budgets
nest steals: Add a new embeddings codec in nest-format/src/encoding/ as `rabitq.rs` (encoding id 4 --
             currently only 0..3 are used; 4..255 are RESERVED within format v1, so this is
             purely additive, no NEST_FORMAT_VERSION bump). Layout mirrors int8.rs: a u32
             payload_version, a single shared D*D rotation seed (deterministic, store the seed
             not the matrix to stay reproducible and tiny), then per vector a packed D-bit sign
             code plus two f32 factors (<o_bar,o>, ||o-c||) and the global centroid c once. This
             is a drop-in replacement for the int8 path in the `tiny` preset, taking embedding
             storage from ~1 byte/dim (int8) to ~1 bit/dim -- roughly an 8x shrink of the
             embeddings section, which is the dominant section in compressed presets, directly
             advancing the 'compress more than everyone' north star (tiny's 0.283 ratio could
             drop materially). In nest-runtime/src/simd/, add a popcount-based RaBitQ kernel
             beside scalar/avx2/neon (AND + popcount over query bit-planes; NEON vcnt, AVX2
             popcount, scalar count_ones fallback) for the cheap ANN filter stage. Critically,
             nest's search contract is PRESERVED for free: the mandatory exact-cosine rerank
             already re-scores survivors from the mmapped vectors, so RaBitQ becomes the
             ANN-proxy filter and the contract's exact rerank guarantees real cosine -- RaBitQ's
             own error bound just makes the candidate set smaller/cleaner. Determinism holds
             because the rotation is seeded and sign() is exact.
compression: Directly central. RaBitQ is the single best-known route to push nest's embeddings section from
             int8 (8 bits/dim) to ~1 bit/dim WITHOUT recall collapse, because its rotation-based
             estimator is unbiased with an optimal error bound. Embeddings dominate
             compressed-preset file size, so an ~8x cut there is the largest available lever on
             nest's headline compression ratio while the mandatory exact-cosine rerank keeps
             returned scores ground-truth.
perf:        Data side is D/8 bytes per vector (e.g. 1536-dim -> 192 bytes) plus 2 f32 factors and one shared
             seed; no per-vector codebook. Distance filter is bitwise AND + popcount over B_q
             query bit-planes (B_q typically 4), which is branch-free and SIMD/SIMT friendly:
             maps to AVX2/NEON popcount on nest's x86/aarch64 dispatch and to __popc on GPU. The
             cuVS paper reports >2.7x throughput over IVF-PQ (no raw rerank) and ~2.2x QPS over
             CAGRA at recall ~0.95 with 7.7x faster index build, quantizing >1M 960-dim
             vectors/sec to 8-bit codes on GPU. For nest's CPU-only mmap runtime, the win is
             memory traffic: 1-bit codes mean ~8x fewer bytes touched per scanned vector than
             int8, and popcount throughput easily saturates the hot path.
