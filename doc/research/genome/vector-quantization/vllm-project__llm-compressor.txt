what:        A post-training quantization toolkit that compresses LLM weights to int4/int8/fp8 and microscale
             fp4 using calibration-driven, Hessian-aware algorithms (GPTQ, AWQ, SmoothQuant),
             serializing the result in `compressed-tensors`, a safetensors extension that
             bit-packs sub-byte values with per-group scales/zero-points.
innovation:  GPTQ-style error-compensated quantization: instead of rounding each vector dimension
             independently (nest's current naive int8), quantize columns left-to-right and
             redistribute each value's rounding error onto the not-yet-quantized dimensions,
             weighted by the inverse Hessian (H^-1 = (X^T X + lambda*I)^-1) of the per-dimension
             covariance computed once over a calibration set of embeddings. Because all rows
             share the same Hessian, the inverse is precomputed once via a Cholesky
             factorization and reused, with lazy block updates for cache locality. This recovers
             far more accuracy at a given bit-width than round-to-nearest, letting you push
             embeddings to ~4 bits while keeping cosine recall high.
techniques:
  - GPTQ: OBS/OBQ-derived inverse-Hessian error compensation, fixed column order, one-time
    Cholesky factorization of (X^T X + 0.01*diag damping), lazy block updates (blocksize ~128)
  - ActOrder: reorder dimensions by sensitivity (largest Hessian diagonal first) so high-impact
    dims are quantized while more dims remain to absorb error
  - Group-wise scales: one scale/zero-point per contiguous group of 128 values, ~0.125
    bits/value overhead but captures local distribution -> big win vs per-tensor
  - pack-quantized codec: logical int4 stored as int8 then packed 8-per-int32, with separate
    weight_scale (bf16) and weight_shape side tensors
  - NVFP4 microscale: 4-bit E2M1 elements, shared E4M3 fp8 scale per 16-value block, plus one
    fp32 per-tensor scale (two-level scaling)
  - MXFP4 microscale: 4-bit E2M1 elements with shared UE8M0 power-of-two scale per 32-value
    block (cheaper, lower quality than NVFP4)
  - SmoothQuant: migrate per-channel activation outliers into weights via a diagonal scaling
    transform so both quantize cleanly
  - safetensors-extension layout: quantized payload plus sibling scale/zeropoint/shape tensors
    named by convention, self-describing per-layer config
nest steals: Three concrete steals. (1) nest-format/encoding: add two additive encoding ids in the reserved
             4-255 range -- a `pack_int4` codec (8 logical int4 per int32, deterministic LE
             packing) and a `microfp4` codec (E2M1 elements + per-16 fp8 block scale + per-shard
             fp32 scale, NVFP4-style two-level), each storing scales in a side blob so the
             embeddings section stays a flat mmap-friendly array; nest-runtime SIMD dispatcher
             gets an unpack+dequant-to-f32 step before the AVX2/NEON dot product (or
             dequant-on-the-fly into the accumulator). This unlocks ~4x and ~8x smaller
             embedding sections vs f32, beating the current `tiny` int8 preset. (2) nest-python
             builder: add an offline GPTQ/group-wise calibration pass over corpus embeddings
             (compute X^T X once, Cholesky inverse, error-compensated round) producing quantized
             bytes; pure build-time, keeps the rust runtime offline and deterministic, and is
             where the real compression-ratio gains live. (3) Group-wise scales (group=128)
             become a tiny side-section feeding the rerank: since nest ALWAYS does an
             exact-cosine rerank, an approximate fp4/int4 ANN-stage score is acceptable because
             the mandatory rerank restores true cosine -- so aggressive quantization is
             risk-free for final scores. Determinism holds: seeded calibration, fixed column
             order, alphabetical/index group order; format stays additive (new encoding ids
             only, no NEST_FORMAT_VERSION bump).
compression: Directly central to nest's 'compress more than everyone' north star: GPTQ error compensation +
             group scales let embeddings drop from int8 (nest's current floor) to ~4 bits at
             comparable recall, roughly halving the largest section again, and NVFP4/MXFP4 give
             a principled sub-byte float path. The mandatory exact-cosine rerank in nest's
             search contract is the perfect safety net that makes aggressive lossy embedding
             quantization safe for final-score fidelity.
perf:        Quantization cost is all build-time (Cholesky is O(d^3) in embedding dim d once, e.g.
             d=384/768/1024 is trivial; per-vector pass is O(d^2) within a block). Runtime cost
             is the unpack/dequant before SIMD: int4-into-int32 unpack is a few shifts+mask
             vectorizable under AVX2/NEON; NVFP4 needs a small E2M1 LUT + fp8 scale multiply.
             Memory: int4 group=128 adds ~0.125 bits/value; NVFP4 adds ~0.5 bits/value (fp8
             scale per 16) plus negligible per-tensor fp32. Smaller embeddings also mean less
             mmap page traffic on the hot dot-product path, partly offsetting dequant overhead.
