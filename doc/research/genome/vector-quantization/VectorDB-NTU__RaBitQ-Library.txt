what:        RaBitQ is a randomized 1-bit-per-dimension vector quantizer (D-dim -> D bits + 2 float
             correction factors) using a random hypercube rotation to yield an unbiased distance
             estimator with provable O(1/sqrt(D)) error, evaluated via AND+popcount or FastScan.
innovation:  Random orthogonal rotation converts 1-bit sign quantization into a provably-unbiased distance
             estimator with a sharp O(1/sqrt(D)) error bound, making bit-only distance ordering
             reliable; the estimator reduces to AND+popcount against an int4 query, beating PQ
             on both size and speed with theoretical guarantees PQ lacks.
techniques:
  - 1-bit/dim binary code = nearest vertex of a randomly-rotated hypercube on the unit sphere
    (D/8 bytes/vec)
  - Two stored f32 factors/vec: distance-to-centroid ||v-c|| and projection factor <x_bar, o>
  - Asymmetric quantization: data is 1-bit, query is int4/B-bit scalar quant, combined via
    bitwise ops
  - Unbiased distance/inner-product estimator with O(1/sqrt(D)) bound from JLT theory
  - Distance kernel = bitwise-AND + popcount (single query) or SIMD shuffle FastScan (batched)
  - Random orthogonal matrix stored as a deterministic SEED; P^-1 q computed once/query,
    amortized over the probe list
  - B-bit extension splits code into binary MSBs + ex-code for incremental refinement (4/5/7-bit
    ~ 90/95/99% recall no-rerank)
  - Centroid-relative encoding before normalize+quantize (IVF/KMeans, or single global centroid
    standalone)
nest steals: New embedding codec in nest-format/src/encoding (id from reserved 4-255, additive, no version
             bump): per vector = D/8 packed sign bits as LE u64 words + 2 LE f32 factors; store
             global centroid + rotation seed in the embeddings section header (repr(C), LE,
             deterministic). ~32x vs f32 (1024-dim: 4096->136 bytes), a tier below int8. Add an
             AND+popcount SIMD kernel in nest-runtime/src/simd (NEON/AVX2/scalar) that scores
             codes straight off mmap as the ANN/coarse score; nest's mandatory exact cosine
             rerank stays ground truth, so recall holds. New nest-cli "nano" preset
             (zstd/rabitq/hnsw) and pairs with the existing HnswIndex (HNSW+RaBitQ). Determinism
             preserved via seeded rotation and fixed-seed centroid.
compression: Highest-leverage compression for nest: ~32x on the embeddings section (the largest part of a
             .nest file) vs 4x int8 / 2x f16, with recall preserved because nest already does
             mandatory exact cosine rerank and the unbiased O(1/sqrt(D)) estimator selects good
             candidates. B-bit ex-code gives a 1/4/5/7-bit dial. Directly advances 'compress
             more than everyone' for vector bytes.
perf:        Single-query distance is AND+popcount, single-cycle ops, reported ~3x faster than PQ RAM table
             lookups at equal accuracy; batched queries use PQ-style SIMD gather/shuffle
             FastScan. Reads D/8+8 bytes/vec instead of 4D, so the mmap hot path is
             memory-bandwidth-light. Inverse rotation P^-1 q is one O(D^2) op per query
             amortized over the whole probe list; per-vector rotation is paid once at build
             time. GPU implementation also exists upstream.
license:     Not confirmed from README in this session; upstream is C++ (academic, VectorDB-NTU / NTU
             Singapore). Verify exact license (likely MIT/Apache-style academic release) before
             vendoring; nest only needs the algorithm/format, reimplemented clean in Rust, so
             license is a reference concern not a code-copy dependency.
