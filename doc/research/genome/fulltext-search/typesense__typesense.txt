what:        A from-scratch C++ in-memory typo-tolerant lexical search engine whose inverted index is an
             Adaptive Radix Tree (ART) over tokens with Frame-of-Reference bit-packed posting
             lists, pointer-tagged compact lists for short postings, incremental
             trie-Levenshtein fuzzy traversal, and relevance encoded as a single sortable 64-bit
             integer.
innovation:  Posting lists are compressed with Frame-of-Reference (FOR) bit-packing: each block stores a min
             base m, then packs (value - m) deltas at the minimal bit-width b = required_bits(M
             - m) for that block. This is a self-contained, branch-light integer codec that
             compresses sorted doc-ids and token positions to near entropy while still allowing
             random access (at(i)) and binary search (lower_bound) directly on the packed bytes
             without full decompression -- exactly the "compress AND still serve from the packed
             form" property nest needs on its scoring hot path.
techniques:
  - Frame-of-Reference (FOR) bit-packing: per-block min base + adaptive bit-width
    b=required_bits(M-m) over delta-from-min, sized via for_compressed_size_bits() (lib for.h)
  - Block-chained posting_list_t with id_block_map = std::map<last_id_t, block_t*> as a skip
    index to jump to the right block for range/AND-intersection without scanning the chain
  - compact_posting_list_t: interleaved [num_offsets, off1..offn, id] records in a single uint32
    flex-array for short lists, avoiding per-list block overhead
  - Low-bit pointer tagging (ptr|1) to distinguish compact vs full posting list at zero extra
    storage; IS_COMPACT/RAW_PTR/COMPACT_PTR macros mask the LSB
  - Relevance packed into one 64-bit int via bit-shifts (word-presence high bits, then
    unique-word count, typo cost, proximity, exact match, position, synonym) so ranking is a
    single integer compare
  - Adaptive Radix Tree node4/node16/node48/node256 upgrading node type as fanout grows, leaves
    holding sorted_array ids + offset_index + raw offsets
  - Trie-Levenshtein fuzzy search: descend ART carrying parent's DP cost-row, compute child row
    from insert/delete/substitute min, prune subtrees by max-word-length and length-delta bound;
    O(k*nodes) not O(terms)
nest steals: Two concrete drops. (1) nest-format: add a FOR bit-packed codec for the bm25_index (section
             0x08) postings -- doc-ids delta-from-min + adaptive bit-width per block, positions
             likewise. Additive (new encoding id in reserved 4-255 applied only to 0x08, never
             embeddings), deterministic (bit-width is a pure function of the block min/max), and
             supports at()/lower_bound on packed bytes so nest-runtime bm25::Bm25Index keeps
             O(log n) AND-merge directly off mmap with no decompress on the hot path -- same
             discipline nest uses scoring embeddings from mmap. (2) nest-runtime: implement
             trie-Levenshtein incremental cost-row fuzzy matching over the bm25 term dictionary
             for typo tolerance and, via a byte/grapheme trie, a path to fix the known CJK/Thai
             word-segmentation gap (match character n-gram paths instead of whitespace words).
             The compact-vs-full interleaving idea maps to a small-posting inline format cutting
             overhead for the many low-DF terms in nest's PT-BR corpus. The 64-bit packed score
             gives a deterministic, alphabetical-tie-broken single-integer sort key fitting
             nest's deterministic bm25 contract before the mandatory exact-cosine rerank.
compression: High and direct: FOR bit-packing of delta-from-min postings is a textbook extreme-compression
             win for the bm25_index doc-id and position lists (the inverted index is often a
             large fraction of a lexical index), and it preserves random access + binary search
             on the packed bytes, so it compresses WITHOUT giving up serve-from-mmap speed --
             exactly nest's north-star constraint. It stacks under nest's existing zstd on
             non-embedding sections (FOR first to shrink integer entropy, zstd second for
             residual redundancy).
perf:        In-memory, read-optimized C++; ART chosen for cache locality. Iterators decompress a FOR block
             into a raw uint32 array on demand for tight loops, but random access works on the
             packed form. FOR decode is branch-light bit-unpacking amenable to SIMD (nest's
             existing AVX2/NEON dispatch could vectorize the unpack). Single-integer relevance
             compare avoids multi-field comparator branches in top-k. Skip index (id_block_map)
             makes AND-intersection sub-linear. Trie-Levenshtein is O(k*nodes) with length-based
             subtree pruning, far cheaper than scanning the dictionary.
