what:        Toshi is an Elasticsearch-style HTTP/Raft frontend over Tantivy, whose value to nest is
             Tantivy's segment codec stack: FST term dictionaries, BP128 delta+bitpacked posting
             blocks with VInt remainders, 1-byte log-quantized fieldnorms, and an auto-selecting
             columnar fast-field codec (constant/GCD/bitpacked/blockwise).
innovation:  Block-wise posting-list compression: split each posting list into fixed 128-doc blocks,
             delta-encode doc_ids within a block, bitpack each block to the minimum bit-width
             needed (num_bits derived from the block max), and VInt-encode the final partial
             block; pair this with a per-term skip header so you can binary-search blocks and
             decode only the block you need. Tantivy generalizes the same min+num_bits
             bitpacking idea to columnar data and auto-picks the cheapest codec (constant when
             all values equal, GCD when they share a divisor, plain bitpacked otherwise) at
             serialize time, so the file always carries the smallest representation without the
             reader needing to know which was chosen.
techniques:
  - BP128: per-block (128 docs) delta-encode doc_ids then bitpack at block-local num_bits =
    bits(max_delta); store one num_bits byte + block min
  - VInt (LEB128-style variable-byte) for the trailing partial block under 128 elements,
    avoiding a wasted full-width block
  - Per-term skip list / block headers (first doc_id + byte offset per block) enabling
    block-skip and future block-max WAND without decoding the whole list
  - FST (finite-state transducer, fst crate) term dictionary: term -> TermOrdinal -> TermInfo,
    giving shared-prefix term compression and ordered prefix/range iteration
  - 1-byte log-quantized fieldnorm encoding: doc length compressed to a single byte (small
    values exact) instead of a raw u32 doc_length
  - Columnar auto-codec selection: probe constant / GCD / bitpacked, emit whichever is smallest,
    recorded in column metadata so decode stays uniform
  - min_value + bitpacked-residual columnar layout giving O(1) random access (min +
    fetch_bits(num_bits*id..)) directly off mmap
  - BlockedBitpacker: bitpacking in 128-element blocks so each block adapts its bit-width to
    local value range
nest steals: Target nest-runtime/src/bm25/codec.rs + index.rs, which today serialize section 0x08 as raw
             fixed-width pairs (Posting{doc:u32, tf:u32} = 8 bytes/posting, no deltas) plus
             doc_lengths as raw u32. Adapt three Tantivy codecs, all deterministic and additive
             within format v1 (no NEST_FORMAT_VERSION bump since the 0x08 payload is internal,
             gated by BM25_PAYLOAD_VERSION 1->2): (1) replace each term's postings with
             sorted-doc delta + BP128-style block bitpacking (block num_bits byte + bitpacked
             deltas + VInt tail), cutting the dominant posting cost roughly 2-6x on real
             corpora; (2) replace per-doc doc_lengths: Vec<u32> with a single min+num_bits
             bitpacked column (the columnar trick), typically 1-2 bytes/doc instead of 4, or go
             further with the 1-byte log-quantized fieldnorm; (3) optionally replace the
             alphabetical term list + 4-byte length prefixes with a front-coded / shared-prefix
             term block (the FST idea in its simplest sorted-prefix form) to shrink the
             dictionary. Keep tf as a parallel bitpacked stream. All structures stay
             seeded/sorted so builds remain byte-identical, and the existing exact-cosine rerank
             means BM25 stays a candidate generator so lossy fieldnorm quantization is safe. A
             small bitpacker (min + num_bits + LE u64 word packing) is ~60-100 LOC, under the
             300-line file cap, and reusable later for HNSW neighbor-id lists (section 0x07) and
             future columnar metadata.
compression: Directly on the north star. The BM25 index is currently one of nest's least-compressed sections
             (8 bytes/posting, 4 bytes/doc, fully raw). Block delta+bitpacking plus a bitpacked
             doc-length column is a proven, lossless, mmap-friendly win that shrinks section
             0x08 several-fold while preserving exact-rerank correctness; the same min+num_bits
             columnar bitpacker is the reusable primitive for compressing any integer-id section
             (HNSW edges, chunk-id maps) under nest's hot-path mmap constraint.
perf:        BP128 / blocked bitpacking is SIMD-friendly: Tantivy decodes 128-doc blocks with SSE2-vectorized
             bitpacking (the bitpacking crate has AVX2/SSE paths; a scalar word-at-a-time unpack
             is the portable fallback, matching nest's existing AVX2/NEON/scalar dispatch
             philosophy). Decode is branch-light and cache-friendly because each block is
             contiguous; random access via min+fetch_bits is a single memory fetch per value.
             Bitpacking touches far fewer bytes than raw u32 arrays, so the mmap/page-cache
             footprint and cold-read I/O both drop, which matters more than raw CPU for nest's
             off-disk model. Determinism holds: bit-width is a pure function of the sorted data,
             so identical input yields byte-identical packed output.
