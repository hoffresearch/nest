siblings: ./00-index.txt   |   map: ../../README.txt

what:        A tokio-backed immutable triple store whose entire on-disk format is built from succinct data
             structures (front-coded dictionaries, minimum-bit-width packed integer arrays, and
             two-level rank/select bit indexes) queried directly from mmapped bytes with no
             decompression step, reaching ~13.6 bytes/triple on 17B-triple graphs.
innovation:  Store integer columns and string dictionaries in succinct, query-in-place encodings so the file
             IS the index: data stays compressed on disk and in the page cache yet supports O(1)
             random access (LogArray.entry) and O(1) rank/select navigation (BitIndex) without
             ever materializing a decompressed copy. This is the missing middle for nest between
             "raw f32 (fast, big)" and "zstd block (small, but must decompress to read one
             element)".
techniques:
  - LogArray: pack N unsigned ints at W = ceil(log2(max+1)) bits each into 64-bit words plus a
    trailing control word holding N (u32) and W (u8); entry(i) reads at most two words and
    shifts/masks W bits
  - BitIndex two-level rank/select: per-64-bit-block popcount counts in a LogArray plus
    per-superblock (52 blocks) cumulative counts in a second LogArray; rank1 = sblock_rank -
    block_rank + count_ones(masked word); select1 = binary search over superblocks then linear
    block scan
  - use_linear_bitscan cache-line shortcut: if start and end share a 512-byte cache line,
    popcount-scan directly instead of consulting the index
  - Plain Front Coding (PFC) dictionary: sort strings, group in blocks of 8, store block head
    verbatim, each successor as vbyte(common-prefix-len)+nul-terminated suffix; prefix
    compression plus binary-searchable string<->id both ways
  - AdjacencyList = LogArray (right-hand values) + BitIndex (1-bit marks last pair of each left
    id); traverse a subject's predicates via rank/select with zero stored pointers
  - vbyte (HDT-style, msb=last-byte flag) for prefix-length and gap encoding inside dictionary
    blocks
  - WaveletTree over a u64 sequence (log2(alphabet) bitarray layers) for
    positional/range/reverse-traversal queries
  - TFC typed dictionary: order-preserving per-XSD-datatype byte encodings (sign-magnitude
    varint integers, decimals, datetimes) so numeric values stay sorted and front-codable in one
    dictionary
nest steals: Add a succinct integer/string codec family to nest-format under crates/nest-format/src/encoding
             using reserved v1 encoding ids 4-255 (additive, no version bump). (1) Encode
             chunk_ids and monotone offset arrays (chunks_original_spans, per-section length
             tables) as a LogArray: ~64k chunks need ~17 bits not 32/64, cutting those sections
             ~2x with O(1) mmap random access and zero decode on cite/materialize. (2) Add a PFC
             front-coded dictionary codec for repetitive string metadata (provenance fields,
             source URIs, tags, BM25 vocabulary in bm25_index 0x08); prefix sharing beats
             per-field zstd for sorted short strings and stays binary-searchable from mmap. (3)
             Port BitIndex rank/select into nest-runtime for sparse presence/tombstone bitmaps
             (optional-field presence, deleted chunks for real-time edit) at ~1.05 bits/bit with
             O(1) navigation. (4) The two-level rank/select plus cache-line bitscan upgrades
             BM25 posting lists and any future graph-search adjacency without pointer overhead.
             Keep deterministic (sorted/seeded), but flip terminusdb's big-endian words to
             little-endian per nest's constraint; each module fits the <=300-line
             single-responsibility rule.
compression: Directly central to "compress more than everyone": succinct structures give near-entropy size
             while keeping random access, which is exactly nest's bind since embeddings must be
             scored from mmap and block compressors are banned on the hot path.
             LogArray/BitIndex/PFC compress every surrounding integer/string/offset/index
             section without the full-block decode that zstd forces, complementing zstd (cold
             sections only) and the f16/int8 quantizers. They do not shrink the dense embedding
             matrix itself.
perf:        Block=64 bits (one register), superblock=52 blocks. rank1 is O(1): two LogArray lookups + one
             word read + hardware popcount; select1 is O(log #superblocks) binary search then
             linear block scan; use_linear_bitscan skips the index when a range fits a 512-byte
             cache line. LogArray.entry(i) touches at most 2 contiguous words (cache-friendly).
             PFC blocks of 8 bound the suffix walk to 7 strings. All structures are
             immutable/read-only: lock-free, trivially parallel, matching nest's mmap-and-serve
             model. Reported density ~13.57 bytes/triple at 17B triples with a full 6-way index.
