what:        A Java RDF quad store whose embedded backends (NativeStore B-tree, LMDB store) split storage
             into a value dictionary mapping every RDF term to a compact integer ID plus
             B-tree/B+tree permutation indexes (spoc, posc, ospc) that store only those IDs,
             with the LMDB store adding an order-preserving variable-length integer (Varint)
             codec for the IDs.
innovation:  Dictionary-encode every repeated term to a small integer ID once, then store and index ONLY the
             IDs (never the bytes), and encode those IDs with an order-preserving
             variable-length integer whose length is recoverable from the first byte alone, so
             sorted key storage stays correct while small/common IDs cost 1-2 bytes instead of a
             fixed 4-8.
techniques:
  - order-preserving varint: smaller values use fewer bytes, total length decodable from the
    first byte, and byte-wise lexicographic order equals numeric order so it doubles as a sort
    key
  - value-type tag (URI/BNode/Literal) packed into the low 2 bits of the integer ID, avoiding a
    separate type column
  - two-level dictionary: ValueStore maps each distinct term to a sequential integer ID; indexes
    store 4 IDs (s,p,o,c) not the terms; ID 0 reserved as null/default-graph context
  - IRI factoring: split each IRI into namespace + local-name, give the namespace its own ID,
    store only [type 1B][namespaceID 4B][localname UTF-8] so shared prefixes are paid once
  - literal layout [type 1B][datatypeID 4B][langLen 1B][langTag<=255B][label UTF-8], referencing
    datatype by ID not inline
  - fixed-slot B-tree page: 16B header (magic btf, version, blockSize, valueSize, rootID), nodes
    one block each, slotSize=4+valueSize, branchFactor=1+(blockSize-8)/slotSize, direct offset
    math with no per-node scan
  - configurable index permutations (spoc/posc/ospc/psoc) chosen per query shape so the most
    selective access pattern is a sorted range scan
  - dictionary-scoped WAL for crash recovery leaving primary .dat files authoritative; mmap + OS
    page cache makes the store behave in-memory when RAM suffices
nest steals: nest-format: add a dictionary-encoded section family plus an order-preserving Varint codec (new
             RESERVED encoding id 4-255, additive within v1) for any section that is a column of
             monotone or repeated integers, principally chunk_ids and future graph/edge
             sections. The biggest concrete win is provenance and repeated metadata: factor
             repeated source strings/URIs into one per-file string/namespace table and store
             only small IDs (mirroring RDF4J ValueStore), which beats zstd-on-raw because
             redundancy becomes integer locality. nest-runtime: when nest adds the promised
             graph search, store edges as (src_id, rel_id, dst_id) Varint triples in spo/ops
             permutation orders so adjacency is a sorted range scan straight off mmap; RDF4J
             permutation indexes are the proven blueprint, and nest's mandated deterministic
             alphabetical/seeded ordering maps cleanly onto preserve-lexicographic-order so the
             index stays byte-identical and reproducible. nest-cli: the cite path can reuse the
             namespace/localname split so nest://content_hash/chunk_id URIs are stored factored.
compression: Directly central. Dictionary encoding + order-preserving Varint is the textbook way to push the
             non-embedding sections nest already zstd-encodes (chunk_ids, provenance, future
             graph edges) BELOW what a generic entropy coder reaches on raw bytes, by removing
             structural redundancy (repeated terms, monotone IDs, shared IRI prefixes) before
             the entropy stage rather than relying on the coder to rediscover it. It never
             touches embeddings (correctly, since those are scored from mmap on the hot path),
             so it stays fully inside nest's never-compress-embeddings rule while lowering the
             size ratio on everything else.
perf:        mmap + OS page cache lets it behave like an in-memory store when RAM suffices (matches nest mmap
             model). Fixed-slot B-tree pages give O(1) in-node offset addressing, no scan.
             Varint decode is branch-light (first byte gives length), good for a tight Rust
             loop; order preservation means you can binary-search encoded keys WITHOUT decoding.
             Reported LMDB footprint ~120-130 bytes/quad with 3 permutation indexes, so the cost
             of graph search is redundant permutations: nest should keep permutation count
             minimal (e.g. spo plus one inverse) to stay compact.
