vision
--------------------------------------------------------------------------------------------------
nest becomes the most compact, portable, sovereign AI database in the world: a single FROZEN-v1
.nest container that compresses every data type harder than the field while keeping four
properties no competitor combines - sovereign/offline (never opens a socket), single-file (one
mmap), deterministic (same chunks + same model fingerprint => byte-identical file), and citable
(nest://content_hash/chunk_id reopens an exact byte span with a real-cosine score). The thesis,
grounded in the actual tree: nest already half-implements the winning pattern - lossy candidate
generation guarded by a MANDATORY exact-cosine rerank (search.rs::search_ann/search_hybrid ->
score_subset), content_hash over DECODED canonical-six bytes with length-prefixed name-domain
framing (a NAR-grade construction), decode_payload that fails closed on unknown encoding ids, an
int8 codec that ALREADY carries a scale_kind discriminator (int8.rs:18), and a OnceLock SIMD
dispatcher. The unrealized wins are concentrated and verifiable: embeddings are the dominant bytes
sitting at an 8 bpw int8 floor while the field has converged on rotation-first sub-byte
quantization (block-int8 4x near-lossless, int4 ~4.25bpw, RaBitQ 1-bit ~32x) all guarded by the
rerank nest already mandates; the cold metadata sections (chunk_ids as 71-byte ascii, spans as
repeated source_uri + raw u64, BM25 raw u32 doc/tf, HNSW raw u32 neighbor ids) carry zero
structural compression and are textbook delta+bitpack/front-code/dedup targets; text runs
hardcoded level-19 zstd with no trained dictionary; and there is no content-hash dedup before the
entropy coder. Two correctness truths gate the aggressive path and are designed in from Phase 0,
not bolted on: score_subset reranks against the SAME lossy stored dtype (so 'real cosine' becomes
'real cosine at stored precision' below int8 - sub-int8 REQUIRES a separate f16/f32 rerank
source), and materialize.rs expands EVERY dtype to an n*dim*4 f32 buffer whenever HNSW is attached
(so any embedding shrink is paid back in RAM unless the ANN path scores packed blocks). Execute
the additive codec stack in dependency order behind these two guardrails and nest pushes the tiny
preset's 0.283 ratio toward sub-0.1 on embedding-dominated corpora with recall@10 held by the
mandatory exact rerank - shipped incrementally by a solo author with AI agents, each codec a
<=300-line single-responsibility module returning typed thiserror, every step additive within
frozen v1.

pillars
--------------------------------------------------------------------------------------------------
1. Universal layered byte container (the moat)
   Make .nest a self-describing additive codec engine: turn decode_payload into a visitor-style
   registry where each encoding id is one <=300-line module implementing decode(&[u8])->Cow;
   reserve encoding ids 4-255 and section ids 0x09+ as named constants; add a skippable-OPTIONAL
   vs unskippable-REQUIRED flag on SectionEntry so old runtimes serve unknown optional sections
   and fail closed on unknown required ones; cost-driven per-section codec selection (trial-encode
   all candidates, keep smallest, record chosen id, raw always a candidate). decode_payload
   already fails closed on unknown ids and content_hash already hashes DECODED canonical-six
   bytes, so every new codec stays content_hash-stable and citation-safe.
   draws from: facebook/zstd, ebiggers/libdeflate, duckdb/duckdb, serde-rs/serde, google/snappy

2. Embedding compression frontier (the dominant bytes)
   Drive the embeddings section from the 8 bpw int8 floor down a deterministic rotation-first
   quantization ladder, all scored in-place off mmap and all guarded by the mandatory exact rerank
   against a separate f16/f32 rerank-source section: block-scaled int8 (scale_kind=1,
   near-lossless 4x, no new id) -> seeded-FWHT Rotational Quantization on int8 (~0.99 recall at
   4x) -> int4 block-64 (~4.25bpw, fused dequant+dot, no f32 in RAM) -> RaBitQ 1-bit
   (AND+popcount, ~32x, unbiased estimator). Matryoshka prefix truncation as a deterministic
   multiplicative dim knob. Rotations/codebooks seeded from the model fingerprint ->
   byte-identical builds. Integer-domain VNNI/dotprod kernels for speed AND true cross-CPU
   bit-determinism on the quantized path.
   draws from: gaoj0017/RaBitQ, VectorDB-NTU/RaBitQ-Library, weaviate/recipes, ggml-org/ggml,
   microsoft/onnxruntime, ARM-software/ComputeLibrary, QwenLM/Qwen3-Embedding, rust-lang/stdarch

3. Integer + string metadata compression (the free wins)
   Replace structurally-uncompressed cold sections with canonical integer/string codecs, all
   decoding byte-identically so content_hash and citations are unchanged: one shared
   delta(d1)+zigzag+per-128-block minimal-bitpack/FOR codec with O(1) select for HNSW neighbor ids
   (sort-per-list), BM25 doc-id gaps + bitpacked tf, and per-source span offsets; 32 raw SHA-256
   digest bytes instead of 71-byte ascii chunk_ids (~2.2x) with front-coding/FST term+id
   dictionary that stays binary-searchable off mmap; a deduped source_uri string pool. Index
   changes bump only HNSW/BM25 payload versions; spans/chunk_ids use a new reserved encoding id.
   PFOR patched exceptions so one giant gap never widens a block.
   draws from: lemire/FastPFor, fast-pack/simdcomp, cruppstahl/libfor, cruppstahl/libvbyte,
   BurntSushi/fst, google/flatbuffers, blazegraph/database, apache/lucene

4. Text + structured-document codec stack (compress-AND-serve everything)
   Beat generic zstd on text by ordering the stack correctly: content-hash dedup of identical
   chunks BEFORE zstd (Nix lesson: dedup on decompressed bytes, compress after); a corpus-trained
   shared zstd dictionary (ZDICT over sorted samples, deterministic) to kill per-section
   cold-start + cross-chunk redundancy on many-short-similar PT-BR chunks; FSST as a transparent
   codec so single-chunk citation reopen decodes O(1) where block-zstd forces a whole-section
   inflate; cost-driven pick-smallest per section; and for the json/yaml/parquet roadmap a
   fixed-stride u64 structural tape + length-prefixed value blob plus per-column lightweight codec
   cascade chosen by a deterministic Analyze pass. Canonical text stays byte-exact so content_hash
   is stable.
   draws from: NixOS/nix, ipfs/kubo, facebook/zstd, facebook/rocksdb, duckdb/duckdb,
   lancedb/lance, simdjson/simdjson

5. Honest serve path + sovereign runtime guarantees
   Two runtime fixes are the precondition for compression to actually pay off and stay honest: (a)
   fix the materialize-to-f32 leak so the ANN distance path scores packed int8/int4 blocks (or
   keeps f16, never expands to n*dim*4 f32 in RAM); (b) decouple rerank precision from storage
   precision via a SECTION_EMBEDDINGS_FP rerank source so score_subset reranks survivors against
   true precision below int8. Plus: generalize the SimdBackend OnceLock into a functable so new
   kernels (f16/F16C, VNNI/dotprod, popcount, nibble-unpack) register one entry each; route HNSW
   traversal through the SIMD dispatcher instead of the scalar cosine_dist loop and swap the
   per-query HashSet visited set for a generational buffer; zero-copy PyBuffer<f32> query borrow +
   Python::detach around the read-only mmap search; one cp312-abi3 maturin wheel.
   draws from: microsoft/onnxruntime, rust-lang/stdarch, nmslib/hnswlib, djc/instant-distance,
   PyO3/pyo3

6. Corpus dedup, graph search, real-time edit + reproducibility
   Add the structural and capability pillars as cheap additive overlays: content-defined chunking
   (FastCDC/Gear, seeded) + content-hash dedup with refcounts (the field's biggest lever on
   whole-repo/dataset payloads); an optional CSR graph_adjacency section (chunk-to-chunk
   semantic/citation/NEXT_CHUNK edges, reusing the intpack codec) traversed off mmap, seeded from
   exact-cosine top-k and feeding the SAME mandatory exact rerank (and letting nest drop
   chunk-overlap text by reconstructing neighbor context from edges); an append-only edit journal
   overlaid in memory at open (frozen bytes immutable) plus a deterministic compact() that re-runs
   the dictionary, re-quantizes, drops dead chunks; a reproducibility manifest (sorted per-section
   content-hash + decoded_length + recipe) making byte-identical builds third-party verifiable
   offline; a byte-level subword tokenizer closing the CJK/Thai BM25 gap and doubling as a
   text-compression front-end.
   draws from: NixOS/nix, ipfs/kubo, tidwall/buntdb, vesoft-inc/nebula,
   neo4j/neo4j-graphrag-python, google/sentencepiece, jvm-repo-rebuild/reproducible-central
