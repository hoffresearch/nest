==============================================================================================
nest master plan v2 :: risks + quick wins
==============================================================================================

part 04.

risks
----------------------------------------------------------------------------------------------
  - the 'ten mediocre products' trap is the existential risk and the draft did not actually
    enforce its own discipline. mitigation is now structural AND sequenced: a vertical is a
    forge profile (toml) + a lens verb alias + a demo corpus, enforced by a test that the
    profile layer produces byte-identical files; AND a hard FLAGSHIP-PROVEN gate blocks all of
    catalog/entity-graph/multimodal/viewer code until the headline number is proven on one
    real corpus and the flagship has external users. if a wedge needs a new crate, a required
    section, or a format-version bump, it is wrong by construction.
  - ADDITIVE-V1 BREACH #1 (fixed): the draft's CHUNKS_ORIGINAL_SPANS v1->2 bump is a breaking
    change to a canonical, content-hashed, REQUIRED section sold as additive. read_prefix
    (codec.rs:98-103) rejects any version != 1, and spans is in CANONICAL_SECTIONS so a v2
    layout changes the decoded bytes and thus content_hash for the same corpus. fix:
    catalog/blob-relative span info lives in a SEPARATE excluded
    SECTION_BLOB_SPAN_OVERLAY=0x16 keyed by chunk ordinal; spans stays v1 byte-identical;
    self_contained and catalog twins keep the SAME content_hash; old readers still open the
    file.
  - ADDITIVE-V1 BREACH #2 (fixed): the draft adds capability flags to the manifest 'so
    existing files are byte-identical', but Capabilities (manifest/mod.rs:21-40) is plain
    non-optional bools with a hand-written Default, so a new required bool is a
    deserialization + file_hash break for every existing file. fix: ALL new manifest fields
    Option<T> skip_serializing_if=is_none and defaulted on read; new capability flags go in
    Option<CapabilitiesExt> or the flatten extra map, never new required bools; a v01_compat
    test asserts old manifests still deserialize and a new default serializes byte-identical.
  - CITATION GUARANTEE CONFLATION (fixed): the draft claimed citations 'reopen exact byte
    spans' but cite (cite.rs:43-62) returns the stored canonical text and prints source_uri as
    a string only - it never opens the original file. split into tier-1 (canonical-span
    reopen, exists, all the flagship needs) and tier-2 (original-byte reopen + blob-digest
    verify, NET-NEW, scheduled as its own card inside catalog mode). the flagship work-order
    claims ONLY tier-1.
  - the candidate-generator contract can leak: a graph edge weight, a graphrag relevance, or a
    per-space ann score could surface as the returned score. score_subset today
    hard-dispatches on a single dtype and the single 0x04 section, so adding
    search_graph/search_space/search_cross without refactoring it would weaken the gate.
    mitigation: refactor score_subset to an explicit rerank-source handle in phase 0, and a
    SINGLE parameterized contract test (over ann/hybrid/graph/space/cross) asserts
    returned_score == score_subset(union) byte-for-byte and recall is NaN, gating the release
    check before any new path lands.
  - sub-int8 anywhere without a per-section fp rerank source silently lies about cosine, AND
    the headline ratio is dishonest without counting the fp source. mitigation: the writer
    rejects a sub-int8 section/space with no fp source, re-checked at open; the --disclose
    explain line states whether the score is full-precision; and every sub-int8 RESULT reports
    the NET-OF-FP ratio (rabitq 1-bit + f16 fp source is roughly 2x, never the bare 32x).
  - scope front-loading: the draft put the entity property graph (G2/G3) + graphrag traversal
    + export api + a cosmos.gl/webgl viewer into phases 1-4 of a linear roadmap, which is a
    second product the flagship does not need. mitigation: only G1 (chunk csr) is pre-gate (it
    earns its place on compression+retrieval merit and reclaims chunk_overlap); ALL of G2/G3,
    multimodal spaces, catalog .nestpack, and the viewer are behind the FLAGSHIP-PROVEN gate,
    and G1 landing is explicitly decoupled from G2/G3 in the plan text.
  - the determinism boundary is subtle: users expect 'same pdf => same .nest' but the real
    guarantee is 'same canonical text + same model fingerprint => byte-identical .nest'.
    mitigation: provenance records extractor+engine+embedder versions and forge plan prints
    them before any heavy run; the default static embedder makes the common case fully
    deterministic and offline.
  - forge-core as a second rust workspace risks chunker drift from builder.chunk_text.
    mitigation: do NOT duplicate the chunker; the python/forge adapter CALLS
    builder.chunk_text so there is one authoritative chunker, locked by a golden ci test
    (duplicate-then-reconcile was the more expensive path the draft chose).
  - catalog mode and the .nestpack sidecar reintroduce multi-file fragility the single-file
    thesis exists to kill, and they are post-gate. mitigation: catalog is strictly opt-in, the
    .nest is fully functional for search/graph/verifiable-citation without the sidecar, and
    'citation verifiable, original unavailable' is a first-class non-alarming typed (never
    panicking) state.
  - UX bloat: the draft's verb-collapse + hidden dev namespace + nest-profile crate + many new
    verbs net INCREASE surface for a tool with no users. mitigation: the flagship ships
    exactly ask + cite, keeps the existing 8 subcommands as-is under the hood, and DEFERS the
    verb-collapse and the nest-profile crate until a second vertical actually needs a second
    profile.
  - the lens viewer could pull the project online (cdn cosmos.gl, remote fonts) breaking
    offline-by-construction, and it is post-gate. mitigation: lens/ stays out of the cargo
    workspace, vendors deps locally, opens no socket, and a check asserts no remote fetch().
  - demo/corpus licensing: the most compelling osint/factcheck demos sit on academic-only or
    no-clear-license data. mitigation: pick ONE concrete permissively-licensed flagship corpus
    in phase 0; ship only synthetic or permissively-licensed demo corpora, never raw
    academic-only data.

quick wins
----------------------------------------------------------------------------------------------
  - reserve ALL reconciled section-id bands (0x11-0x16, 0x20-0x2F, 0x30-0x3F) as named
    constants in the phase-0 codec-registry card with a single disjoint-bands test, before any
    feature branch edits layout/mod.rs - kills the four-pillar 0x11 collision AND pre-claims
    the 0x16 overlay that replaces the illegal spans bump, for free.
  - refactor score_subset to an explicit rerank-source handle and add the ONE parameterized
    rerank-honesty test during phase 0, so every future search path (graph/space/cross) plugs
    into a gate that already exists instead of weakening it.
  - add the additive SearchExplain field to SearchResult during the phase-0 recall harness
    work, so the --disclose explain honesty line and the agent-native retrieve() provenance
    both come nearly free later.
  - decide the default embedder NOW (vendor a static model2vec/potion table): it makes
    byte-identical builds trivial, keeps the flagship pip-install tiny and fully offline, and
    removes the first-use network fetch that breaks offline-by-construction - it is a flagship
    blocker, not research.
  - pick ONE concrete license-clean demo corpus in phase 0: it is cheap, currently absent, and
    gates the whole one-gif go-to-market.
  - keep ONE chunker: have the python/forge adapter call builder.chunk_text rather than
    duplicate it in forge-core, removing the drift risk by construction instead of by a
    reconcile test.
  - pull the chunk-to-chunk csr (G1) into phase 1: it reuses the intpack primitive already
    being built, delivers named graph-search, and pays for itself by letting nest drop
    chunk_overlap - while staying decoupled from the entity graph.
  - ship the agent-native retrieve() + ask + tier-1 cite as soon as phase 0-1 is green - it
    fuses existing search + tier-1 cite, needs no new format and no original-byte reopen, and
    is the cheapest provable wedge plus the one-gif demo.
  - make storage_mode an Option defaulting to self_contained and force all new manifest fields
    to be Option/skip_serializing_if so existing files stay byte-identical and all
    golden/v01_compat tests pass untouched.
  - when the entity graph eventually lands, build the cosmos.gl export and its
    deterministic-ordering tests early against the EXISTING hnsw level-0 adjacency as a
    stand-in, so the viewer and a11y surface come up cheaply on already-present data.
