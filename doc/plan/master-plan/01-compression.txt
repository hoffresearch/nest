part 01.

keep the consolidated phases 0-3 stack intact as the foundation and ship it FIRST; the larger
redesign capabilities extend it only behind the flagship-proven gate. the through-line stays:
lossy candidate generation (hnsw/bm25/graph/space-ann) guarded by the MANDATORY exact-cosine
rerank (score_subset), content_hash over DECODED canonical-six so every codec that round-trips
bit-exactly keeps the same hash and citation. (1) embeddings ladder (phase 2-3):
rotation-first (block-int8 4x near-lossless -> seeded-FWHT rotational int8 ~0.99 recall ->
int4 block-64 ~4.25bpw -> rabitq 1-bit), each sub-int8 step gated by an embeddings_fp rerank
source. HONEST NET RATIO: the fp rerank source is mandatory for every sub-int8 section, and an
f16 fp source is ~16x the size of rabitq 1-bit data, so the headline 32x on the quantized slab
collapses to roughly 2x once the mandatory fp source is counted; every sub-int8 RESULT fill-in
MUST state the NET-OF-FP ratio (quantized + fp), never the bare quantized ratio. the headline
target is restated honestly: push tiny's 0.283 toward sub-0.1 on embedding-dominated corpora
WITH the fp source counted, recall@10 held by the exact rerank, proven on ONE real corpus
before anything past phase 1 starts. (2) per-space quant (post-gate, phase 4): each named
space declares its own dtype/quant gated by its OWN per-space fp source, same rotation ladder,
each space a fixed-stride 64-byte-aligned slab the existing simd kernels score byte-for-byte;
the same net-of-fp accounting applies per space. (3) graph sections reuse the intpack codec:
csr offsets, neighbor-id gaps, edge-type runs all delta+zigzag+bitpack; the chunk-to-chunk csr
(G1, in phase 1) pays for itself by letting nest drop chunk_overlap text and reconstruct
neighbor context from NEXT_CHUNK edges. the heavier entity graph (G2/G3) reuses the same
codecs but is gated post-flagship. (4) catalog blobs (post-gate, phase 3): store a
content-hash blob_refs table (sorted, intpack offsets) and move only the heavy ORIGINAL bytes
to an optional content-addressed sidecar, while embeddings+index+graph+canonical TEXT stay
inlined and searchable off mmap. catalog mode REQUIRES a net-new original-byte reopen path
(today cite returns stored canonical text only, never original bytes) so that path is scoped
explicitly inside catalog, not assumed. (5) forge/structured inputs feed the EXISTING text
codec stack: pdf/font/dataset extraction produces canonical text that runs the trained zstd
dict + fsst + dedup-before-zstd path unchanged, so a heterogeneous catalog gets
state-of-the-art text ratio with no new core code.
