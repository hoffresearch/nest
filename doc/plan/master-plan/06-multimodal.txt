==============================================================================================
nest pillar :: multimodal embedding spaces in one .nest (named spaces, additive within v1)
layer: nest
==============================================================================================

a design doc. the executable steps are in ../tasks/.

thesis
----------------------------------------------------------------------------------------------
one .nest holds many named embedding spaces (text, image/clip, glyph/typography, symbol) by
treating the v1 required `embeddings` section as space[0] and adding additive optional
sections that each carry their OWN dim, count, dtype, model_hash, and modality tag. the
winning shape is NAMED SPACE SECTIONS over a tagged-interleaved pool: each space stays a
contiguous, fixed-stride, 64-byte-aligned mmap slab so the existing simd dot kernels score it
byte-for-byte unchanged, while a tagged pool would force a stride/dtype branch into the inner
loop and re-layout the proven hot path. a tagged pool only wins when one query must score ALL
modalities at once at the same dim, which is never our case: cross-modal search is always
"route to ONE space whose model produced the query vector, then exact-rerank in THAT space." a
space is a self-describing tuple {name, modality, model_hash, dim, dtype, n_vectors,
row_index_map}, and the row_index_map is the one piece of real engineering: vectors in
space[k] do not 1:1 map to chunks (an image space has fewer rows than text chunks, a glyph
space has one row per glyph not per chunk), so each space owns an explicit u32 entity-id list
(delta+intpack, reusing task #10) that maps space-local row -> global entity id. the mandatory
exact-rerank contract is preserved PER SPACE: ann/bm25 are candidate generators inside one
space, and the returned score is always the real cosine computed against that space's own
(optionally fp) vectors. quantization presets (int8/int4/rabitq) are declared per space, so a
corpus can keep text at int8 and crush a 200k-row clip image space to rabitq 1-bit, each gated
by its own per-space embeddings_fp rerank source. all of this is additive: v1 readers that
don't know the multimodal capability still open the file, serve text search from the required
`embeddings` section, and ignore the extra space sections (skippable-optional), so no
NEST_FORMAT_VERSION bump and no citation breakage.

format impact
----------------------------------------------------------------------------------------------
additive within v1, no NEST_FORMAT_VERSION bump. NEW reserved optional section ids: 0x11
SPACE_TABLE, 0x20-0x2F SPACE_EMBEDDINGS (per-space vector slabs), 0x30-0x3F
SPACE_EMBEDDINGS_FP (per-space fp rerank sources). all excluded from content_hash
(canonical-six only), so multimodal spaces never invalidate citations. NEW manifest fields
(both optional, backward compatible): `spaces: Option<Vec<SpaceManifestEntry>>` and
`capabilities.supports_multimodal: bool` defaulting false. requires the
skippable-optional-vs-unskippable-required SectionEntry flag bit from master-plan 02-format
(set spaces as skippable-optional) so a v1-only runtime serves text search and cleanly ignores
unknown space sections. per-space dtype reuses the EXISTING dtype/encoding vocabulary
(float32/float16/int8 now; int4/rabitq when tasks #16/#17 land) - no new encoding ids needed
for multimodal itself; a space just declares its own dtype in its descriptor. the
row_index_map (space-local row -> global entity id) is intpack-encoded (reuses task #10 codec)
inside each SPACE_EMBEDDINGS section's payload prefix, or as a sibling field in SPACE_TABLE
for small spaces.

architecture changes
----------------------------------------------------------------------------------------------
nest-format gains a new submodule `sections/spaces/` (mod.rs, descriptor.rs, index_map.rs,
registry.rs) and three new reserved optional section ids in layout/mod.rs ABOVE the
already-claimed 0x09-0x10 band: SECTION_SPACE_TABLE=0x11 (a small json/binary registry:
ordered list of space descriptors), SECTION_SPACE_EMBEDDINGS_BASE=0x20 (the first space-vector
slab; spaces beyond [0] occupy 0x20..0x2F, one section id per space, fixed-stride
raw/quantized bytes, NEVER zstd, 64-byte aligned), SECTION_SPACE_EMBEDDINGS_FP_BASE=0x30 (the
matching per-space fp rerank source, 0x30..0x3F, mirrors task #06 embeddings_fp). the v1
required `embeddings`(0x04) section stays the canonical space[0]=text and stays in
content_hash; every space section at 0x11/0x20+/0x30+ is EXCLUDED from content_hash exactly
like 0x09-0x10, so adding image/glyph/symbol spaces never invalidates a nest:// citation.
nest-format/src/sections/spaces/descriptor.rs defines SpaceDescriptor{ name:String,
modality:enum{text,image,glyph,symbol,custom(u16)}, model_hash:String, embedding_dim:u32,
dtype:String, n_vectors:u64, section_id:u32, fp_section_id:Option<u32>,
index_section_id:Option<u32>, normalize:String }, serialized in the SPACE_TABLE with the same
12-byte payload prefix + JCS-canonical body as search_contract. manifest gains an OPTIONAL
`spaces: Option<Vec<SpaceManifestEntry>>` field (skip_serializing_if None) and a
Capabilities.supports_multimodal flag; absent => single-space file, fully backward compatible.
nest-runtime gains `runtime/src/spaces/` (mod.rs, view.rs, route.rs): MmapNestFile keeps its
existing single-space fields as the text fast path AND gains `spaces: Vec<SpaceView>` where
SpaceView{ name, modality, dim, n, dtype, offset, size, entity_ids:Vec<u32>, fp_offset:Option,
ann:Option<HnswIndex> }; each SpaceView reuses the EXISTING simd dot kernels and the EXISTING
DType dispatch unchanged (the whole point of fixed-stride-per-space). a new
`search_space(space_name, query, k)` and `search_cross(from_space, to_space, ...)` wrap the
existing score_all/score_subset/exact-rerank against a chosen SpaceView instead of the
implicit space[0]. nest-cli gains a `--space <name>` flag on search/search-ann/search-graph
and a `nest spaces` subcommand listing each space's
modality/model_hash/dim/dtype/quant/row-count. nest-python exposes spaces() and
search(space=...). FORGE (outside the core) owns producing the per-space entity-id maps and
per-space model fingerprints; LENS routes a query to the space matching the query embedding's
model_hash and can run multi-space fan-out (one exact-rerank per space, merge by space-local
cosine, never mixing scores across spaces).

ux
----------------------------------------------------------------------------------------------
cli verbs: `nest spaces <file>` lists every space (name, modality, model fingerprint
short-hash, dim, dtype/quant, n_vectors, has-fp-rerank, has-ann); `nest search <file> --space
image --image query.png` and `--space text "query"` route per modality; default (no --space)
preserves today's behavior and searches text space[0]. progressive disclosure: a single-space
file behaves exactly as today and never mentions spaces; multimodal surfaces only when
present. accessibility/graph-first audience: `nest spaces` output is plain, scannable,
lowercase, and the per-space model_hash makes "which model made this" legible (the
gifted/autistic/adhd graph-thinker audience values explicit provenance over magic).
cross-modal verbs read like the mental model: `find similar image`, `find this typeface`
(glyph space), `find this symbol` (symbol space) each map to `search --space <modality>`.
every returned hit still carries score_type=cosine plus the space name and that space's model
fingerprint, so a result is never ambiguous about which space and which model produced it.
lens (not the core) owns any gui; the core only exposes the routed, exact-reranked, cited
results.

phase placement
----------------------------------------------------------------------------------------------
new phase 4 "multimodal + graph pillars", AFTER the consolidated compression phases 0-3. hard
prerequisite is phase 0 task #06 (SECTION_EMBEDDINGS_FP / per-space honest rerank) and task
#08 (codec registry) - multimodal generalizes embeddings_fp to per-space fp sources, so it
must not fork that code. task #10 (intpack) is a soft prereq for the row_index_map encoding.
priority within phase 4: the SPACE_TABLE + named-space read/route path is HIGH (it is the
multimodal foundation and the graph pillar's sibling, both being additive optional sections
feeding the same exact rerank); per-space sub-byte quantization presets are MEDIUM (they ride
on phase-3 int4/rabitq, tasks #16/#17, applied per space). sequence the four tasks below as
4a(format) -> 4b(runtime route) -> 4c(quant presets) with 4d(cli/python) parallelizable after
4b.

proposed tasks
----------------------------------------------------------------------------------------------
* 4a :: reserve named-space sections + SpaceDescriptor + SPACE_TABLE format
    goal:   make the .nest container able to DESCRIBE and STORE multiple named embedding spaces
            additively: reserve section ids 0x11 (space_table), 0x20-0x2F (per-space vector
            slabs), 0x30-0x3F (per-space fp rerank), define SpaceDescriptor and the
            SPACE_TABLE payload, and prove a v1-only reader still opens a multimodal file and
            serves text search. format work only, no runtime routing yet.
    owns:   crates/nest-format/src/layout/mod.rs, crates/nest-format/src/sections/spaces/mod.rs,
            crates/nest-format/src/sections/spaces/descriptor.rs,
            crates/nest-format/src/sections/spaces/registry.rs,
            crates/nest-format/src/sections/spaces/index_map.rs,
            crates/nest-format/tests/multimodal_additive.rs
      - reserve SECTION_SPACE_TABLE=0x11, SECTION_SPACE_EMBEDDINGS_BASE=0x20 (band 0x20-0x2F),
        SECTION_SPACE_EMBEDDINGS_FP_BASE=0x30 (band 0x30-0x3F) as named constants in
        layout/mod.rs, all EXCLUDED from CANONICAL_SECTIONS/content_hash and added to
        OPTIONAL_SECTIONS only when their feature ships; document the full reserved-id map in
        a comment
      - add a test (mirror reserved_additive_ids_are_in_range_and_distinct) asserting the new
        bands are disjoint from 0x01-0x08 and 0x09-0x10 and that section_name resolves space
        ids only when active
      - define
        SpaceDescriptor{name,modality,model_hash,embedding_dim,dtype,n_vectors,section_id,fp_section_id,index_section_id,normalize}
        in descriptor.rs (<=300 lines) and a Modality enum
        {text,image,glyph,symbol,custom(u16)}
      - implement encode/decode for SECTION_SPACE_TABLE in registry.rs using the existing
        12-byte payload prefix + JCS-canonical json body (copy the shape of contract.rs), an
        ordered Vec<SpaceDescriptor>; reject duplicate names and duplicate section ids
      - implement index_map.rs: encode/decode the space-local-row -> global-entity-id u32 list
        (raw for now; leave a TODO to switch to intpack once task #10 lands) with
        bounds-validation against n_chunks
      - add manifest.spaces:Option<Vec<SpaceManifestEntry>> and
        capabilities.supports_multimodal (default false, skip_serializing_if None) so
        single-space files are byte-identical to today; validate that supports_multimodal
        implies spaces.is_some()
      - write multimodal_additive.rs: build a file with space[0]=text(0x04) plus an image
        space at 0x21+fp at 0x31, assert (a) content_hash is identical to the same file
        without the image space, (b) NestView::from_bytes parses and a reader ignorant of
        spaces still reads embeddings(0x04)
    risk:   claiming the wrong section-id band or letting a space section leak into content_hash would
            either collide with reserved 0x09-0x10 or break citations; the disjoint-bands test
            and the content_hash-identical test are the guards.

* 4b :: runtime SpaceView + per-space routing feeding the same exact rerank
    goal:   load every declared space at open into a SpaceView that reuses the EXISTING simd dot kernels
            and DType dispatch unchanged, and add search_space(name,...) +
            search_cross(from,to,...) that run the candidate-generate-then-exact-rerank
            contract PER SPACE so the returned score is always real cosine in the queried
            space. no changes to the text fast path's existing behavior.
    owns:   crates/nest-runtime/src/spaces/mod.rs, crates/nest-runtime/src/spaces/view.rs,
            crates/nest-runtime/src/spaces/route.rs,
            crates/nest-runtime/tests/multimodal_route.rs
      - in spaces/view.rs define
        SpaceView{name,modality,dim,n,dtype,offset,size,entity_ids,fp_offset,ann} and a
        constructor that maps a SpaceDescriptor + mmap into byte ranges, reusing
        DType::from_str and the existing embeddings_bytes-style slicing; each space slab is
        fixed-stride and 64-byte aligned so simd::dot_f32_bytes/dot_f32_f16_bytes/dot_f32_i8
        work with ZERO kernel changes
      - in mmap_file.rs add `spaces:Vec<SpaceView>` populated at open from SECTION_SPACE_TABLE
        when present, keeping the existing single-space fields as space[0]/text; absent table
        => empty vec, today's behavior
      - in spaces/route.rs add search_space(space_name,query,k): pick the SpaceView by name,
        validate query dim against THAT space's dim, run exact (or that space's ann
        candidates) then exact-rerank against that space's fp source if present else its
        stored vectors, materialize hits with the space name + space model_hash +
        entity-id-resolved citation
      - add search_cross(from_space,to_space,query,k) only where dims/model are compatible or
        via a stored join; otherwise return a typed error (no silent cross-dim scoring)
      - ensure entity_ids resolve to valid chunk spans for citations: bounds-check at open,
        map space-local hit rows -> global entity ids -> spans before building nest://
        citation
      - write multimodal_route.rs: a file with a text space and a small synthetic image space;
        assert search_space("text",...) is byte-identical to today's search(),
        search_space("image",...) returns real cosine in the image space, and a dim-mismatched
        query is rejected with a typed error not a panic
    risk:   any shared mutable assumption that 'embeddings' means space[0] could let a space query read
            the wrong slab; the byte-identical-to-today test on the text space and per-space
            dim validation are the guards, and SpaceView must never expand a space to n*dim*4
            f32 (carry the materialize-leak fix from task #07 per space).

* 4c :: per-space quantization presets gated by per-space fp rerank
    goal:   let each space declare its own dtype/quant (int8 now; int4/rabitq when tasks #16/#17 land) so
            a corpus can keep text at int8 and crush a clip image space to rabitq, with every
            sub-int8 space REQUIRED to ship its own fp rerank source so 'real cosine' stays
            honest per modality. extends task #06's embeddings_fp generalization to N spaces.
    owns:   crates/nest-format/src/sections/spaces/quant.rs, crates/nest-format/src/writer/spaces.rs,
            python/tools/measure_spaces.py
      - in quant.rs map each space's declared dtype to the existing encoding vocabulary
        (float32/float16/int8; reserve hooks for int4=7/rabitq=8 from layout) and validate
        that any space with dtype below int8 MUST set fp_section_id (writer-time error
        otherwise), mirroring task #06
      - in writer/spaces.rs emit per-space SECTION_SPACE_EMBEDDINGS (raw/quantized, NEVER
        zstd, 64-byte aligned, fixed stride) and matching SECTION_SPACE_EMBEDDINGS_FP, wiring
        them into build.rs's sections vec after the required six (build.rs is owned by
        4a-coordination: 4c only appends via a helper, do not rewrite build_bytes)
      - define a per-space preset ladder (text:int8, image:int8-or-rabitq, glyph:int8,
        symbol:int8) as named defaults so forge can pick a preset by modality without
        hand-tuning
      - write measure_spaces.py: for a multimodal fixture, report per-space size ratio and
        recall@10 of the quantized+fp-reranked path vs an f32 baseline for THAT space, proving
        rabitq-on-image stays honest via its fp source
      - add a roundtrip + content_hash-equality test path note: space sections are excluded
        from content_hash, so the equality assertion is that adding/removing a quantized space
        leaves content_hash unchanged
    risk:   a sub-int8 space without an fp rerank source silently lies about cosine for that modality (the
            exact trap task #06 closes for text); the writer-time 'sub-int8 requires
            fp_section_id' validation plus the per-space recall harness are the guards.
            coordinate build.rs edits with 4a to avoid a parallel-edit conflict (4c only
            appends through a helper).

* 4d :: cli + python surface for spaces (route, list, cite)
    goal:   expose multimodal to lens: a `nest spaces` subcommand listing each space (modality, model
            fingerprint, dim, quant, row-count, has-fp, has-ann) and a `--space <name>` flag
            on search/search-ann so a user/agent routes per modality, with single-space files
            unchanged. python gets spaces() and search(space=...).
    owns:   crates/nest-cli/src/cmd/spaces.rs, crates/nest-cli/src/cmd/mod.rs,
            crates/nest-python/src/spaces_fn.rs, crates/nest-cli/tests/cli_spaces.rs
      - add cmd/spaces.rs: a 10th-style subcommand `nest spaces <file>` printing one lowercase
        line per space (name modality model_short_hash dim dtype n_vectors fp=yes/no
        ann=yes/no), reusing inspect_json plumbing; default output stays scannable for the
        graph-thinker audience
      - add a `--space <name>` flag to search and search-ann (default = text/space[0]); when
        set, call search_space; keep the no-flag path byte-identical to today
      - wire python: spaces_fn.rs exposes nest_file.spaces() -> list of dicts and
        search(query, k, space='text'); update lib.rs registration only via the additive
        function (do not touch existing signatures' defaults beyond adding space='text')
      - write cli_spaces.rs e2e: build a multimodal fixture, assert `nest spaces` lists
        text+image with distinct model hashes, `nest search --space image` returns hits scored
        as cosine in the image space, and `nest search` (no flag) is byte-identical to the
        pre-multimodal output on a single-space file
      - ensure every result still prints space name + that space's model fingerprint so a
        citation is never ambiguous about which space produced it
    risk:   adding a default space argument to existing python/cli search signatures could break callers;
            keep the default exactly 'text'/space[0] and prove byte-identical single-space
            output, and register `nest spaces` as a new subcommand rather than overloading
            inspect.

risks
----------------------------------------------------------------------------------------------
  - the v1 header hardcodes a single embedding_dim/n_embeddings and the manifest a single
    dtype/model_hash; if any reader path assumes space[0] is the only embeddings, multimodal
    sections could be silently ignored or mis-scored. mitigation: keep
    space[0]=embeddings(0x04) authoritative for the header fields, make all extra spaces
    self-describing in SPACE_TABLE, and add a negative test that a v1-only runtime opens a
    multimodal file and serves text search.
  - scope creep into 10 mediocre products: image/glyph/symbol embedding GENERATION is heavy
    and belongs in forge, not the core. risk that quant/route code drags model-loading into
    nest-runtime. mitigation: the core only stores/scores/routes pre-computed per-space
    vectors; forge produces them; the critic enforces no model runtime in nest-runtime.
  - per-space quantization without a per-space fp rerank source silently degrades 'real
    cosine' for that modality (same trap task #06 fixes for text). mitigation: SPACE_TABLE
    requires fp_section_id to be present whenever a space's dtype is below int8, validated at
    writer time and re-checked at open.
  - row_index_map bugs (space-local row vs global entity id) would return correct cosine for
    the WRONG entity, a citation-integrity failure. mitigation: bounds-check every entity id
    at open against n_chunks/entity-table size, fuzz the map, and assert citation byte-spans
    resolve for every returned cross-modal hit.
  - section-id exhaustion / banding mistakes: claiming 0x11 and 0x20-0x3F must not collide
    with the already-reserved 0x09-0x10 or any future graph/catalog ids. mitigation: document
    the full id map in layout/mod.rs with a test asserting all reserved bands are disjoint,
    exactly like the existing reserved_additive_ids_are_in_range_and_distinct test.

open questions
----------------------------------------------------------------------------------------------
  - does a glyph/typography space embed per-glyph (one row per unicode codepoint+font) or
    per-rendered-image, and does that change whether the row_index_map points at chunks or at
    a separate glyph entity table (likely a new optional entities section shared with the
    graph pillar)?
  - should cross-space joins (text chunk -> its clip image embedding for the same page) live
    as graph edges in SECTION_GRAPH_ADJACENCY (0x0C) or as a per-space entity-id alignment,
    and who owns that join (forge at ingest vs lens at query)?
  - for catalog mode, do quantized space slabs stay inlined (small, hot) while only original
    blobs go to the sidecar, or can an entire low-priority space (e.g. full-res image vectors)
    also be sidecar-referenced by content-hash?
  - is a single shared SPACE_EMBEDDINGS section with an internal per-space directory ever
    worth it for files with many tiny spaces (symbol sets), trading one section id for a
    directory lookup, or does the per-space-section simplicity win given the 0x20-0x2F band
    gives 16 spaces?
  - should the SPACE_TABLE encode a per-space `default: bool` so a non-text file (pure image
    catalog) can declare image as the default space without violating the v1 'embeddings(0x04)
    is text space[0]' rule?
